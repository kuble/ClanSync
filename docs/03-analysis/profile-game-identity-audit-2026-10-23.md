# 계정 닉네임·게임 ID 표시 점검

2026-10-23 사용자 결정: 가입 시 계정 닉네임을 받지 않는다. 공통 프로필에 별도 닉네임을 만들지 않고, 클랜별 게임 ID로 플레이어를 식별한다.

## 이번 반영

| 위치 | 표시 규칙 |
|---|---|
| 내 프로필·방문 프로필 | 닉네임·닉네임 첫 글자 아바타 제거. 기본 아바타와 소개 사용. 중복 게임 목록·클랜 소제목 제거 |
| 클랜별 프로필 콜아웃 | 게임 로고·클랜·역할·전체 배틀태그/라이엇 ID와 해당 클랜의 대표 엠블럼을 묶음. 여러 소속은 캐러셀로 탐색 |
| 미니룸 | 개인 이름 대신 `나의 방` |
| 게임 선택의 계정 메뉴 | 기본 아바타·`내 계정`·본인 이메일 |
| 참가자 기록 연결의 현재 계정 | 본인 이메일과 계정 ID 일부. 연결 대상의 게스트 기록명은 보존 |
| 공개 방문 | `미니룸 공개`와 `함께하는 클랜`을 켰을 때 모든 로그인 방문자에게 해당 클랜의 인증된 게임 ID 제공. 이메일·내부 제공자 ID·코인·보관함·계정 정보는 제외 |
| 공통 네임카드 미리보기 | `Player#1234` 예시 유지. 클랜에서는 해당 게임의 실제 ID 표시 |

## 2026-10-30 실제 표시 경로 전환

10월 23일에는 프로필 중심으로 전환하고 아래 경로를 후속으로 남겼다. 당시 상태를 “레거시 닉네임을 모두 제거했다”로 설명한 것은 잘못이었다. 10월 30일 아래 경로의 실시간 조회도 해당 게임에 등록된 ID로 전환했다.

| 파일·구간 | 이전 출처 | 현재 출처 |
|---|---|---|
| [clan-manage-content](../../src/components/main-clan/clan-manage-content.tsx) 공지·가입 신청·구성원·구매 이력 | 계정 닉네임 | 해당 클랜 게임 ID. 권한·기록 주체 ID 유지 |
| [clan-balance-room-data](../../src/components/main-clan/clan-balance-room-data.tsx) 방장 표시 | 계정 닉네임 | 방의 클랜 게임 ID |
| [load-clan-polls](../../src/lib/clan/load-clan-polls.ts) 공개 투표 참여자 | 계정 닉네임 | 투표의 클랜 게임 ID. 익명 투표 비공개 유지 |
| [hof-comments](../../src/app/actions/hof-comments.ts) 댓글 저장 직후 | 계정 이름 | 재조회와 동일한 게임별 ID |
| [clan-events](../../src/app/actions/clan-events.ts) 참석자 목록 | 게임/계정 닉네임 | 검증된 `battle_tag`/`riot_id` |
| [공통 클랜 이름·네임카드·엠블럼·새 운영자 스냅샷](../../supabase/migrations/20261030022000_game_identity_labels.sql) | 계정 호환 캐시 | 게임별 DB 이름 함수. 로비·통계·게시판 등 공통 호출자에 적용 |

오버워치는 전체 배틀태그(이름+#번호), 발로란트/LoL은 Riot ID를 사용한다. 구형 `game_uid`는 배틀태그 형식인 경우에만 허용하며 제공자 내부 ID는 표시하지 않는다. 직접 입력한 미인증 ID도 이름으로 사용하며 프로필에서 미인증 상태를 표시한다. ID가 없으면 입력을 안내하고 레거시 이름으로 대체하지 않는다. 게스트 기록명·구분 별칭과 기존 과거 기록 스냅샷은 보존한다. RPC의 `nickname` 반환 필드명은 호환 계약으로 유지하며 값의 출처만 변경한다.

## 2026-10-30 DB 레거시 컬럼 폐기 (QA)

화면 전환 이후 남겨 두었던 `users.nickname`을 QA DB에서 삭제했다. `user_game_profiles.nickname`은 적용 전부터 존재하지 않았으며, 두 컬럼이 모두 남아 있다고 설명한 부분을 정정한다. 가입 트리거와 누락 계정 행 복구 코드에서 닉네임 쓰기·Auth 메타데이터 읽기를 제거하고 배틀태그→계정 닉네임 동기화 트리거/함수를 폐기했다. QA 시드·데모·통계 도구·테스트는 계정 닉네임을 생성/조회하지 않으며 표시 이름은 게임 ID를 사용한다.

마이그레이션은 이름을 다른 곳에 복사하거나 새 보존 필드를 만들지 않는다. 기존 `clan_participants.nickname`의 게스트/기록명·`operator_name`·경기 스냅샷과 RPC의 이름 반환 계약을 유지한다. 적용 전후 공개 테이블 66개의 전체 행 수·데이터 해시(삭제 대상 `users.nickname`만 제외)가 모두 같고, 전체 컬럼 대조에서 삭제 1개·추가 0개를 확인했다. 생성 타입·스키마 색인을 동기화했으며 운영 DB 적용·배포는 보류한다. [마이그레이션](../../supabase/migrations/20261030030000_retire_legacy_account_nickname.sql) · [컬럼 부재·기록 보존 회귀](../../scripts/legacy-nickname-retirement-db.test.mjs).

## QA 임시 ID

- [허용 목록](../../scripts/fixtures/qa-fixtures.mjs)의 14계정만 대상으로 [QA 보정 스크립트](../../scripts/qa-game-identities.mjs)를 실행했다. 14개 모두 인증 표시가 이미 켜져 있었고 비어 있던 배틀태그를 채웠다. 예: `QALeader01#1001`, `QAMember02#2002`.
- `node scripts/qa-game-identities.mjs`는 변경 예정만 조회한다. `--apply`를 명시해야 쓴다. QA 프로젝트를 강제하며 기존에 채운 게임 ID는 덮어쓰지 않는다. 다시 실행한 결과 변경0건을 확인했다.
- 제공자 `game_uid`·로그인·사용자 ID를 유지한다. 코인 등 보정 대상 밖의 데이터를 보존한다. 초기 보정 당시 사용하던 `users.nickname` 캐시와 동기화 트리거는 위 폐기 작업으로 제거했다.
- QA 표시 데이터이며 실제 외부 OAuth 증명을 만들지 않는다. 기존 명단을 시드로 다시 생성하지 않았다. 이후 명시적으로 시드할 때도 같은 임시 배틀태그를 사용하도록 보완했다.
