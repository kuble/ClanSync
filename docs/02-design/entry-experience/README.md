# 서비스 진입 경험 상세 설계

작성일: 2026-10-24 · 상태: **상세 변경 기획 / 검토용 설계안 / 구현 전**

상위 문서: [변경 방향과 범위](../../01-plan/entry-experience-redesign.md)

## 1. 읽는 순서와 문서 역할

`변경 기획 → 이 문서의 공통 규칙 → 화면별 상세 → 구현 의존성 확인 → QA 구현 → 실제 검증 기록` 순서로 진행한다. 이 문서화 작업은 상세 설계까지다. 화면 구현·운영 반영 승인을 받은 상태로 기록하지 않는다.

| 문서 | 역할 | 담지 않는 것 |
| --- | --- | --- |
| [상위 변경 기획](../../01-plan/entry-experience-redesign.md) | 왜 바꾸는지, 남길 것·없앨 것, 전체 방향 | 화면별 세부 구현 상태 |
| 이 문서 | 공통 레이아웃, 문서 우선순위, 이동·상태·검증 규칙 | 여섯 화면의 문구 반복 |

| [구현·검증 기록](../../TODO_Phase2.md) | 구현 후 실제 결과와 미검증 범위 | 기획만으로 체크 완료 |

파일 번호는 문서 식별자이며 사용자 이동 순서는 위 표를 따른다. 게임 인증을 로그인과 합치지 않고 독립 설계 대상으로 다룬다.

## 2. 현재·제안·후속을 구분하는 기준

- **현재:** 이번 조사에서 확인한 코드·기존 QA 상태다. 초기 디자인 확인 기준은 `c709c33`이며, 병행 중인 프로필 진열장 작업은 완료·검증 기록을 확인한 뒤 대표 이미지에 반영한다.
- **이번 설계:** 여섯 화면의 구도·표현·전환·상태 처리에 대한 구체안이다. 기존 정책의 확정 범위를 넓히지 않는다.
- **구현 의존성:** 새 조회 필드, 모바일 상세의 주소/뒤로가기, 오류 결과 구분 등 실제 코드 변경이 필요한 지점이다.
- **후속 기능:** 외부 OAuth, 비밀번호 복구, 소셜 로그인, 실제 구독 결제, 비회원 클랜 탐색이다. 미구현 버튼을 이번 화면의 완성 조건으로 위장하지 않는다.

기존 명세와 표현이 다르면 화면별 상세를 **새 UI 제안**으로 읽는다. 현재 권한·정원·소속·계정 검증 규칙은 코드와 기존 정책을 유지하며, 충돌을 발견하면 해당 상세의 의존성에 기록한다. 특히 한국어 랜딩 제목은 기존 잠정 영어 문구(D-LANDING-01)를 바꾸는 제안이고, 연령·동의 기준 변경은 제안에 포함하지 않는다.

## 3. 공통 시각 규격

| 항목 | 설계 기준 |
| --- | --- |
| 글꼴·색 | 기존 Pretendard와 `background / surface / card / foreground / muted-foreground / border / primary` 토큰 사용 |
| 헤더 | 높이 60px. 왼쪽 브랜드·현재 맥락, 오른쪽 테마·해당 사용자 메뉴 |
| 공개 헤더 | 랜딩은 서비스 화면·지원 게임 앵커와 로그인. 로그인·회원가입 화면은 홈 로고와 테마만 |
| 로그인 후 헤더 | 현재 위치 + 게임 선택 진입 + 계정 메뉴(프로필·로그아웃) + 테마. 현재 화면과 같은 이동을 중복 강조하지 않음 |
| 본문 | 최대 1280px, PC 좌우 24~32px, 모바일 16px |
| 인증 폼 | 최대 440px, 보조 장면 포함 전체 최대 1040px, PC 두 영역 사이 최소 48px |
| 모서리·표면 | 기본 12~16px, 큰 대표 장면 20px. 입력·카드·배너를 같은 강도로 감싸지 않음 |
| 간격 | 관련 필드 16~20px, 정보군 24~32px, 섹션 48~72px. 작은 화면에서는 단계적으로 축소 |
| 제목·본문 | 페이지 제목 28~32px/모바일 24~28px, 본문 14~16px, 입력 16px, 보조 12~13px |
| 주요 버튼 | 최소 높이 44px, 한 화면의 주요 작업에 초록 강조. 보조는 외곽선/텍스트 |
| 아이콘·이미지 | 기존 게임 로고·클랜 아이콘 재사용, 없으면 기본 아이콘. 새로운 이모지 썸네일은 사용하지 않음 |

PC는 1024px 이상, 태블릿은 640~1023px, 모바일은 639px 이하를 설계 분기로 삼는다. 인증의 소개 패널은 1024px 미만에서 숨긴다. 상세별 특별 규칙이 없으면 태블릿은 1열 본문, 게임 카드는 가용 폭에 따라 2열을 허용한다. 수치는 구현 검토 때 조정할 수 있으며 실제 측정 완료 수치가 아니다.

### 공통 구성요소

| 구성 | 재사용·표현 방식 |
| --- | --- |
| 브랜드·헤더 | `EntryBrand`, `HeaderBreadcrumbs`, `AccountShell`과 기존 테마 전환을 필요한 범위에서 조합 |
| 입력·버튼 | 기존 `Input`, `Button`, `Switch`, `PasswordInput`의 시각·초점 규칙 사용. 인증 전용 민트 그라데이션 제거 |
| 단계 표시 | `게임 선택 → 게임 계정 연결 → 클랜 참여` 3단계. 게임 인증은 2, 클랜 탐색은 3. 로그인·가입에 강제로 붙이지 않음 |
| 상태 메시지 | 현재 정보 바로 옆/아래에 설명. 성공·대기·마감을 색상과 텍스트로 함께 표시 |
| 이미지 미리보기 | 정적 이미지, 명시적 크기·비율·대체텍스트. 실시간 미니룸·진열장·움직이는 데모를 자동 실행하지 않음 |

게임 참여 단계의 완료 항목은 장식이고, 이동이 필요하면 `게임 선택으로`처럼 실제 링크 이름을 쓴다. 진행하지 않은 다음 단계를 누르면 인증을 건너뛸 수 있는 표현을 만들지 않는다.

## 4. 이동과 복귀 계약

```text
서비스 이해 → ClanSync 계정 진입 → 게임 선택 → 필요하면 게임 인증
                                               ↓
                     내 클랜 ← 소속 확인 ← 클랜 탐색 → 신청 → 승인 대기
                                               └→ 생성 → 리더 환영 → 클랜 홈
```

1. 로그인·가입 성공의 기본 목적지는 `/games`다. 보호된 링크에서 시작하면 검증된 내부 `next`가 우선한다.
2. 로그인↔가입 링크는 `next`를 유지한다. 외부 URL·인증 자기 자신 등 허용되지 않은 값은 기존 `safeNextPath` 규칙으로 기본 목적지에 보낸다.
3. 게임 인증 완료 목적지와 **인증 취소 목적지**를 구분한다. 인증이 필요한 보호 경로를 취소 링크로 사용해 인증 화면을 반복하지 않는다.
4. 게임 선택에서 온 취소는 `/games`, 프로필의 재연결에서 온 취소는 `/profile`을 기본으로 한다. 연동 성공 후에는 유효한 원래 목적지를 우선하고 소속 가드가 최종 판단한다.
5. 클랜 가입 승인은 즉시 입장과 다르다. 서버가 소속을 확인하기 전에는 가입 완료 화면이나 클랜 내부를 보여주지 않는다.
6. 모바일 상세를 열고 닫아도 필터·페이지·목록 위치를 보존한다. 새 주소 상태를 도입하면 직접 진입·새로고침·브라우저 뒤로가기를 함께 정의한다.
7. 로그인한 사용자의 루트 자동 이동과 `/?from=logo` 예외를 유지한다. 해시만으로 서버 이동 예외를 판단할 수 있다고 가정하지 않는다.

| 주소/상태 | 현재 여부 | 처리 |
| --- | --- | --- |
| `next`, `reauth` | 현재 사용 | 서버 검증·기존 가드 유지 |
| 클랜 검색의 `q/style/tier/page` | 현재 사용 | 검색·필터·페이지 복원 기준 |
| 클랜 상세 `selected`, 생성 `mode` | 상세 설계의 추가 제안 | 현재 구현으로 오인하지 않음. 선택 대상 검증과 새로고침·뒤로가기 처리까지 구현해야 사용 |
| 메시지·이메일·비밀번호 초안 | 폼 상태 | 주소에 넣지 않음. 비밀번호/인증정보를 브라우저 영구 저장소로 따로 보존하지 않음 |

## 5. 로딩·오류·초안의 공통 규칙

- 최초 진입과 조건 변경을 구분한다. 조건 변경 중에는 헤더·제목·입력·현재 신청과 외곽 영역을 유지한다.
- 결과를 갱신할 때 목록·상세만 상태를 바꾼다. 이전 조건의 결과를 유지한다면 `갱신 중`임을 알리고 이전 결과로 새 작업을 제출하지 못하게 한다.
- 계정·게임·권한이 바뀌면 이전 응답·초안을 재사용하지 않는다. 새 계정 정보가 오기 전까지 이전 전체 게임 ID·소속을 가린다.
- 검색 실패와 검색 결과 없음은 다른 상태다. 실패를 `0개`로 표시하지 않고 재시도 동작을 제공한다.
- 제출 중에는 중복 제출과 입력 변경을 막고 제출 버튼 크기·외곽 구도를 유지한다. 실제 서버 결과를 받은 뒤 성공·부분 실패·실패를 구분한다.
- 필드 오류는 해당 입력에 연결하고, 자격·네트워크·서버 오류는 폼 공통 영역에 둔다. 토스트만으로 중요한 실패를 알리지 않는다.
- 실패 시 이메일·필터·선택·메시지는 같은 작업 범위에서 보존한다. 비밀번호는 같은 폼의 메모리 내 보존만 허용하고 경로 변경·재로딩 후 복원을 약속하지 않는다.
- 인증 폼 전체를 큰 고정 높이로 만들지 않는다. 짧은 상태 문구 공간을 확보하되 긴 오류는 읽을 수 있게 자연스럽게 늘린다.
- 작성 중인 메시지/생성 초안을 버리는 화면 전환에는 확인을 제공한다. 제출 중 다른 작업으로 이동하면 성공을 임의로 추정하지 않고 복귀 시 서버 상태를 다시 읽는다.

## 6. 구현 시작 전에 해결할 의존성

| 항목 | 이번 설계의 기준 | 실제 구현 전 확인 |
| --- | --- | --- |
| 운영 게임 연결 | 신규 연동 미제공 상태를 정직하게 표시 | `oauthReady` 메타만 보고 실제 제공 여부를 판단하지 않음 |
| 게임별 ID | `이름#태그` 전체를 기본 식별 정보로 사용 | 본인 게임 카드 조회 필드와 재연동 계정 동일성 규칙 |
| 공개 클랜 정보 | 소개·규칙·모집 정보·배너/아이콘만 조회 | 비구성원에게 허용된 필드/권한. 회원용 기록·통계 요청 금지 |
| 약관·개인정보 | 실제 문서 보기와 기존 필수 체크 범위 유지 | 연결 가능한 문서와 현재 수집 항목의 일치 |
| 신청 교체 | 기존 취소 후 새 제출의 부분 실패를 표시 | 원자적 교체를 제공하려면 별도 데이터 변경·검증 필요 |
| 신청중 클랜 생성 | 현재 동작을 숨기지 않고 별도 명시 | 명시 취소를 선행하도록 바꾸는 안은 정책·동작 변경 제안으로 검토 |
| 재연동·취소 복귀 | 재연동을 건너뛰거나 반복하지 않게 함 | 호출 링크의 `reauth`와 안전한 취소 목적지 |
| 대표 이미지 | 구현·검증된 화면만 현재 기능으로 소개 | 병행 프로필 작업 완료 후 최신 촬영본 확인 |

미정 의존성이 있다고 전체 레이아웃 설계를 멈추지 않는다. 해당 기능은 제공 불가 상태로 설계하고, 실제로 준비되기 전에는 활성 버튼·성공 문구를 내보내지 않는다.

## 7. 구현·검증으로 넘기는 순서

| 묶음 | 작업 | 검토할 결과 |
| --- | --- | --- |
| A | 공통 헤더·표면 + 로그인·가입 | 정책을 유지한 폼 배치, 오류·확인 메일 안내, 복귀 |
| B | 게임 선택 + 게임 인증 | 상태별 목적지, QA/운영 분리, 재연동·취소 |
| C | 클랜 탐색·상세·신청 + 생성·환영 | PC/모바일 전환, 대기·교체·실패, 기존 초안 보존 |
| D | 랜딩·최신 대표 이미지 | 실제 제공 상태·현재 서비스 표현과의 일치 |
