# 14 Profile Customization · 프로필 / 꾸미기

기준일: 2026-10-26. QA 현재 동작을 기준으로 한다. 운영 DB·배포는 별도 승인 전까지 보류한다.

## 화면과 경로

| 경로 | 용도 | 권한 |
| --- | --- | --- |
| `/profile` | 플레이어 소개 / 계정 정보 두 탭 | 본인 |
| `/profile/{userId}` | 기존 링크 호환: 공통 클랜 개인 기록으로 이동 | 로그인 사용자 |
| `/games/{gameSlug}/clan/{clanId}/stats?player={userId}` | 플레이어 소개·개인 기록 통합 | 클랜 구성원; 통계는 기존 열람 권한 적용 |
| `/profile/{userId}/emblems` | 개인 엠블럼 케이스 | 로그인 방문자; 대표 저장은 본인만 |
| `/profile/emblems` | 본인의 현재·탈퇴 클랜 획득 기록 통합 | 본인 |
| `/profile/miniroom` | 기존 미니룸 가구 배치·보관 | 본인 |
| `/store` | 개인 코인으로 가구·칭호·프레임 구매 | 본인 |

프로필의 진열장·굿즈 보관함·진열장 관리·전용 상점은 제거했다. 해당 기획과 시안은 Git 이력에서 확인한다. [DB 정리 대상과 결과](../../03-analysis/retired-db-storage-2026-10-26.md).

## 플레이어 소개

- 본인 화면은 게임 프로필에 공통 네임카드를 통합하고 그 아래에 성별·출생 연도·가입일을 세 열로 묶는다. 넓은 화면에서는 왼쪽 게임/기본 정보와 오른쪽 한 줄 소개/대표 엠블럼을 두 열로 표시하며, 1000px 이하에서는 같은 순서의 한 열로 전환한다. 소개 카드는 탭 본문 폭을 채운다.
- 네임카드에는 선택한 게임의 인증된 배틀태그/라이엇 ID를 표시하고 미연동·미인증·등록된 게임이 없으면 `Player`를 표시한다. 내부 제공자 ID는 표시하지 않는다. 클랜이 없는 연동 게임도 게임 프로필에서 선택할 수 있다.
- 게임 프로필은 클랜·역할·인증된 전체 배틀태그/라이엇 ID를 사용하며 계정 공통 닉네임·아바타는 표시하지 않는다. 상대 플레이어의 소개는 개인 기록 상단에 같은 소개 구성과 계정 공통 칭호·프레임으로 표시한다. 클랜 없는 연동 게임도 선택하며 미인증·미연동은 `Player`다. 본인 전용 기본 정보·네임카드 편집은 방문자에게 제공하지 않는다.
- 여러 클랜이면 게임 아이콘/이름 버튼과 한 장씩 넘기는 캐러셀을 사용한다. 터치 스와이프·방향키/Home/End와 현재 순번 안내를 제공한다. 숨겨진 카드의 링크는 키보드·스크린리더 탐색에서 제외한다. 한 클랜이면 전환 버튼을 생략한다.
- 한 줄 소개는 최대 120자다. 본인만 편집·저장할 수 있으며 취소 시 기존 값을 유지한다. 저장은 계정의 다른 메타데이터를 덮어쓰지 않는다.
- 본인 소개의 대표 엠블럼은 캐러셀 바깥에 한 번 표시한다. 세 칸과 케이스 링크를 제공하며 클랜 프로필 변경과 독립적이다.
- 계정 정보 탭으로 전환해도 소개 상태를 유지한다. 모바일에서는 카드·네임카드가 화면 밖으로 넘치지 않는다.

## 계정 정보와 공통 네임카드

- 공통 네임카드는 각 게임 프로필 안에서 해당 게임 ID와 함께 표시한다. 꾸미기·개인 상점 버튼은 현재 선택한 카드의 클랜 이름·역할 행 오른쪽에 한 번만 제공하고 편집 창을 공유한다. 게임별 선택 대신 계정의 한 구성을 모든 게임·클랜에서 공유하며 게임을 바꾸어도 같은 칭호·프레임을 적용한다. 편집 창 미리보기에도 현재 게임 ID 또는 `Player`를 표시한다.
- 네임카드의 프리셋 엠블럼·이름표·칭호·프레임은 `nameplate_options` 카탈로그, `user_nameplate_inventory` 보유, `user_namecard_selections` 선택을 사용한다. 개인 엠블럼 획득 케이스와는 별도 기능이다.
- 장착은 본인·카테고리·활성 상품·기본/보유 조건을 서버에서 검증한다. 칭호 구매는 개인 코인에서 가격을 확인해 원장·보유 정보를 원자적으로 기록하고 중복 요청은 재차 차감하지 않는다.
- 네임카드의 상점/편집 아이콘은 접근성 이름·초점/hover 도움말과 44px 터치 영역을 제공한다. 선택은 저장 후 공유 네임카드에 반영하며 실패 시 재시도한다.
- 꾸미기 편집은 드롭다운 대신 프레임·심벌·이름표·칭호 분류와 보유 디자인의 네임카드 미리보기 목록을 사용한다. 현재 게임 ID와 나머지 장착 외형을 유지한 후보를 비교하며, 적용 중인 디자인은 체크와 테두리로 표시한다. 상단 현재 적용 모습은 목록 스크롤 중에도 유지하고, 클릭 저장이 성공한 뒤에만 적용 상태를 바꾼다. 새 디자인은 개인 상점으로 연결한다.
- 하단 안내와 상점 이동은 44px 아이콘으로 제공하고 도움말은 hover·초점·터치로 확인한다. 심벌은 기본 방패 외에 왕관·불꽃·번개·별·게임패드 5종을 무료 기본 카탈로그로 제공한다. 게임별 같은 기본 항목만 이름으로 중복 제거하며 서로 다른 무료 심벌은 모두 표시한다. 선택한 심벌의 모양·색을 미리보기·프로필·개인 기록·내전 네임카드에 공통 적용한다.
- 무료 기본 프레임 6종(실버 라인·챔피언 골드·아이스 블루·로즈 쿼츠·듀얼 라인·스티치), 이름표 배경 6종(미드나잇·포레스트·선셋·오로라·체커보드·블루프린트), 칭호 8종을 추가 제공한다. 프레임·배경·심벌·칭호는 독립적으로 조합한다. 칭호 숨김은 `*-sub-default`인 명시적 해제 항목에만 적용하며 무료 칭호도 본인·공개 소개·클랜 공유 카드에 문구를 표시한다. 기존 유료 상품의 보유 조건과 코인 잔액은 유지한다.
- 기존 Premium 프레임은 기존 보유·구매 조건을 유지한다. 구매 취소/환급으로 보유를 회수하면 계정 공통 장착에서도 해제한다.
- 편성자에게만 편성 중 장식을 숨긴다. 다른 참여자와 이후 단계에는 표시한다.

## 게임별 관리·가입 신청

- 게임별 관리에는 연결된 게임 계정·클랜·역할을 모으고 정보 펼치기, 부계정 자기신고, 선호 역할 관리를 제공한다.
- 인증된 게임 ID만 공개 프로필에 표시한다. 제공자의 내부 ID를 표시 이름으로 사용하지 않는다. 실제 외부 OAuth는 후속이며 QA 시뮬레이터와 구분한다.
- 부계정은 본인 또는 같은 게임의 공통 클랜 관계에서 허용된 범위로만 조회한다. 클랜 탈퇴·재가입·운영진 권한은 각각의 기존 서버 정책을 따른다.
- 가입 신청은 pending을 유지하고 결과는 최근 7일을 표시한다. 취소와 중복 요청은 서버 상태를 재검증한다.
- 계정 탭은 이메일·언어·자동 로그인·로그아웃·탈퇴, 게임별 관리와 가입 신청을 제공한다. 성별·출생 연도·가입일은 본인의 소개 탭으로 이동하며 계속 본인 전용이다. 자동 로그인은 약 30일의 세션 유지 설정이며 끄면 짧은 세션 정책을 적용한다.
- 계정/게임별 관리/가입 신청/자동 로그인 도움말은 제목에 연결된 툴팁으로 제공한다. 도움말 조작이 설정을 바꾸지 않는다.

## 개인 엠블럼

- 대표는 `account_personal_emblem_picks`에 계정당 한 행으로 저장한다. `클랜UUID:엠블럼키`를 최대 세 개 순서대로 선택하며 본인의 획득 원장에서 검증한다.
- 현재·탈퇴 클랜의 획득 이력을 게임별로 모아 보고 상세에서 게임·클랜을 구분한다. 마감 수상과 최초 달성일은 영구 보관한다. 클랜 통계의 개인 기록 공개 권한은 별도로 적용한다.
- 수상형/달성형의 분류·실루엣·계열별 최고 단계·관련 단계 상세와 날짜 색상을 사용한다. 고유 별명 대신 `10승 달성`과 같은 조건 설명을 표시한다.
- `clan_personal_emblem_picks`는 현재 클랜별 통계 조회와 기존 대표 선택의 출처로 사용한다. 폐기된 수동 5칸 배지 테이블을 다시 사용하지 않는다.

## 기존 미니룸

- `/profile/miniroom`에서 기존 방·가구를 유지한다. `housing_catalog`, `user_housing_rooms`, `user_housing_inventory`와 본인 전용 RPC를 사용한다.
- 가구를 길게 집어 배치·회전·보관하고 하단 드로워에서 꺼낸다. 벽지·바닥은 견본 선택으로 바꾼다. 별도 편집/완료 버튼은 사용하지 않는다.
- 키보드 집기/배치·R 회전·Delete 보관·Escape 취소, 모바일 44px 조작과 간편 보기를 제공한다. 모션 감소 설정을 존중한다.
- 유효한 조작과 재질 변경은 자동 저장 큐에서 순차 처리한다. 계속 편집할 수 있고 실패한 초안을 유지한다. revision 충돌·계정 변경·이동 중 저장을 검증한다.
- 가구 구매는 개인 코인·서버 가격·보유·원장을 함께 검증한다. 공개 방문 응답은 계정/구매 정보나 보관 중 가구를 노출하지 않는다. 현재 방문 화면에는 미니룸을 렌더링하지 않는다.

## 공개 범위와 데이터

- 내전의 비운영 화면에서 플레이어 네임카드를 누르면 현재 클랜의 `stats?player={userId}`를 연다. 소개·게임 계정·계정 대표 엠블럼을 개인 기록 상단에서 함께 보고, 전적·점수는 기존 열람 권한에 따라 제공한다. 소개만 허용된 방문도 통계 데이터는 받지 않는다. 운영 조작과 링크는 분리한다.
- 개인 기록은 현재 클랜의 게임 프로필 한 개만 표시하고 클랜 이름·직위를 숨긴다. 성별·출생 연도·해당 클랜 가입일은 기존 개인 기록 열람 범위에서 제공하며 공개 소개 API에는 추가하지 않는다. 계정 대표 케이스는 네임카드 밖의 한 줄 소개 아래에 두고 케이스 전체를 누르면 대상의 계정 엠블럼을 연다. 소개가 이미 같은 화면에 있으므로 네임카드 본문의 별도 프로필 이동과 케이스 링크 문구는 두지 않는다. 일반 멤버의 멤버 선택 버튼은 숨기며 서버장·운영진만 사용한다.
- 로그인 방문자에게 현재 클랜·인증된 게임 ID·공통 네임카드 외형·한 줄 소개·획득 엠블럼을 기본 공개한다. 서버는 기존 프로필 열람 확인 후 외형과 게임 ID만 전달하며 미인증 ID·보유 목록·잔액은 전달하지 않는다. 별도의 공개 토글이나 공개 설정 저장소는 없다.
- 별도 상대 프로필 화면은 두지 않는다. 기존 `/profile/{userId}`는 공통 클랜 개인 기록으로 이동하고 공통 클랜이 없으면 본인은 `/profile`, 타인은 기존 계정 엠블럼 케이스로 이동한다. 통합 소개는 인증된 `/api/player-profiles/{userId}`에서 공개 필드만 받고 대상 변경·실패·재시도를 영역 안에서 처리한다.
- 이메일·제공자 내부 ID·잔액·계정 정보·편집 권한은 방문 화면에 제공하지 않는다. 누락·탈퇴 계정은 방문 불가, 비로그인 사용자는 로그인 후 원래 경로로 돌아간다.
- 게임별 꾸미기 선택과 수동 5칸 배지, 과거 공개 설정은 QA DB에서 제거됐다. 현재 테이블은 [스키마](../schema.md)의 계정 공통 선택과 [삭제·보존 감사](../../03-analysis/retired-db-storage-2026-10-26.md)를 기준으로 한다.
