# 용어 사전 (Glossary)

제품의 내전 운영 용어와 자주 나오는 웹 용어를 정리한다. 내전 운영에서는 아래 확정한 의미를 사용하고, 기술 용어는 처음 나올 때만 병기한다.

## 내전 운영 용어

**2026-09-16 사용자 확정 · D-SESSION-01.** 제품 기획의 기준이며 실제 앱·데이터 구조에 모두 반영됐다는 뜻은 아니다.

| 용어 | 정의 |
|---|---|
| 세션 | 운영진이 열고 닫는 **당일 내전 전체**. 그 안에서 여러 라운드를 진행한다. |
| 라운드 | **경기 한 판**. 출전 명단·팀 편성·진행·결과를 구분하는 단위다. |
| 내전 날짜 | **세션을 연 시점의 날짜**. 기존 서비스 시간대인 KST로 표시하며 세션 동안 고정한다. 자정이나 오전 6시를 넘어도 그 세션의 날짜를 바꾸지 않는다. |
| 회차 / 라운드 번호 | 해당 세션 안에서 진행한 경기의 순서. 화면에서는 `1라운드`, `2라운드`처럼 표기한다. 편성을 다시 뽑거나 연출을 재생하는 횟수가 아니다. |
| 세션 참여자 | 열린 세션에 사이트로 접근하여 실시간 진행을 보고 기능별 권한에 따라 참여하는 클랜원. 해당 라운드 출전자에만 한정하지 않는다. |
| 라운드 출전자 | 해당 라운드에 실제로 플레이할 명단. 현재 오버워치 편성 기준은 10명·2팀이다. |
| 베팅 / 승부예측 | 해당 라운드 결과에 대한 참여 기능. 기존 권한·플랜·출전 여부·마감 조건을 따른다. 팀원 경매의 입찰과 구분한다. |
| 공유 화면 | 디스코드 라이브·방송 등에 띄우는 읽기 전용 표현 화면. 클랜원이 사이트에서 사용하는 세션 참여 화면과 구분한다. |

### 진행과 기록

1. **세션 열기:** 운영진이 당일 내전을 열면 클랜원이 사이트에서 해당 세션에 접근할 수 있다. 세션 접근은 라운드 출전 확정이나 모든 조작 권한 획득과는 별개다.
2. **라운드 진행:** 명단·편성 → 필요한 밴픽 → 라운드 시작 → 결과 기록을 반복한다. 클랜원은 같은 진행 상태를 실시간으로 보며 허용된 조작·베팅 등에 참여할 수 있다.
3. **다음 라운드:** 이전 라운드의 명단을 유지·교체해 같은 세션에서 다음 회차를 진행한다. 한 라운드의 종료로 세션이 자동 종료되는 것은 아니다.
4. **세션 닫기:** 종료 시점까지 진행한 라운드와 회차를 그 세션의 기록으로 남긴다. 라운드마다 새 내전 날짜를 계산하거나 종료 시각의 날짜로 다시 묶지 않는다.

예: **9월 16일 23:30에 세션을 열고 17일 01:00에 4라운드까지 진행 후 종료**했다면, `9월 16일 내전 · 1~4라운드`로 기록한다. 같은 날짜라는 이유만으로 서로 다른 세션의 라운드를 합치지 않는다.

### 혼동하지 않을 경계

- 사이트 참여는 지원한다. 기존의 ‘매 라운드 웹 접속·체크인을 강제하지 않는다’는 방향은 사이트 참여 기능을 없애거나 방송 시청만 허용한다는 뜻이 아니다.
- 명단 입력에서 관전자 등록을 제외한 것은 **10명 출전자 입력 보드**의 범위다. 비출전 클랜원의 세션 접근·승부예측을 제외하지 않는다.
- **내전 날짜**와 통계·코인·일일 배치의 **집계 기준일**은 별개다. 별도 집계 정책이 KST 06:00을 사용하더라도 세션의 내전 날짜를 덮어쓰지 않는다.
- 로그인 상태를 뜻할 때는 **로그인 세션**, 개발 작업 이력은 **작업 세션**으로 구분한다. `sessionStorage` 등의 기술 식별자는 바꾸지 않는다.
- 지명 순서의 묶음은 **지명 차례**, 밴픽 진행은 **밴픽 단계**로 부른다. 경기 한 판을 뜻하는 라운드와 혼용하지 않는다.
- 진행 중 라운드가 있을 때 세션을 닫는 절차, 무효·중단·재경기의 회차 처리, 닫힌 세션 재개·사후 정정은 후속 결정이다. 세션 종료만으로 미입력 결과나 베팅 정산을 자동 확정하지 않는다.

## 주소·이동 관련

| 한국어 표기 | 영문/기술 표현 | 한 줄 설명 |
|-------------|----------------|-----------|
| 주소 | URL · 라우트(Route) | 웹 화면의 위치. 게임의 "맵 ID"와 비슷하게 화면 ID 역할 |
| 화면 진입 잠금 | 라우트 가드(Route Guard) | 조건 미충족이면 다른 화면으로 자동 이동 |
| 자동 이동 | 리다이렉트(Redirect) | "당신은 못 들어와요, 여기로 가세요" 식으로 보냄 |
| 주소 옵션 값 | 쿼리 파라미터(Query Parameter) | 주소 끝에 `?key=value`로 붙는 옵션 |
| 주소 안 ID | 패스 파라미터(Path Parameter) | 주소 안에 `/clan/[clanId]`처럼 박힌 ID |
| 화면 안 작은 화면 | 탭(Tab) · 서브뷰(Sub-view) | 같은 주소 안에서 위쪽/사이드 메뉴로 갈아끼우는 작은 화면 |

## UI·인터랙션 관련

| 한국어 표기 | 영문/기술 표현 | 한 줄 설명 |
|-------------|----------------|-----------|
| 팝업 창 | 모달(Modal) | 화면 가운데 떠서 다른 조작을 막는 창 |
| 옆 패널 | 드로어(Drawer) | 화면 옆에서 미끄러져 나오는 패널 |
| 알림 띠 | 토스트(Toast) | 잠깐 떴다 사라지는 안내 띠 |
| 풍선 도움말 | 툴팁(Tooltip) | `?` 아이콘 등에 마우스를 올리면 뜨는 작은 설명 |
| 입력 검사 | 폼 검증(Form Validation) | 입력값이 규칙(이메일 형식, 글자 수)에 맞는지 검사 |
| 항상 보이는 좌측 메뉴 | 사이드바(Sidebar) | 게임의 좌측 메뉴와 동일 |
| 위쪽 메뉴 | 헤더 / 내비바(Navbar) | 화면 맨 위 가로 메뉴 |
| 빈 상태 화면 | Empty State | 데이터가 0건일 때 보여주는 안내 화면 |

## 로그인·권한 관련

| 한국어 표기 | 영문/기술 표현 | 한 줄 설명 |
|-------------|----------------|-----------|
| 로그인 세션 / 출입증 | Auth Session · Token | 로그인 상태를 유지하는 인증 정보. 당일 내전 전체를 뜻하는 세션과 구분 |
| 다른 서비스로 로그인 | OAuth | 디스코드/배틀넷 같은 외부 계정으로 로그인 |
| 권한 | Role · Permission | 운영자/일반 회원 등 할 수 있는 일의 범위 |
| 구독 등급 | Plan · Tier | 기본(Free) / 유료(Premium) 구분. 게임의 패스 등급 비슷 |

## 저장·데이터 관련

| 한국어 표기 | 영문/기술 표현 | 한 줄 설명 |
|-------------|----------------|-----------|
| 브라우저 영구 저장소 | localStorage | 탭을 닫아도 남는 작은 저장 공간 |
| 브라우저 임시 저장소 | sessionStorage | 탭을 닫으면 사라지는 저장 공간 |
| 서버 데이터 모양 | 스키마(Schema) · 데이터 shape | 어떤 필드가 어떤 타입으로 들어 있는지의 규격 |
| 데이터 한 줄 | 레코드(Record) · 로우(Row) | 표의 한 줄 |
| 검문소 | 미들웨어(Middleware) | 서버에서 화면 코드에 닿기 전에 한 번 거치는 단계. 로그인/권한 검사에 자주 씀 |

## 사용 규칙

1. 페이지 문서 본문에서 위 용어가 처음 나올 때만 `한국어 (= 영문)` 식으로 한 번 병기.
2. "구현 참고 (개발자용)" 섹션 안에서는 영문/기술 용어만 써도 OK.
3. 새 용어가 페이지 문서에 등장하면 이 사전에 추가한 뒤 본문에서 사용한다.
