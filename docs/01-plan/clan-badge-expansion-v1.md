# 클랜 배지 확장 V1 — 디자인 선택과 발급 기준

2026-10-14 사용자 요청. 6계열·21개의 획득 단계에 각각 5가지 스타일을 제작했다. 선택은 정규 1안·깜짝 1안·동료 5안·첫 정규 1안·코칭 2안·게시글 1안이며 [개별 투명 핀](../design/clan-badges/expansion-v1/production-v1/README.md)과 발급을 QA에 적용했다. 현재 창단·주년·멤버를 포함해 30종이다.

## 확인된 기록과 구현 연결

기존 종료 회차 조회를 서비스 전용 `read_clan_badge_metrics` 집계로 교체했다. 정정·삭제를 반영한 통계 원본과 통계 대상이 아닌 깜짝 라운드를 함께 조회하고 `team1`/`team2`/`draw` 결과를 개설 회차 ID로 묶는다. 통계 원본·명시 경기·정정 기록이 존재하는 라운드는 원본으로 다시 복구하지 않는다. 한 회차의 여러 결과·같은 경기 투영은 중복 집계하지 않으며 회차 종료 여부만으로 달성시키지 않는다. 무효·미기록만 있는 회차와 회차/종류를 확인할 수 없는 기록은 제외한다.

정규 50/100회·깜짝 10회 키는 새 기준과 그림으로 유지한다. 기존 정규 10/500회·깜짝 1회는 진열 목록에서 제외하고 기존 DB 획득 기록을 보존했다. 기존 대표 선택이 해당 키인 경우 현재 달성한 같은 계열의 최고 단계로 표시한다. 첫 정규 `regular-1`은 독립 기념 핀이다.

장기 동료는 `clan_members`의 현재 `active`와 `joined_at`으로 각 멤버의 연속 소속 기간을 판정한다. 10명이 같은 날 가입할 필요는 없지만 각자 최소 기간을 채워야 한다. 새 활성 가입의 시작일이 없으면 가입 시각을 기록하며 기존 미상 날짜를 임의로 채우지 않는다. 비활성→활성 전환 시 시작일을 현재 시각으로 초기화해 이전 소속 기간을 이어 붙이지 않는다. `joined_at = null`을 창단일/계정 생성일로 대체하지 않으며 해당 기간을 채운 활성 동료가 10명 미만이면 남은 최고 단계로 돌아간다.

코칭은 `clan_board_posts.kind = feedback`이고 `status = complete`인 클랜 전체의 현재 고유 신청을 집계한다. 같은 신청의 댓글/완료 토글/수정은 중복 횟수가 아니다. 사용자 선택대로 완료 상태를 기준으로 하며 실제 답변 수를 추가 조건으로 삼지 않는다. 최초 완료 날짜를 복원할 수 없는 기존 기록은 과거 날짜를 추정하지 않고 배지가 처음 확인된 시각을 저장·보존한다.

게시글은 `kind = free`인 클랜 전체 자유 게시판의 현재 고유 글이다. 댓글/공감/조회수/편집 횟수와 사진·피드백·채널·공지는 포함하지 않는다. 기록 정정·삭제, 완료 취소·글 삭제, 활성 동료 감소로 집계가 조건에 미달하면 기존 회수 의미를 유지하고 남은 최고 단계로 돌아간다.

## 표시와 제작

금빛 테두리·같은 계열의 외곽을 유지하고 내부 검/지도/번개/동료의 결속/배움/이야기가 단계적으로 커진다. 문양 요소 수는 성장의 상징이며 실제 횟수/인원과 일대일 대응하지 않는다. 이름·조건·날짜는 케이스 바깥에 둔다.

단계형은 기존 공통 `series` 진열을 사용한다. 최고 달성 한 슬롯을 클릭하면 큰 그림·설명·모든 연관 단계의 케이스를 연다. 첫 정규 내전은 독립 슬롯이다. 동료·코칭·게시판 분류, 년/주년·명/회/개 단위, 같은 계열의 첫 핀 실루엣 홈을 적용했다. 집계가 실패하면 발급/회수 전에 오류로 처리하며 클라이언트가 서비스 전용 집계를 호출할 수 없다. 운영 DB/배포는 보류한다.

## 2026-10-15 케이스 분류와 새 배지 확인

분류는 Rubber Segment의 전체·기념·동료·내전·활동이다. 동료는 멤버/장기 동료, 내전은 정규/깜짝, 활동은 코칭/게시판을 함께 보여준다. 원래 배지의 조건·계열 이름은 상세에 유지한다. 상단 선택 정보·새 획득 배너·핀 선택 밑줄은 제거하며 창단·첫 정규를 포함한 모든 핀을 클릭하면 상세를 연다. 대표 지정/해제도 상세 창에 둔다.

새 획득은 해당 분류와 전체의 N으로 표시한다. 상세를 열면 해당 핀과 상세의 연관 계열을 확인한 것으로 처리하고 다른 미확인 계열의 N은 유지한다. 부분 확인은 사용자/클랜/획득 시각별로 현재 브라우저에 저장하며 전체를 확인하면 기존 서버 확인 기록에도 반영한다. 서버 확인 시각은 화면에서 본 마지막 획득 시각까지만 전진하므로 요청 중 들어온 새 배지는 미확인으로 남는다. DB 스키마·발급 기준은 유지한다.
