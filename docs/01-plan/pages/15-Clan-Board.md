# 15 Clan Board · 클랜 게시판과 배지 케이스

2026-10-13 사용자가 구성안의 제작을 승인했다. QA 전용 구현이며 운영 DB 적용·수동 배포는 보류한다.

## 게시판

클랜 공통 메뉴의 게시판은 활성 클랜원에게 공개한다. 데스크톱은 왼쪽 목차, 모바일은 메뉴 선택기로 공간을 바꾼다. 기본 진입은 공지 및 규칙이다.

| 공간 | 주소의 마지막 구간 | 구성 |
|---|---|---|
| 클랜 공지 및 규칙 | `board/notices` | 규칙 문서와 고정 우선 공지 목록. 운영진 편집, 클랜원 열람 |
| 자유 게시판 | `board/free` | 제목·본문·선택 사진, 댓글·공감 |
| 피드백 신청 게시판 | `board/feedback` | 클랜원 선생님 자기 등록·분야/소개·신청 중단, 선생님 지정 리플레이 신청과 신청/답변 중/완료 |
| 방송 채널 홍보방 | `board/channels` | 방송 이름·시간, YouTube/CHZZK/Twitch/SOOP 최대 4개 외부 링크, 작성자 수동 생방송 표시 |
| 추억 열람방 | `board/memories` | 사진 한 장·100자 이내 한마디·게시일 자동 표시. 폴라로이드 목록 |

전체 기본 주소는 `/games/[gameSlug]/clan/[clanId]`이다. 글 상세는 `board/[section]/[postId]`, 목록은 24개씩, 댓글은 50개씩 페이지로 조회한다.

- 공지는 기존 `clan_notices`, 규칙은 `clans.rules`와 저장 액션을 유지한다. 구 `manage?tab=notices` 주소는 게시판으로 연결하며 대시보드 공지·관리 링크와 새 Discord 공지 링크는 게시판을 가리킨다. 기존 `?notice=<id>` 직접 링크도 열람을 유지한다.
- 일반 글은 `clan_board_posts`, 댓글/공감은 각각 `clan_board_comments`/`clan_board_reactions`로 관리한다. 게임 허브의 공개 홍보·스크림 게시판과 섞지 않는다.
- 작성자는 본인 글/댓글 편집·삭제, 운영진은 게시판 관리가 가능하다. 댓글 권한은 글 작성자와 별개다. 클랜원이 직접 선생님으로 등록하고 신청 받기를 중단/재개한다. 새 요청은 활성 소속이며 신청을 받는 다른 선생님을 지정한다. 기존 미지정 요청은 보존한다. 피드백 상태는 신청자·담당 선생님·운영진이 변경하며 선생님에게 신청자 글의 편집/삭제 권한을 주지 않는다. 비공개 신청은 후속 범위다.
- 선생님 지정 신청은 해당 선생님에게 사이트 알림을 보낸다. 새 댓글은 신청자·선생님·이전 댓글 참여자의 활성 소속을 확인해 본인을 제외하고 한 번씩 보낸다. 댓글 수정은 재알림하지 않는다. 알림의 원본 링크는 해당 신청/댓글 영역으로 이동하며 표시 중인 탭은 30초마다 새 알림을 확인한다.
- 방송 플랫폼은 추가/삭제할 수 있으며 같은 플랫폼을 중복 등록하지 않는다. 기존 단일 채널 글도 유지한다. 2026-10-14 사용자 요청으로 외부 라이브 실조회·주기적 호출과 API 경로/어댑터를 제거했다. 이후 요청에 따라 작성자가 직접 생방송 표시를 켜고 끄며 목록/상세에 `작성자 설정` 상태를 보여준다. 운영진도 타인의 방송 토글은 제공하지 않으며 서버 액션은 현재 작성자·활성 소속을 확인한다. 자동 조회·만료는 없다.
- 채널 소개 입력/표시를 제거하고 방송 이름·시간·플랫폼 링크로 구성한다. 이전 소개 본문은 보존하고 편집에서 덮어쓰지 않는다. 새 채널은 방송 대기로 시작한다. 일반 채널 편집은 최신 수동 상태를 유지하고, 상태/정보 동시 저장은 `updated_at` 비교로 충돌을 실패 처리한다.
- 피드백 목록은 데스크톱에서 상태·신청 내용·담당 선생님·댓글 수를 열로 나누고, 모바일에서는 제목/작성 정보와 담당자를 두 줄로 배치한다. 댓글 편집/삭제는 접근성 이름과 툴팁이 있는 아이콘 버튼이다.
- 자유/피드백/채널 목록은 본문을 조회·전송하지 않고 사진 목록은 짧은 한마디만 전달한다. 목록에는 관리 권한/원본 사용자 ID를 보내지 않는다. 소속·닉네임은 현재 서버 렌더 요청 안에서 재사용하고, 상세에서 편집 권한이 있는 피드백만 선생님 선택 데이터를 조회한다. 저장 후 서버 재검증을 사용하며 중복 새로고침과 목록 상세 링크의 자동 프리패치를 제거했다. 상세 본문·권한·알림 규칙은 유지한다.
- 상세는 제목/작성 정보 헤더, 방송 시간/플랫폼 또는 코칭 정보, 본문, 공감/댓글 요약과 댓글 입력 영역을 구분한다. 글/댓글 편집·삭제와 채널 제거는 접근성 이름/툴팁이 있는 아이콘만 표시한다. 게시판 입력창·편집 창에는 테마 색을 따르는 얇은 스크롤과 높이 제한을 적용한다. 공지와 선생님 프로필도 같은 여백/입력 스타일을 사용한다.
- 사진은 비공개 저장소 `clan-board-images`를 사용한다. JPEG/PNG/WebP, 원본 최대 5MB와 600px WebP 미리보기로 저장한다. 사진 변경/글 삭제·확정되지 않은 업로드 실패 때 파일 정리를 시도하고, 정리 실패는 성공한 글 저장과 구분해 알린다. 저장 응답이 끊겨도 이미 저장된 글의 사진을 지우지 않는다.
- 사진 열람은 `board/image/[postId]`에서 요청마다 현재 계정·게임·클랜 소속·글을 확인한다. 원본/미리보기 모두 공개 URL을 발급하지 않으며 응답은 `private, no-store`이다. 탈퇴자 요청은 기존 미들웨어의 가입 화면 연결 또는 접근 거부로 차단한다.
- 2026-10-14 사용자 선택에 따라 추억 열람방은 기존 전체 보기의 폴라로이드 목록만 유지한다. 앨범/전체 보기 전환·원형 회전·이전/다음 버튼을 제거하고 사진을 선택하면 상세/원본을 연다. 긴 한마디는 목록에서 세 줄로 요약하고 상세에서 전체를 읽는다. 첫 두 사진은 즉시, 이후 사진은 지연 로드한다.
- 촬영일 입력과 표시는 제거했다. 사진 날짜는 서버의 최초 `created_at`을 한국 시간으로 표시하며 수정해도 바뀌지 않는다. 기존 `takenAt` 기록은 저장된 상태로 보존하지만 표시 날짜로 사용하지 않는다. 새 사진에 별도 촬영일을 저장하지 않는다.
- 저장 실패 시 작성 내용과 선택 파일을 유지한다. 공간/페이지 이동과 로딩·오류는 공통 목차 아래의 내용 영역에서 처리한다. 사진은 미리보기부터 지연 로드한다.

## 배지 케이스와 회차

- 운영 현황은 정규/깜짝 **개설 회차**를 따로 표시한다. 합계는 보조로 남기고 아직 열지 않은 예약은 제외한다. 누락된 방 종류는 임의 분류하지 않는다.
- `badges`에서 활성 클랜원 모두 전체 핀 배지 케이스를 본다. 매트한 안감·모양별 눌린 홈·클랜 이름 각인으로 구성하며, 안에는 큰 배지만 진열한다. 미획득 배지는 빈 홈으로 표시한다.
- 기념/멤버/정규/깜짝 컬렉션과 창단, 정규 1·10·50·100·500회, 깜짝 1·10회, 1·3·5·10주년, 활성 멤버 10·20·50·100명의 16종을 제공한다. 시즌 배지의 조건은 후속 결정한다.
- 창단 그래픽은 사용자 선택인 [첫 깃발 에나멜 핀](../../design/clan-badges/founding-v1/README.md)을 케이스·대표 진열에 공통 사용한다. 배지명은 창단이며, 투명 PNG를 Next Image로 화면 크기에 맞게 제공한다.
- 주년 그래픽은 사용자 선택인 [자라는 역사 V3](../../design/clan-badges/anniversary-growth-v3/README.md)다. 1·3·5주년은 잎 1·3·5개, 10주년은 무성한 나무다. 테두리는 첫 깃발·성채와 같은 금빛 금속으로 통일한다. 미획득 홈은 1주년 방패 실루엣을 공통 사용한다.
- **모든 단계형 계열**은 달성한 최고 단계만 한 슬롯에 진열한다. 주년 5주년까지라면 5주년, 활성 멤버 20명까지라면 멤버 20명이다. 첫 달성 전에는 그 계열의 가장 낮은 빈 홈 하나를 표시하고 조건 미달 시 남은 최고 단계로 돌아간다. 선택한 상세 창 상단 좌측은 큰 배지, 우측은 이름/이야기/획득 방식/획득일·예정일/진척이며 하단은 계열의 전체 연관 케이스다. 모바일은 세로로 배치한다. 연관 배지 선택 시 상단을 갱신하며 미획득 그림은 회색 미리보기로 명시한다.
- 카탈로그의 `series`가 같은 주년·멤버·정규·깜짝 배지를 한 계열로 묶는다. `years` 또는 `target` 값으로 단계 크기를 비교하므로 카탈로그 순서에 의존하지 않는다. 이후 단계/계열도 같은 메타데이터를 지정하면 공통 진열과 상세를 사용한다. 창단 같은 단일 기념 배지는 독립 슬롯이다.
- 주년은 창단 시각에서 해당 UTC 연도를 더한 기준일에 획득하고 이름·획득 방식·획득일은 케이스 밖에 표시한다. 기존 1주년 키 `anniversary`와 UTC 윤일 이월 규칙은 유지한다. 신규 3·5·10주년은 기존 발급/대표/확인 테이블을 사용하며 스키마를 변경하지 않는다.
- 멤버 그래픽은 [우리의 성채](../../design/clan-badges/members-v1/README.md)다. 10·20·50·100명에서 1·3·5·7개 탑으로 성장하고 미획득 홈은 10명 아치 실루엣을 공유한다. 현재 `active` 인원만 세며 대기/탈퇴/차단은 제외한다. 조건 미달이면 발급을 회수하고 대표 진열에서도 제외한다. 획득일은 최초 조건 확인 시각이며 보유 중에는 유지하고 재획득 시 새 시각을 저장한다. 과거 달성일은 추정하지 않는다.
- 내전 성취는 종료된 해당 종류의 회차를 센다. 조건을 넘긴 실제 종료 시점에서 획득일을 복원하며, 알 수 없는 과거 날짜는 확인 필요로 둔다. 기록 정정으로 조건 미달이면 기존 판정과 같이 미획득으로 되돌린다.
- `clan_badge_awards`는 서버에서만 발급한다. 운영진이 고른 대표 계열 최대 3개는 `clan_badge_featured`에 저장하고 대시보드/운영 현황에 표시한다. 선택 전에는 진열 대상의 획득한 첫 3개를 사용한다. 저장된 과거 단계 대표는 그 계열의 현재 최고 단계로 표시하며 동일 계열의 여러 대표는 하나로 합친다. 이후 저장/해제는 현재 최고 키를 사용한다. 단계별 발급 기록은 유지한다.
- 단일 배지는 선택 시 팝업 없이 케이스 바깥의 이름·획득 방식·획득일을 갱신한다. 단계형 배지는 연관 케이스 상세를 함께 연다. 전체 케이스는 위의 고정 정보 행, 대표 진열은 아래의 정보 행을 사용한다. 미획득 진척은 획득 방식에 함께 표시한다. 분류를 바꾸면 표시 중인 배지로 선택 정보를 맞춘다. 대표 지정/해제는 일반 정보 행 밖과 현재 최고 단계의 상세에서 제공한다.
- 새 획득 확인은 `clan_badge_seen`에 사용자별로 기록한다. 새 핀 연출은 사용자/클랜/발급 이력별로 브라우저에 표시 여부를 저장해 반복 방문에서 재생하지 않으며 동작 축소 설정을 따른다.
