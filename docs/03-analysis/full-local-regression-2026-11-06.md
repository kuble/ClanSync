## 수정과 재현 근거

- 코칭 창: 열림 애니메이션의 95% 높이 456px을 기준으로 잡고 이후 실제 480px과 비교하던 검사였다. 확대가 끝난 뒤 높이를 기록하고 프로필 변경 후 높이 보존을 확인한다. `48e1b623`.
- 활동 상태: 검색이 실제 반영되기 전에 가상 시계를 진행한 실행에서는 5분 뒤 서버 재조회가 없었다. 필터 적용을 확인한 뒤 시간을 진행하고 실제 RSC 응답·활성 상태·검색값 보존을 검증한다. `391d5512`.
- 사진·프로필의 게시판 오류: 수정 없이 10회씩 반복했을 때 18 통과·2 실패였다. 서버 진단에서 두 실패 모두 `clan_peer_nicknames`의 502 응답을 확인했다. 공통 이름 조회에 기존 읽기 복구를 연결해 일시 오류만 150ms 뒤 한 번 재조회한다. SDK 중복 재시도는 끄며 인증·권한·취소 오류는 재시도하지 않는다.
- 게시판 재조회 버튼: 연속 502 뒤 기존 `reset`은 서버 데이터를 다시 읽지 않았다. 설치된 Next.js 문서의 `unstable_retry`로 교체했다. 이름 조회만 수정한 중간 검사는 사진·프로필·일시 오류 30회 통과, 버튼 복구 10회 실패였다. 두 수정 뒤 사진·프로필·일시/연속 오류 총 40회가 모두 통과했다. 저장 본문 보존과 자동 재조회 상한도 확인했다. `949f55a4`.
- 기록 재조회와 로그인 만료: 개발 모드 추가 검사에서 만료된 POST가 로그인 주소로 전달된 뒤 서버 액션을 찾지 못했다. 운영 모드는 동일 요청에서 액션을 찾아 통과했다. 재조회는 기존 stats GET API로 옮겨 두 모드에서 같은 401/403을 처리한다. `directory=1`은 날짜 목록·멤버 목록과 선택 날짜를 함께 읽으며 archive 요청만 허용한다. 응답 본문을 끝까지 읽어 권한 차단 본문도 검증한다. 이전 재조회 액션은 제거하고 저장 액션은 유지했다. 개발·운영 각각 7개를 통과했고 저장 RPC 1회·권한 복원·미로그인·잘못된 요청을 확인했다. `47818960`.

경매 단계, 관리 구형 주소, 홍보/320px, 코인 풀과 투표는 이번 첫 전체 실행에서 통과했다. DB 스키마·금액/정산·공통 인증 라우팅은 변경하지 않았다. 상류 502 자체의 내부 원인을 제거했다고 주장하지 않으며, 연속 실패는 기존 오류 안내와 사용자의 재조회로 처리한다.
