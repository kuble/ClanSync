# 클랜 탐색·가입·생성 상세 설계안

작성일: 2026-10-24 · 상태: 구현을 위한 제안 / 구현 전

[전체 변경 기획](../../01-plan/entry-experience-redesign.md)의 클랜 참여 화면을 구체화한다. 공통 색상·헤더·타이포그래피는 [공통 상세 설계](README.md)를 따르며, 이 문서는 목록에서 클랜을 이해하고 신청하는 과정과 생성 보조 흐름을 정의한다.

## 1. 현행과 변경 목표

현재 경로는 `/games/{gameSlug}/clan`이다. 로그인·해당 게임 인증이 필요하며 이미 소속된 사용자는 자신의 클랜 홈으로 이동한다. [페이지](../../../src/app/games/[gameSlug]/clan/page.tsx), [목록·상세·신청](../../../src/components/onboarding/clan-join-list.tsx), [액션](../../../src/app/actions/game-clan-onboarding.ts)을 기준으로 확인했다.

현재는 상세 모달에서 내용을 읽은 뒤 닫고 목록 카드의 별도 신청 폼을 열어야 한다. 상단 신청 안내와 고정 신청 카드도 같은 대기 상태를 반복한다. 이를 **목록 → 같은 맥락의 상세 → 신청 → 승인 대기**로 연결한다. 신청 성공을 가입 승인으로 표시하지 않는다.

| 유지 | 변경 | 추가하지 않을 요소 |
| --- | --- | --- |
| 게임별 소속·인증 규칙, 신청·취소·교체 액션, 선택 메시지 | 목록/상세 2열, 상세 안 신청, 대기 요약 1개, 생성 보조 진입 | 추천 점수, 허구 활동시간·접속률, 지원하지 않는 즉시 가입 |
| 클랜명·지향·티어 검색, 페이지 이동, 생성 후 리더 안내 | 공통 클랜 아이콘, 기존 배너/아이콘 재사용, 모바일 상세 복귀 | 모집과 관계없는 Premium 강조, 비회원용 내부 대시보드 노출 |

## 2. PC 구도와 읽기 순서

1024px 이상에서 최대 1280px 본문과 목록 44% / 상세 56%의 2열을 제안한다. 열 사이 간격은 24px, 각 열은 `min-width: 0`으로 긴 이름·ID가 전체 폭을 밀지 않게 한다. 수치는 구현 시 실제 문장과 화면으로 조정한다.

```text
[공통 헤더 / ClanSync]                         [게임 선택] [계정 메뉴] [테마]
오버워치                                                       클랜 만들기
클랜 찾기
함께 플레이할 클랜을 살펴보고 가입을 신청하세요.
[게임 선택 완료 — 게임 계정 연결 완료 — 클랜 참여]
[현재 신청: 클랜명 · 승인 대기]                    [상세 보기] [신청 취소]
[클랜명 검색             ] [지향 전체] [모집 티어 전체] [검색] [초기화]
클랜 N개 · 최근 생성순
┌ 목록 44% ──────────────────┐  ┌ 상세 56% ─────────────────────────┐
│ 아이콘 클랜명              │  │ 배너(있을 때)·아이콘·클랜명       │
│ 지향 · 모집 티어           │  │ 지향 · 인원/정원 · 창설일         │
│ 소개 최대 2줄 / 태그 2~3개 │  │ 소개 / 모집 조건 / 규칙           │
│ 인원/정원 · 상세 보기      │  │ 등록된 외부 커뮤니티 링크         │
│ 선택된 행의 테두리 강조    │  │ 신청에 사용할 내 전체 게임 ID     │
│ …                          │  │ 운영진에게 전달할 메시지 (선택)   │
│ [이전] 1 / N [다음]       │  │ [이 클랜에 가입 신청]             │
└────────────────────────────┘  └───────────────────────────────────┘
```

- 최초 진입에서는 첫 결과의 상세를 표시한다. 첫 항목이 선택되었다는 시각 표시와 상세 제목을 일치시키며 신청은 실행하지 않는다.
- 목록 항목은 상세를 여는 하나의 버튼이다. 이름·요약·상태를 버튼 안에 넣되 별도 신청 버튼을 중첩하지 않는다. 클릭 한 번으로 제출되지 않는다.
- 상세의 순서는 `클랜 소개 → 모집 조건 → 클랜 규칙 → 외부 링크 → 신청 정보`다. 긴 소개·규칙은 문단과 줄바꿈을 보존하고 내부의 짧은 고정 스크롤 상자에 가두지 않는다.
- 배너는 주행동보다 강하게 보이지 않게 높이를 제한한다. 배너가 없어도 제목·조건·신청 영역의 시작점이 과도하게 달라지지 않게 기본 표면을 둔다.
- 클랜 생성은 제목 옆 텍스트/보조 버튼으로 둔다. 가입과 생성의 동급 대형 탭은 없앤다.

## 3. 요소·문구·행동 계약

| 위치 | 표시 | 행동/규칙 |
| --- | --- | --- |
| 제목 | `클랜 찾기` | 선택 게임은 작은 상단 라벨로 표시 |
| 검색 | 라벨 `클랜명`, placeholder `클랜 이름으로 검색` | Enter 또는 `검색` 한 번으로 검색어와 두 필터 함께 적용 |
| 필터 | `지향`, `모집 티어`, 기본 `전체` | 임시 선택만으로 목록을 바꾸지 않고 검색 시 적용 |
| 목록 행 | 이름, 지향, 티어, 소개 2줄, 태그 최대 3개, 인원/정원 | 전체 태그는 상세에서 표시. 부재한 소개는 `등록된 소개가 없습니다.` |
| 상세 정보 | 소개·모집 조건·규칙·창설일 | 없는 티어/지향은 `제한 없음`을 추정하지 않고 `미등록`으로 구분 |
| 외부 링크 | `Discord 커뮤니티`, `카카오톡 커뮤니티` | 등록된 유효한 http/https URL만 표시. 새 창 안내와 외부 링크 표식 제공 |
| 내 게임 ID | `신청에 사용할 게임 ID` + 전체 배틀태그/라이엇 ID | 본인의 인증된 값만 읽기 전용 표시. 이메일·공통 닉네임으로 대체하지 않음 |
| 메시지 | `운영진에게 전달할 메시지 (선택)` | 안내 `간단한 소개나 궁금한 점을 적어 주세요.` + `현재 길이 / 2,000` |
| 제출 전 | `이 클랜에 가입 신청` | 필수 메시지·추가 신상·규칙 동의 체크를 새로 요구하지 않음 |
| 제출 중 | `신청 보내는 중…` | 버튼 크기 유지, 동일 제출 차단. 입력과 선택 맥락 유지 |
| 성공 | `신청 완료 · 운영진 승인 대기` | 메시지 입력 대신 보낸 메시지 표시, `신청 취소` 제공 |
| 정원 마감 | `정원 마감` | 상세 열람 가능, 신청 비활성. 조회 실패를 마감으로 표시하지 않음 |

게임 ID 수정이 필요하면 [게임 계정 연결](05-game-auth.md)의 기존 연결 관리로 안내한다. 인증 후 돌아올 안전한 목적지와 선택 클랜을 보존한다. 게임 연동의 개발·QA 시뮬레이터와 실제 외부 인증 제공 상태는 혼동하지 않는다.

## 4. 조회·공개 범위와 필드

| 데이터 | 현재 확인한 계약 | 설계에서의 사용/제약 |
| --- | --- | --- |
| 목록 | 같은 game_id, lifecycle_status=active, moderation_status=clean | 검색 결과와 상세가 같은 자격 기준을 사용하도록 확인 |
| 클랜 기본값 | id/name/description/rules/tags/max_members/style/tier_range/created_at/discord_url/kakao_url/subscription_tier | 현재 조회 가능한 필드 중 모집에 필요한 것만 표시. Premium 표식 제거 |
| 활성 인원 | `clan_active_member_counts` | 표시 대상 ID만 묶어 조회. 인원 조회 실패는 `인원 확인 불가` + 정원 표시 |
| 배너·아이콘 | 현재 가입 목록 조회/타입에는 없음 | 기존 클랜 자산의 실제 필드·비소속 조회 권한 확인 후 추가. 없으면 기본 아이콘/단색 배경 |
| 내 게임 ID | 현재 온보딩 상태 조회는 인증 여부 중심 | 본인 user_id·선택 game_id로 필요한 식별 필드만 조회하는 확장 필요 |
| 내 신청 | requestId/clanId/clanName/message | 본인의 선택 게임 신청만. 다른 신청자의 정보·메시지 조회 금지 |

- 이 화면의 ‘공개 정보’는 **로그인했지만 클랜 비소속인 사용자가 모집 판단을 위해 볼 수 있는 정보**다. 익명 공개로 정책을 넓히지 않는다.
- 구성원 명단·개별 게임 ID·계정 이메일·개인 기록·코인·내전 명단·가입 신청자 목록·운영진 전용 공지는 불러오지 않는다. 상세를 위해 클랜 내부 대시보드 조회를 재사용하지 않는다.
- 현재 가입 목록에서 조회하는 모집 소개·규칙·외부 링크만 사용한다. 추가 가입 조건 필드는 현재 목록 계약에 없으므로 조회/공개 범위 확정 없이 자동 표시하지 않는다.
- 서버 오류·DB 메시지는 사용자에게 필요한 설명으로 변환한다. 내부 식별자·쿼리·비밀값을 오류 UI에 내보내지 않는다.

## 5. 검색·페이지·선택 상태

현행은 `q/style/tier/page` 쿼리, 클랜명 검색어 trim 후 64자, `%/_` 제거 후 이름 부분 일치, 지향 4종·티어 8종의 허용 목록을 쓴다. 목록은 **5개/페이지, 생성일 내림차순**이다. 이 기준을 유지하고 같은 생성시각의 순서를 안정화할 ID 보조 정렬 추가를 제안한다. 검증하지 않은 ‘추천순’·최근 활동순은 추가하지 않는다.

- 검색 조건 변경 시 1페이지로 이동한다. 이전/다음에는 적용된 조건이 유지된다. 페이지는 유효 범위로 정규화하고 범위 밖 페이지는 마지막 유효 페이지로 교정한다.
- 결과 수는 서버의 같은 검색 조건 집계다. 페이지에 보이는 5개를 전체 수로 표시하지 않는다. 대기 요약을 위해 결과 밖의 신청 클랜을 읽어도 검색 결과 수를 증가시키지 않는다.
- 상단 현재 신청에 있는 클랜은 목록에서 중복 카드로 표시하지 않는다. 해당 항목을 제외한 페이지가 4개가 되어도 다른 페이지에서 임의로 채워 중복/누락을 만들지 않는다. 총 결과 수가 신청 클랜을 포함하면 `검색 결과 N개 · 신청 중인 클랜은 위에 표시`로 설명한다.
- 선택은 결과 안에 남으면 유지하고 제외되면 새 첫 항목으로 바꾼다. 단, 상단 `현재 신청 상세 보기`로 연 대상은 검색 결과와 별개라는 라벨을 표시해 유지할 수 있다.
- `selected=<clanId>`를 상세 상태로 사용하는 안을 제안한다. 현재 구현에는 없는 상태값이며 임의 ID로 내부 정보 접근이 열리지 않도록 게임·공개 자격·본인 신청을 다시 확인한다.
- 검색/페이지 이동으로 선택 클랜이 바뀔 때 초안이 있으면 §7 규칙을 먼저 적용한다. 제목이나 필터 값을 key로 삼아 전체 화면을 재생성하지 않는다.

## 6. 현재 신청과 제출·취소·교체 상태

현재 신청은 검색 위의 **요약 1개**에 클랜명·승인 대기·상세 보기·신청 취소로 표시한다. 메시지 전문과 중복 대기 카드는 요약 아래에 반복하지 않고 상세에 둔다. 검색 결과가 0개여도 요약은 남는다. 신청 조회 실패를 ‘신청 없음’으로 표시하지 않는다.

| 상태/계기 | 화면 처리 | 완료·실패 이후 |
| --- | --- | --- |
| 새 신청 | 본인 인증·대상 상태를 확인하며 제출 | 성공 시 서버 신청을 다시 읽고 대기 요약/상세를 동시에 갱신 |
| 같은 클랜 중복 제출 | `이미 이 클랜에 신청 중입니다.` | 상태 재조회 후 승인 대기 화면. 두 번째 신청 생성 금지 |
| 다른 클랜 신청 | `현재 「A」에 신청 중입니다. 취소하고 「B」에 새로 신청할까요?` | `기존 신청 유지` / `취소 후 새로 신청`을 확인창에 제공 |
| 단독 취소 | `「A」 가입 신청을 취소할까요?` | 취소 확정 전에는 대기 유지. 성공 후 요약 제거, 같은 상세에서 재신청 가능 |
| 취소 요청 중 | `취소하는 중…` | 실패하면 기존 대기를 사실 확인 후 유지하고 재시도 제공 |
| 교체 중 | 두 대상 이름과 `신청 바꾸는 중…` | 다른 취소/제출 차단. 취소와 새 신청을 하나의 성공으로 추정하지 않음 |
| 정원/모집/재가입 제한 변경 | 신청되지 않았다는 오류와 사유 | 상세 재조회. 전체 목록·초안을 지우지 않음 |
| 승인·거절 등 외부 처리 | 재방문/새로고침/제출 결과에서 확인 | 소속이면 해당 클랜으로 이동. 새 실시간 구독은 별도 범위 |

**교체 부분 실패:** 현행 `replacePendingJoinRequestAction`은 기존 pending을 canceled로 바꾼 뒤 새 신청을 호출한다. 원자적 교체가 아니며 기존 신청 자동 복구도 없다. 새 신청 실패 시 성공 토스트를 표시하거나 기존 신청이 남았다고 단정하면 안 된다.

실패 후 본인 소속·pending을 다시 읽어 ① A가 남으면 `기존 신청이 유지되었습니다.`, ② 신청이 없으면 `기존 신청은 취소되었지만 새 신청은 보내지 못했습니다.`와 B 재시도, ③ B가 있으면 대기, ④ 이미 소속이면 클랜 이동으로 정리한다. 재조회도 실패하면 `현재 신청 상태를 확인하지 못했습니다.`와 `상태 다시 확인`을 표시하고 확정되지 않은 중복 제출을 잠시 막는다. 원자적 교체로 변경하려면 별도 데이터 설계·회귀 검증이 필요하다.

## 7. 모바일 상세·뒤로가기·초안

1024px 미만에서는 한 열 목록을 기본으로 하고 항목 선택 시 **전체 화면 상세**를 연다. 작은 고정 높이 바텀시트에 소개·긴 규칙·메시지 입력을 모두 넣지 않는다.

```text
[클랜 목록으로]                선택 클랜명
[작은 배너·아이콘 / 이름·모집 정보]
소개 → 모집 조건 → 규칙 → 외부 링크
신청에 사용할 내 전체 게임 ID
운영진에게 전달할 메시지 (선택)
[오류/승인 대기 상태]
[이 클랜에 가입 신청]
```

- 목록에서 상세를 열 때 브라우저 이력에 상세 상태를 한 번 추가한다. 뒤로가기는 상세를 먼저 닫고 검색어·필터·페이지·목록 스크롤·선택한 행을 복원한다. 앞으로가기는 같은 상세를 복원한다.
- 상세 주소로 직접 들어온 경우 목록으로 돌아가기에서 같은 게임의 현재 검색 목록을 열고, 존재하지 않는 내부 이력을 가정해 외부 페이지로 보내지 않는다.
- 같은 방문 중 입력한 메시지는 userId/gameSlug/clanId별 메모리 초안으로 보관한다. 상세 닫기/복귀·반응형 전환만으로 초기화하지 않는다. 새로고침 이후의 영구 초안 저장은 이번 기본안에 포함하지 않는다.
- 다른 클랜 선택, 선택이 제외되는 검색, 생성 화면 이동 시 미전송 내용이 있으면 `작성 중인 메시지가 있습니다.` + `계속 작성` / `초안 남기고 이동`을 제공한다. 후자는 현재 방문에서만 보존됨을 알린다. 기본 행동은 계속 작성이다.
- 게임/계정 변경·로그아웃 시 이전 초안과 조회 응답을 폐기한다. 다른 계정에서 이전 메시지를 복원하지 않는다. 신청 성공 시 해당 초안은 보낸 메시지로 대체한다.
- 메시지 입력 시 가상 키보드와 safe-area를 고려한다. 기본은 본문 끝의 버튼이며 고정 버튼을 적용한다면 본문 하단 여백을 확보하고 키보드 위에서 오류·입력을 가리지 않는다.

## 8. 로딩·빈 결과·오래된 상세

- 최초 조회는 목록과 상세의 예상 높이 안에서 스켈레톤을 표시한다. 검색 갱신 중에는 제목·검색·필터·현재 신청·열 외곽을 유지하고 데이터 영역에 `결과를 불러오는 중…`을 표시한다.
- 적용 중인 조건과 이전 조건을 분리한다. 이전 상세를 잠시 보존할 때는 `검색 결과 갱신 중`을 표시하고 신청을 비활성화한다. 응답 후 선택/상세/결과 조건을 함께 확정한다.
- 빠른 연속 검색·페이지 이동은 마지막 요청만 반영한다. 게임·계정·선택이 바뀐 뒤 도착한 이전 상세 응답은 폐기한다.
- 0개는 `조건에 맞는 클랜이 없습니다.`와 `검색 조건 초기화`, 보조 `클랜 만들기`를 표시한다. 목록 오류는 `클랜 목록을 불러오지 못했습니다.`와 같은 조건의 `다시 시도`를 제공한다.
- 상세만 실패하면 목록은 계속 탐색할 수 있다. 상세 영역에 실패/재시도를 표시하며 이전 클랜의 신청 버튼을 새 제목 아래 남기지 않는다.
- 인원 수 미조회는 0명으로 바꾸지 않는다. 신청 가능 여부와 정원 검증은 제출 시 서버의 실제 결과로 판정하며 UI 비활성만으로 보장하지 않는다.

## 9. 보조 흐름: 클랜 만들기

제목 옆 `클랜 만들기`로 같은 경로의 생성 화면을 연다. `mode=create`는 제안하는 표시 상태다. 상단 `클랜 찾기로 돌아가기`로 필터·페이지·목록 스크롤을 복원하고, 모바일 뒤로가기도 같은 역할을 한다. [기존 생성 폼](../../../src/components/onboarding/clan-create-form.tsx)을 재배치하며 새 별도 생성 기능을 만들지 않는다.

| 순서 | 입력·현재 계약 | 배치/안내 제안 |
| --- | --- | --- |
| 1 기본 정보 | 클랜명 필수 1~24자, 소개·규칙 선택 | `우리만의 클랜 만들기` / `생성하면 클랜장이 됩니다.`. 소개·규칙은 서로 다른 입력 |
| 2 모집 조건 | 지향 선택 4종, 티어 8종 복수 선택 | 선택 항목으로 묶고 현재 값 유지 |
| 3 태그·정원 | 태그 최대 5개·각 1~12자(한글/영문/숫자/공백), 쉼표 구분; 정원 2~200·기본30 | 태그 개수/규칙 표시. 정원은 정수 입력으로 명확히 검증하는 보완 필요 |
| 4 부가 모집 조건 | 출생연도 선택, 성별 all/male/female·기본all | 선택 접기로 정보량 축소. 정책 자체를 삭제하거나 강화하지 않음 |
| 5 외부 링크 | Discord/카카오 URL 선택 | `커뮤니티 초대 링크이며 자동 알림 연결과는 다릅니다.` |
| 6 완료 | `클랜 만들기` | `처리 중…` 후 기존 리더 환영 경로로 이동 |

소개·규칙·URL은 현재 폼/액션에 명시된 글자 상한이 없다. 새 상한을 현재 계약으로 적지 않으며 구현 전 DB 제한과 서버 검증을 대조한다. URL은 현재 브라우저 type=url과 읽기 시 http/https 검사가 있으나 제출 서버에서 허용 프로토콜 검증을 보완할 필요가 있다. 출생연도는 현재 라벨이 ‘최소’인데 선택 문구는 ‘N년생 이전’이므로 조건의 실제 의미를 확인한 뒤 문구를 확정한다. 화면 재배치로 새로운 연령 기준을 만들지 않는다.

- 생성 중 폼값/레이아웃을 유지하고 중복 제출을 막는다. 필드 오류는 해당 입력으로 연결하고 요청 오류는 폼 안에 표시한다. 실패 후 입력값과 선택 항목을 보존한다.
- 현행 생성은 클랜 생성 후 리더 소속 삽입이며 소속 삽입 실패 시 생성 클랜 삭제를 시도한다. 트랜잭션 성공/자동 완전 복구를 화면에서 약속하지 않는다. 불확실한 결과는 소속을 확인한 뒤 재시도한다.
- **별도 동작 변경 제안:** 현재는 같은 게임의 pending을 취소하지 않고 클랜 생성이 가능하며, 현행 액션도 신청을 자동 취소하지 않는다. 생성 전 명시 취소를 요구하는 안은 가입 정책/동작 변경이므로 이번 배치 개편의 확정 조건에 넣지 않는다. 이 안을 채택한다면 기존 신청을 별도로 취소·확인한 뒤 생성하고, 취소 실패 시 생성 중단·취소 후 생성 실패 시 초안 보존을 검증한다. 무음 취소나 두 동작의 원자적 처리를 약속하지 않는다.

## 10. 생성 후 리더 환영·Discord 연결

기존 `/games/{gameSlug}/clan/{clanId}/welcome`을 사용한다. [현재 환영 페이지](../../../src/app/games/[gameSlug]/clan/[clanId]/welcome/page.tsx)는 리더만 열며 다른 역할은 클랜 홈으로 이동한다.

1. 제목 `클랜을 만들었어요`와 생성한 클랜명을 표시한다. `멤버를 초대하기 전에 기본 정보를 확인하고 클랜 활동을 시작하세요.`를 짧게 제공한다. 별도 초대 코드·초대 링크 기능을 새로 약속하지 않는다.
2. `Discord로 클랜 소식 이어가기`에 기존 알림 장면을 최대 필요한 만큼 보여주고 `Discord 자동 알림은 Premium 기능입니다. 연결 상태와 플랜은 설정에서 확인하세요.`를 함께 표시한다.
3. `Discord 알림 설정`은 기존 `/manage?tab=notifications`로 이동한다. 버튼을 누른 것만으로 봇/서버/채널 연결이나 알림 발송이 완료된 것처럼 표시하지 않는다.
4. 동급의 이해 가능한 탈출 행동 `나중에, 클랜으로 이동`은 클랜 홈으로 보낸다. Discord 설정·외부 계정 입력을 클랜 생성의 필수 완료 조건으로 만들지 않는다.

실제 Discord 설정·권한·외부 전송은 [기존 연결 안내](../../guides/discord-bot-setup.md)의 범위다. 현재 앱 키 설정과 분 단위 워커/실제 수신 검증 잔여를 구분하며, 이 재설계로 새 외부 설정을 수행하거나 완료로 기록하지 않는다.

## 11. 접근성·수용 시나리오

목록은 ul/li와 명시적인 상세 열기 버튼, 선택은 색과 함께 aria-current 등으로 전달한다. PC 상세 제목은 영역의 접근 가능한 이름이 된다. 모바일 상세 열림 시 제목으로 초점 이동, 닫기 시 원래 목록 버튼으로 복귀한다. 목록 버튼의 일반적인 Tab/Enter 조작을 유지하며 불완전한 listbox 키보드 동작을 만들지 않는다. 필터 label, 글자 수 설명, aria-invalid/오류 연결, 제출 aria-busy, 성공 role=status를 제공하고 터치 목표는 최소 44px로 한다.

| 확인할 상황 | 수용 기준 |
| --- | --- |
| 첫 결과·긴 이름·아이콘/배너 없음 | 선택과 상세가 일치하고 320px에서도 가로 넘침 없음 |
| 검색·지향·티어·페이지·0개/오류 | 조건/페이지가 맞고 외곽·현재 신청 유지. 실패를 0개로 오인하지 않음 |
| 빠른 검색·선택 제외·상세 조회 실패 | 이전 상세/신청 버튼이 새 결과처럼 남지 않음 |
| 모바일 상세·뒤로/앞으로·직접 주소 | 상세부터 닫히고 필터/스크롤/선택/같은 방문 초안 복원 |
| 새 신청·중복·취소·다른 클랜 교체 | 승인 대기 1개와 실제 서버 결과 일치 |
| 교체 취소 성공/새 제출 실패·재조회 실패 | 기존 신청 유실 여부를 사실대로 안내하고 중복 성공 표시 없음 |
| 정원 변경·모집 중단·재가입 제한·인증 해제 | 실패 사유/다음 행동 표시, 초안 보존, 접근 권한 재확인 |
| 생성 유효값·실패·pending 보유·리더 환영 | 입력 보존, 현행 pending 처리와 별도 변경안 구분, 건너뛰기·설정 연결 경로 정상 |
| 다른 계정/게임 전환·로그아웃 | 이전 ID·신청·메시지·늦은 응답 폐기 |
| 키보드·확대·라이트/다크·모션 감소 | 읽기/초점 순서·선택/오류 식별·전체 화면 상세 닫기 정상 |

기존 시작점은 [온보딩](../../../e2e/onboarding.spec.ts), [가입 신청](../../../e2e/join-request-flow.spec.ts), [재가입](../../../e2e/clan-membership-return.spec.ts)이다. 기존 테스트가 위 제안까지 검증했다는 뜻은 아니다. 공유 QA 계정을 변경하는 가입 테스트를 그대로 실행하지 않으며 구현 검증은 별도 임시 사용자·클랜, `E2E_SKIP_SEED=1`, E2E 전용 3010 서버를 사용한다. 사용자 QA 3011과 기존 명단은 보존한다.

이번 문서 작업에서는 앱·DB·외부 연결을 변경하지 않았으며 빌드/E2E를 실행하지 않았다. 조회 필드·권한·공통 라우팅을 실제 변경할 때 관련 회귀와 빌드를 포함한다.
