# 편성 방식과 공유 화면 — 기준안 v0.1

작성: 2026-09-16 · 관련 논의: [D-UX-03](../01-plan/product-design-evolution.md#ux-03)

**상태: 역할 선고정과 세션·라운드·사이트 참여 정의는 사용자 확정이다. 아래 실제 적용 범위는 QA 구현 기준이며, 지명 시간 제한·정정 등 후속 제안의 구현 완료를 뜻하지 않는다.** 확정한 수동 명단 입력 UI를 유지하면서 라운드의 편성 시작·진행·결과 공개를 구체화한다.

## 실제 페이지 적용 범위 (2026-09-16)

`codex/live-session-formation`의 QA 앱에 실제 저장·권한·실시간 연동을 적용했다. 운영 반영은 보류한다. 전체 검증 결과와 DB 적용 상태는 [Phase 2](../TODO_Phase2.md)를 따른다.

- **명단:** 선택·우클릭·드래그·되돌리기를 자동 저장한다. 편성·설정 적용 전 미완료 저장을 기다리며 동시 편집은 로컬 변경 보관과 명시적 충돌 해결로 처리한다.
- **선호:** 프로필의 게임별 선호를 기본으로 쓰고 본인이 이번 라운드만 변경할 수 있다. 역할명 목록 대신 역할 아이콘 3개와 순위 숫자를 표시하고 드래그·두 아이콘 클릭·좌우 방향키로 교환한다. 이름은 툴팁과 접근성 이름으로 제공한다. 프로필 복귀와 명시적 `선호 없음`을 구별하며 화면을 보기만 해서는 순위를 저장하지 않는다. 미설정/선호 없음은 자기 차례에 남은 역할 자리에서 추첨하며 운영진에게 순위표를 공개하지 않는다. 체크인·선호 제출 완료 대기는 없다.
- **라운드 선호 표시:** 평소에는 `내 선호` 메뉴와 세 역할 아이콘만 표시한다. `프로필 기본값`·`선호 없음`·`프로필에서 기본값 설정`은 메뉴 안에 모으고 선택 즉시 닫는다. 설명은 접근성 안내에 두며 저장 중에는 스피너, 실패 시에는 오류를 표시한다. 빈 순위와 프로필 상속은 메뉴의 선택 상태로 구분한다.
- **규칙:** 직접 역할 배정/공통 추첨순서와 현재 팀 유지/역할별 팀 추첨/주장 지명/경매를 조합한다. 설정 패널에서 같은 역할 주장, 경매 예산·최소/증액 단위·제한 시간, 맵/영웅 밴을 저장한다. 역할 추첨을 쓰면 추첨으로 탱커가 된 두 명이 주장이 된다. 다음 라운드에는 규칙·밴픽을 이어 쓰고 개별 주장 지정·라운드 선호는 초기화한다.
- **저장·동기화:** 설정 적용은 부모 화면이 저장 이후 버전을 받으면 완료하며 적용 중에는 패널을 닫지 않는다. 편성 시작은 클릭 당시 명단·규칙·밴픽·추첨 이력 길이를 대조한 뒤 최신 비공개 선호를 해석하고 revision CAS로 저장한다. 선호만 갱신된 버전은 허용하되 초기화 전의 오래된 시작은 거부한다. 실시간 구독 준비 시 누락을 재조회하고 활성 라운드는 2초마다 작은 revision 상태를 비교한다. 개별 투표·예측 등의 복구는 30초 전체 갱신을 사용한다.
- **공개 화면:** 역할 추첨은 아래 §5의 **18초 팝업**으로 운영진·클랜원에게 함께 공개한다. 역할 직접 배정 뒤 팀만 추첨하면 기존 4초 보드를 사용하고, 직접 배정+현재 팀 유지에는 추첨 연출을 넣지 않는다. 결과 다시 보기·상시 안내 패널은 두지 않는다. 중복된 방송용 전체 화면 모달은 제거하고 클랜원 전용 화면으로 공개 내용을 전달한다.
- **안내·기록:** 안내 아이콘으로 단계별 강조 설명을 연다. 클랜장·운영진은 최근 30세션의 기록을 조회하고, 일반 멤버는 기록 아이콘을 숨긴다. 예외로 깜짝 개설자는 열린 자기 세션 기록만 조회하며 서버도 같은 범위를 검사한다. 깜짝 내전 종료 시 임시 기록은 삭제한다. 편성 이력에는 추첨 순서·시각·운영 규칙·초기화가 남고 개인 선호·베팅은 제외된다.

역할 손들기 채팅 수집·불가 역할·실력 자동 균형·지명 시간 제한·자동 경매 마감·클랜별 세션 간 설정 보존은 후속이다. 기존 승부예측은 기존 자격/5분/5코인 보상 정책을 유지한다.

## 경기 시작 전 밴픽 설정 (2026-09-16)

- 역할·팀 편성 규칙은 편성 시작 전에 정한다. 맵 밴·영웅 밴 사용 여부와 제한 시간은 **경기 시작 버튼을 누르기 전까지** 설정에서 변경한다. 편성 중·완료 후에도 밴 설정 변경은 기존 역할·팀을 유지한다.
- 각 투표 제한 시간은 5~300초 정수이며 기본 맵 15초·영웅 20초다. 서버의 마감 시각을 기준으로 투표를 닫으며 다음 라운드에도 설정을 이어 쓴다.
- 편성 결과 확인 후 **편성 적용**을 누르면 맵 전용 화면으로 이동한다. 적용 상태는 기존 편성 데이터에 저장되어 클랜원·재접속 화면에도 반영된다. 멤버가 아직 확인하지 않은 역할 추첨 팝업은 맵 단계에서도 본인이 닫을 때까지 유지한다. 팀 명단과 밴 설정은 **라운드 도구** 드로워로 옮기고 가이드는 현재 화면의 조작을 안내한다.
- 맵 투표는 **편성 시작 → 편성 결과 → 편성 적용 → 맵 유형 선택 → 맵 투표** 순서다. 운영진이 **전체 / 쟁탈 / 밀기 / 화물 / 혼합**을 고르고 **유형 선택 완료**를 누르면 즉시 후보 3개와 투표가 열린다. 전체는 단독 선택, 나머지는 복수 선택이며 별도의 맵 밴 시작 화면은 없다.
- 수동 맵 선택은 **편성 적용 → 유형 선택 → 이미지 아코디언에서 맵 선택 → 경기 시작** 순서다(영웅 밴을 켜면 경기 시작 전 영웅 밴 진행). 선택한 맵을 넓게 펼쳐 강조하며 저장 성공 후 다음 버튼을 활성화한다. 맵 선택은 자동 저장되어 모든 클라이언트·라운드 기록에 반영된다. 투표와 결과 팝업에도 같은 실제 전장 이미지를 사용한다.
- 맵·영웅 투표 확정은 경기 시작과 별개다. 맵 및 필요한 영웅 밴 결과를 확인한 뒤 운영진이 **경기 시작**을 누르면 설정을 잠근다.
- 설정 변경 시 영향받는 투표·결과를 초기화하고 준비 화면으로 돌아간다. 맵 설정 변경은 맵·영웅 투표를 초기화한다. 영웅 설정만 바꾸면 확정된 맵을 보존한다. 브라우저가 표시한 마감 시각을 함께 검증해 재시작 전 투표의 지연 제출을 거절한다. 수동 맵을 실제로 바꾸면 기존 영웅 밴을 다시 진행한다.
- 실제 맵 추첨은 저장된 서버 결과를 배경 블러 팝업으로 공개한다. 새로 접속한 사람에게 다시 추첨하지 않는다. QA 관리자 설정의 **QA 맵 투표 연출**은 3·5·2표를 가상으로 보여 주며 실제 표·맵·기록을 변경하지 않는다.

## 1. 범위와 전제

- **세션은 당일 내전 전체, 라운드는 경기 한 판**이다. 내전 날짜는 세션 개설일로 고정하고 종료 시점까지의 라운드·회차를 기록한다([D-SESSION-01 용어 기준](../01-plan/glossary.md#내전-운영-용어)).
- 편성 대상은 **해당 라운드 출전자 10명·2팀**, 각 팀 **탱1·딜2·힐2**다. 관전자 명단 입력·출전자 선발은 이 편성의 범위에 포함하지 않는다. 세션에 사이트로 참여할 수 있는 클랜원을 10명으로 제한한다는 뜻은 아니다.
- 손들기·선호 추첨은 **역할 배정**, 주장 지명·경매는 **팀 구성**이다. `손들기 → 지명`, `선호 추첨 → 경매`처럼 조합한다.
- **사용자 확정:** 역할을 먼저 정하고 팀원을 선발한다. 지명·경매 중에는 역할을 변경하지 않는다.
- 지명·경매 시작 전에 전체 역할 **탱2·딜4·힐4**, 같은 역할의 주장 2명 포함, 팀별 목표 **탱1·딜2·힐2**를 검증한다. 이 조건에서는 남은 역할 자리에만 영입하면 끝까지 정원을 채울 수 있다.
- 역할 배정만 마치면 팀 구성은 아직 미완료다. 수동 배치 또는 별도로 선택한 자동 밸런스 단계로 이어진다. 자동 밸런스 알고리즘을 이 문서에서 확정하지 않는다.
- 세션이 열리면 클랜원은 사이트에서 실시간으로 참여하고 기능별 권한·진행 상태에 맞는 조작이나 베팅을 할 수 있다. 웹을 사용하지 않는 출전자에 대해서는 게임·디스코드 의사를 운영진이 대신 반영할 수 있다. 매 라운드 로그인·체크인을 강제하지 않는 방향과 사이트 참여 기능은 함께 유지한다.
- 같은 세션의 다음 라운드에는 저장한 방식을 불러오며, 이번 10명·역할·주장·시간·예산은 시작 전에 운영진이 확인한다. 세션 간 클랜 기본 설정 저장은 후속이다.
- 프로필 선호, 불가 역할, 개인 점수는 공유 화면에 기본 노출하지 않는다. 경매 포인트를 실력 점수·선수의 가치로 표현하지 않는다.

## 2. 운영 화면·클랜원 참여 화면·공유 화면

| 구분 | 운영진 조작 화면 | 클랜원 참여 화면 |
|---|---|---|
| 목적 | 세션·라운드 운영, 입력·중지·정정 | 사이트에서 실시간 확인·참여 |
| 기본 내용 | 설정, 가능한 후보, 접수 결과, 변경 이력 | 내전 날짜·현재 라운드, 같은 편성 진행, 본인에게 허용된 행동 |
| 개인 정보 | 권한에 맞는 선호·배정 조건 | 본인의 입력·접수 상태와 허용된 정보 |
| 조작 | 부여된 운영 권한과 대리 입력 | 해당 기능·역할·차례에 허용된 조작 및 라운드 베팅 |
| 접속 | 운영 권한이 있는 클랜원 계정 | 열린 세션에 클랜원 계정으로 접근 |

- 방송용 모달과 진입 버튼은 제거했다. 클랜원 전용 화면의 공개 내용과 기능별 참여 권한을 유지한다.
- 날짜·라운드 번호는 편성 카드 헤더에 통합한다. 일반 관전자에게 설정·편집/초기화·운영 가이드·내전 기록 아이콘을 숨긴다. 깜짝 개설자는 자기 세션 기록만 볼 수 있다.
- 세션 종료는 편성 시작 왼쪽의 기존 방식 설명 위치에 빨간 버튼으로 배치한다. 맵 선택·경기 단계에도 하단에 유지하며, 미확정 경기에서는 결과/무효 기록 후 활성화한다. 종료 확인창은 깜짝 기록 삭제와 정규 기록 보존을 구분해 알린다.

### 점수·예측 비교 UI (2026-09-16)

- 정규 내전의 운영진 화면에 M/A 점수 토글을 제공한다. Free는 M만, Premium은 M/A 중 하나만 표시한다. 멤버와 깜짝 방에는 점수·예측 비교 영역을 전달하지 않는다.
- 최근 정규 라운드 100개에서 사용자별 가장 최근 저장 점수를 읽고 현재 라운드 값을 우선한다. 역할별 누적 실력 모델이 아니며, 기록 없는 값은 `—`로 표시한다. 편집 슬롯의 점수와 두 팀 합계/차이는 같은 토글을 따르고 선수 교환 시 즉시 갱신한다.
- Premium의 팀 비교 영역에 일반 예측 승률과 맵 반영 승률의 좌우 수치/막대·신뢰도/표본 자리까지 구현한다. 모델 미연결 상태는 빈 막대와 `—`, ‘예측 준비 중’으로 표시하며 임의의 50%를 만들지 않는다. 명단 미완성·맵 미선택은 별도로 안내한다.
- 수동 맵 클릭 즉시 선택 맵과 비교 영역을 함께 갱신하고 저장 실패 시 이전 맵으로 복구한다. 향후 예측 결과는 명단·점수 종류/값·맵 식별값이 현재 상태와 일치할 때만 표시하므로 이전 맵의 늦은 결과를 재사용하지 않는다. 실제 예측 모델·학습·역할/맵 보정 수치는 후속이다.
- UI 참고: [NN/g 점진적 공개](https://www.nngroup.com/articles/progressive-disclosure/)에 따라 자주 쓰는 순위 변경은 바로 제공하고 부가 옵션만 메뉴로 옮긴다. 메뉴의 키보드·포커스 동작은 [WAI Menu Button](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/) 기준과 기존 Base UI 컴포넌트를 따른다.
- 사이트를 통한 실시간 참여 가능은 확정이다. 주장 지명·입찰 등 **개별 기능의 직접 입력 주체·권한·대리 입력 전환 규칙**은 구체화할 항목이다. 동시에 들어온 대리 입력과 직접 입력을 중복 반영하지 않는다. 세션 접근만으로 전체 명단 편집 권한을 주지 않는다.
- 베팅은 라운드 승부예측이며 팀원 경매의 입찰과 다르다. 기존 Premium·해당 라운드 비출전·마감 조건을 유지한다. 편성 화면의 공개가 베팅 접수 시작을 뜻하지 않는다.
- 역할 배정 중에는 중앙에 현재 사람/역할, 하단에 미배정 인원과 역할별 남은 정원을 보여 준다. 역할만 정해진 사람을 특정 팀에 확정된 것처럼 놓지 않는다.
- 팀 구성 중에는 좌우 팀의 **딜·딜·탱·힐·힐**을 고정하고 가운데에 현재 지명·경매 대상을 둔다. 남은 후보는 하단에 둔다.

## 3. 공통 진행 상태와 변경 규칙

아래는 **라운드 안 편성 과정**의 상태다. 편성 완료·라운드 종료·세션 종료는 서로 다르며, 결과 기록 후 같은 세션에서 다음 라운드를 진행할 수 있다.

| 상태 | 허용되는 행동 | 공유 화면 |
|---|---|---|
| 준비 | 명단·선호·역할·주장·규칙 점검, 시작 | 방식과 참가자, 시작 대기 |
| 진행 | 현재 차례에 맞는 배정·지명·유효 입찰 접수 | 현재 단계, 확정 결과, 남은 시간 |
| 중지 | 시간 정지, 원인 확인, 재개 또는 정정 | `진행 중지`와 마지막 확정 상태 |
| 완료 | 기존 참가자 보드에서 결과 확인, 밴픽/경기 진행 | 최종 역할·팀과 완료 상태 |
| 정정 | 수정 범위 미리 보기, 변경 사유 기록, 다시 검증 | `정정 중` 후 바뀐 이름·역할·예산만 짧게 표시 |

- 실제 결과는 서버가 확정하고 공유 화면은 이를 표현한다. 애니메이션 종료가 결과 접수·타이머의 기준이 되지 않는다.
- 지명·입찰은 편성 식별자·진행 버전·요청 식별자를 검증한다. 중복 요청, 이전 차례의 클릭, 정지 중 요청은 적용하지 않고 조작자에게 이유를 보여 준다.
- 재접속은 최신 확정 상태로 복구하며 이미 공개한 결과를 다시 추첨하거나 장면 전체를 재생하지 않는다. 공유 화면 연결이 끊기면 연결 상태와 마지막 갱신 시점을 표시한다.
- 시간제 진행 중 조작 연결이 끊기면 서버에서 중지 처리하는 경로를 마련한다. 연결 상태 판정 전 만료된 단계는 서버 이력을 기준으로 복구하며 소급 접수하지 않는다.
- 시작 후 명단·역할 변경은 진행 중지와 정정을 거친다. 이후 선택에 영향을 주면 **영향받는 단계 이후를 취소**할 범위를 먼저 보여 준다.
- 다시 보기 버튼은 제공하지 않는다. 명단 수정 후 새 편성은 새로운 추첨이며, 서버 이력에 이전 시작·초기화·다음 시작을 모두 보존한다. 세밀한 정정 사유 입력·영향 범위 확인은 후속이다.
- 최종 팀 구성 완료 조건은 중복 없는 10명, 양 팀 5명, 팀별 역할 정원 충족이다. 미배정자가 남았는데 완료로 표시하지 않는다.

## 4. 기존 방식 — 게임 채팅 손들기

아래는 기존 클랜 운영 방식과 후속 수집 UI 제안이다. 현재 앱에서는 게임 채팅 순서를 운영진이 확인해 확정한 수동 명단에 직접 반영하며, 별도 역할 모집 화면이나 채팅 자동 수집은 제공하지 않는다.

**시작 조건:** 출전자 10명과 역할 정원이 있고 운영진이 모집 순서를 선택했다. 기존처럼 역할별로 모집하는 방식을 유지하며 특정 순서를 공정성 개선으로 설명하지 않는다.

1. 운영진이 모집 역할을 열면 공유 화면 중앙에 `딜러 모집 · 4자리`처럼 표시한다.
2. 게임 채팅의 `손` 순서를 운영진이 확인하고 해당 이름을 한 번씩 선택한다. 해당 역할에 순차 배정하며 정원이 차면 다음 역할로 넘어간다.
3. 이미 배정된 사람은 후보에서 빠진다. 다른 역할로 변경하려면 기존 배정을 취소한 뒤 다시 반영한다.
4. 역할 10명 배정 완료 후 선택한 팀 구성 단계로 이어진다.

**예외:** 채팅 도착 순서가 다르게 보이거나 동시 지원이 있으면 운영진이 확인한 순서를 기준으로 결정한다. 앱이 채팅을 자동 읽거나 선착순을 검증한 것처럼 표시하지 않는다. 지원자가 부족하면 해당 역할을 남겨 두고 모집을 이어가며 남은 사람을 강제로 배정하지 않는다.

**공유 연출:** 확정한 이름이 역할 영역으로 약 **400ms**에 이동하고 남은 정원만 갱신한다. 선착순 순위표·낙선 연출은 만들지 않는다. 마지막 사람까지 배정되면 역할별 결과를 한 화면에 정리한다.

## 5. 선호 추첨 — 공통 무작위 순서

**시작 조건:** 확정된 출전자 10명의 프로필 기본값 또는 본인이 저장한 이번 라운드 선호를 사용한다. 선호가 없어도 시작할 수 있다. 미설정/명시적 `선호 없음`인 사람에게 임의 순위를 만들지 않고 그 사람의 차례에 남은 역할 자리를 추첨한다.

1. 운영진이 시작하면 **10명의 무작위 순서와 그 순서로 계산한 역할 결과를 저장**한다.
2. 순서가 앞선 사람부터 남은 정원 중 가장 선호하는 역할을 받는다. 정원은 전체 탱2·딜4·힐4다.
3. 계산이 완성됐으면 저장한 추첨 순서에 따라 역할 결과를 공개한다. 화면 연출은 저장된 결과를 표현하며 계산·접수·재추첨을 실행하지 않는다.
4. 역할 결과 확인 후 선택한 팀 구성 단계로 이어진다. 팀 재구성만 실행할 때는 역할 추첨 결과를 유지한다.

**공정성 설명:** 모두 같은 무작위 순서 기회를 갖는다. 모든 1지망을 먼저 채우는 규칙은 아니며 앞사람의 2지망 때문에 뒷사람의 1지망이 마감될 수 있다. 기본안은 독립 추첨이며 연속판 보정·점수 보정은 포함하지 않는다.

**불가 역할:** 첫 기준안은 세 역할을 모두 수용할 수 있는 경우의 단순 순차 배정이다. 불가 역할을 허용하면, 가능한 전체 배정이 있어도 단순 순차 배정이 막힐 수 있다. 해결 알고리즘을 별도로 정하기 전에는 불가 역할이 있는 상태에서 자동 추첨을 시작하지 않고 수동 합의로 연결한다. 동순위 선호도 임의 순서로 해석하지 않는다.

**예외:** 정원·선호 변경으로 완료할 수 없으면 결과 공개 전에 중지한다. 역할 부족을 강제 배정·무통보 재추첨으로 해결하지 않는다. 이미 추첨한 뒤의 수정은 이전 순서·사유를 기록한다.

**공유 연출:** 역할 추첨 시작 시 운영진·클랜원 화면에 배경 블러 팝업을 연다. 처음 3초는 전체 추첨 순서와 본인 순번을 읽는 시간이며 이후 약 1.5초씩 역할을 공개한다(총 18초). 본인 순번은 상단에 고정하고 현재 차례·역할·남은 정원·전체 진행을 표시한다. 1·2·3지망 여부나 비공개 선호는 공개하지 않는다. 결과는 자동으로 사라지지 않고 각자 확인/닫기로 닫는다. 닫아도 다른 클라이언트나 추첨은 변하지 않으며 본인 순번·역할은 보드 위에 남는다. 재접속은 현재 시점에 합류하고 완료 뒤에는 팝업을 다시 띄우지 않는다. 동작 줄이기 설정에서는 결과를 바로 표시한다.

## 6. 주장 지명 — 두 주장과 8번의 선택

**시작 조건:** 전체 역할 정원이 맞고 같은 역할의 주장 2명을 선정했다. 두 주장도 10명에 포함되며 자기 팀의 해당 역할 1자리를 차지한다. 주장 선정은 운영진 지정이 기준안이고 자동 실력 균등 선정을 가정하지 않는다.

1. 먼저 지명할 팀 A를 추첨·저장한다. 다른 팀은 B이며 화면에는 실제 팀 이름과 함께 순서를 표시한다.
2. 남은 8명 지명 순서는 **A → B → B → A → A → B → B → A**다. 각 팀이 4명씩 선택한다.
3. 현재 주장이 음성으로 이름을 말하면 운영진이 한 번 선택해 확정한다. 직접 지명 모드에서는 현재 주장만 같은 동작을 실행한다.
4. 자기 팀에 남은 역할 자리와 맞는 후보만 선택할 수 있다. 불가능한 후보는 가리고 넘어가기보다 선택 불가 이유를 명확히 표시한다.
5. 확정 후 다음 순번으로 이동한다. 같은 팀의 연속 차례도 `다시 A팀 차례`로 구별한다. 8번 선택하면 최종 팀을 공개한다.

**시간 제안(미구현):** 지명당 **30초**와 시간 초과 시 중지는 후속 제안이다. 현재는 시간 제한 없이 현재 주장 또는 운영진이 선택하고, 자동 무작위 지명은 하지 않는다. 선택 가능한 사람이 한 명뿐이어도 한 번의 확정으로 진행한다.

**예외:** 주장 이탈은 중지 후 같은 팀의 대리인 지정 또는 진행 취소를 결정한다. 마지막 선택 취소는 공개 이력에 남기고, 이전 지명 정정은 그 이후 선택까지 영향 범위를 검토한다. 같은 역할 주장·스네이크 순서가 실력 균형을 보장하지 않는다.

**공유 연출:** 현재 팀 테두리와 중앙 차례 안내를 함께 강조한다. 지명 확정 시 이름 카드를 약 **700ms**에 해당 팀 역할 자리로 이동한다. 다음 후보 정보가 읽힐 수 있게 연속 효과를 짧게 유지한다. 지명 번호를 실력 순위처럼 표시하지 않는다.

## 7. 포인트 경매 — 동일 예산으로 8명 영입

**시작 조건:** 고정 역할과 같은 역할의 주장 2명, 각 팀 4자리, 예산·입찰 규칙을 준비 화면에서 확인했다. 주장 영입 비용은 0P로 동일하게 시작한다.

| 항목 | 기준안의 예시값·규칙 |
|---|---|
| 시작 예산 | 기본 각 팀 **1,000P**, 설정에서 변경; 이번 편성 전용이며 클랜코인·현금·계정 자산과 분리 |
| 최소 낙찰가 / 증분 | 기본 **10P / 10P**, 설정한 단위 이상으로 최고 유효 입찰 갱신 |
| 경매 순서 | 주장 제외 8명의 순서를 사전 추첨·저장·공개 |
| 최초 제한 시간 | 기본 한 사람당 **20초**, 설정에서 10~60초로 변경 |
| 막판 입찰 | 남은 5초 이내 유효 입찰이면 5초를 다시 확보하되 **설정 시간 + 30초**가 최종 마감; 중지 시간 제외 |
| 총 연장 한도 | 기본 20초 + 최대 30초(50초); 설정 시간에도 추가 연장은 최대 30초 |
| 입력 경로 | 사이트 직접 참여와 운영진 대리 입력을 구분하며 해당 경매의 입력 권한·전환 규칙은 후속 확정 |

1. 현재 후보의 이름·역할, 최고 유효 입찰, 양 팀 남은 예산·역할 자리를 공유 화면에 크게 표시한다.
2. 해당 경매의 입력 권한자가 팀·가격을 제출하면 서버가 권한·예산·역할·접수 시각을 검증한다. 주장 직접 입력과 운영진 대리 입력은 그 경매에 정한 입력 규칙을 따른다. 유효 입찰만 최고가를 갱신하고 마감 연장을 적용한다.
3. 마감 시 최고 유효 입찰 팀에 영입을 확정하고 비용을 한 번 차감한다. 다음 후보는 운영진의 진행으로 열어 설명·대화 시간을 확보한다.
4. 팀이 정원·역할을 채우면 관련 입찰이 불가능하다. 전체 8명 영입 완료 후 최종 팀을 공개한다.

**입찰 상한:** `남은 예산 − 최소 낙찰가 × (남은 자리 수 − 1)`. 남은 자리 수에는 지금 영입할 자리를 포함한다. 예를 들어 1,000P·4자리이면 상한은 970P다. 이 제한과 별개로 현재 후보의 역할 자리가 있어야 한다. 한 팀의 최고 입찰 예약액과 이미 차감한 금액을 중복 계산하지 않는다.

**동시 입력:** 서버에 접수된 순서대로 원자적으로 처리한다. 같은 금액이면 먼저 유효하게 접수된 요청만 인정하고 뒤 요청에는 현재 최고가를 알려 준다. 거절한 요청을 공유 화면에서 접수된 것처럼 띄우지 않는다. 음성·방송에서 들린 순서를 자동 판별하는 기능은 없으며 대리 입력 기준을 시작 전에 안내한다.

**무입찰:** 설정한 최소가(기본 10P)로 한 번 재상정한다. 다시 무입찰이면 역할·정원·최소 예산을 만족하는 팀 중 추첨으로 최소가에 배정한다. 가능 팀이 하나면 해당 팀에 배정한다. QA 앱에는 이 기본안을 적용했으며 다른 처리 방식은 후속 규칙 검토 대상이다. 누구도 영입할 수 없으면 정합성 오류로 중지한다. 유찰을 참가 탈락으로 처리하지 않는다.

**중지·정정:** 중지 중 새 입찰은 거절하며 재개 시 저장한 잔여 시간을 사용한다. 낙찰 취소 시 예산·자리·후보를 함께 복구하고 이후 영입에 미치는 영향을 검증한다. 운영진이 임의로 타이머만 늘리지 않으며 시간 규칙 변경은 중지·공개 안내 후 새 단계에 적용한다.

**공유 연출:** 유효 입찰 때 가격·해당 팀을 약 **150ms** 강조한다. 낙찰은 이름·팀·가격을 약 **1초** 보여 준 뒤 해당 역할 자리로 옮긴다. 무입찰에는 실패 효과음·불쾌한 낙인 문구를 쓰지 않는다. 최종 팀 화면에서 가격은 보조 정보이며 선수 이름보다 크게 표시하지 않는다.

## 8. 공유 화면의 시각·연출 규칙

- **16:9 공유 화면**, 1280×720·1920×1080에서 이름·현재 차례·가격·남은 시간을 읽을 수 있게 검증한다. 긴 이름은 최소 한 번 전체를 확인할 수 있게 하며 팀 표에서 필요한 이름을 말줄임만으로 구분하지 않는다.
- 기존 다크 화면과 팀별 파랑·빨강을 이어 쓰고 현재 차례는 중립색·골드 테두리로 강조한다. 팀명·역할 아이콘·텍스트를 함께 써서 색만으로 상태를 구분하지 않는다.
- 최종 결과는 양 팀을 함께 약 **1.5초**에 드러낸 뒤 고정한다. 한 팀만 오래 감추거나 승패를 암시하는 연출을 넣지 않는다.
- 연출 강도는 `간결 / 기본 / 방송용` 후보로 둔다. 간결은 약 **200ms**, 기본은 각 모드의 위 시간, 방송용은 이름·전환 강조를 키운다. **방송용 선택만으로 지명·입찰 제한 시간을 늘리지 않는다.**
- 기본 무음. 소리는 선택 기능으로 두고 볼륨·미리 듣기를 제공한다. 빠른 점멸·연속 화면 흔들림은 쓰지 않는다.
- 동작 줄이기 설정에서는 이동·확대 연출 대신 확정 결과를 표시한다. 별도의 건너뛰기·다시 보기 버튼은 제공하지 않는다.
- 공유 화면 타이머는 서버 마감 시각에 맞춘다. 디스코드·방송의 전달 지연은 있을 수 있으므로 주장 직접 입력 시 자신의 조작 화면을 마감 기준으로 삼는다. 공유 지연을 이유로 마감 후 입찰을 되살리지 않는다.
- 공개 연출은 저장한 결과의 표현이며 다시 뽑기가 아니다. 재접속·공유 화면 진입은 현재 단계에 합류하고 지난 입찰·지명을 대량 재연출하지 않는다.
- 정정은 변경된 사람·팀·가격과 `정정됨` 상태를 보여 준다. 개인 선호·민감한 사유는 공개 로그에 자동 노출하지 않는다.

### 공유 화면 배치 기준안

1280×720을 기준으로 한다. 대화 안의 축소 시연과 실제 방송 화면의 크기를 구분하며, 1920×1080에서는 같은 비율로 확장한다.

| 요소 | 기준안 |
|---|---|
| 화면 여백 / 열 간격 | 바깥 32px / 열 사이 24px |
| 팀 구성 배치 | 좌측 1팀 / 중앙 현재 대상 / 우측 2팀, 하단 남은 후보 |
| 팀 명단 | 슬롯 높이 최소 66px, 이름 20px 이상, 긴 이름은 두 줄 허용 |
| 현재 대상 / 가격·시간 | 이름 36px, 가격 40px, 시간 32px; 이름과 역할을 가장 먼저 읽게 배치 |
| 보조 정보 | 16px 이상; 압축된 방송에서도 읽히는지 실제 공유로 검증 |
| 차례 강조 | 팀 색은 유지하고 현재 팀에 골드 테두리 + `현재 지명` 문구 |
| 작은 조작 화면 | 팀 2열의 역할 위치는 유지하며 중앙 진행 정보를 위로 이동 |

### 대화 시연의 범위

**초기 연출 비교 시연:** 네 방식과 `간결 / 표준 / 방송` 속도를 비교하며 정해진 명단·결과를 재생한다. 기존 방식은 마지막 역할 입력, 선호 추첨은 10명 결과 공개, 주장 지명은 8번의 확정 장면, 경매는 마지막 5초부터 한 선수의 영입까지를 보여 준다.

시연의 재생·일시정지·마지막 장면 이동은 비교용 제어다. 실제 운영에서 `건너뛰기`가 미입력 지명·입찰을 대신 결정할 수 있다는 뜻이 아니다. 실제 화면에서는 저장된 확정 결과의 표현만 건너뛴다.

**세션 참여 시안(2026-09-16):** 세션 개설·고정 내전 날짜·라운드 기록을 바탕으로 운영진/클랜원/방송의 관점을 전환한다. `손들기 또는 선호 추첨 → 주장 지명 또는 경매`를 조합하고, 권한에 따른 직접 지명·입찰, 비출전자 베팅, 라운드 결과 기록·다음 라운드·세션 종료를 로컬 상태로 시연한다. 다음 라운드는 출전자·배치·주장을 유지하고 이전 베팅은 그 라운드의 개인 기록에 남긴다. 재편성은 지명 차례·경매 잔액 등을 새로 시작한다.

관점·시작 장면 선택과 `마감 시점 보기`는 시안 비교 도구로 제품 화면 밖에 둔다. 마감 시점 이동은 실제 운영진의 조기 마감 기능을 확정하는 것이 아니다. 클랜원 관점과 방송 관점은 동일한 시연 상태를 보되 개인 베팅 내역은 방송에 표시하지 않는다.

선호 추첨 결과·최초 지명 팀·경매 상정 순서·무입찰 배정은 고정된 예시다. 지명·입찰·베팅의 세부 조작은 검토안이며, 실제 다중 접속 동기화·서버 권한 검증·추첨 알고리즘·코인 정산·DB 저장·종료 후 세션 재개는 구현하지 않았다. 시안을 통과한 검증은 아래 실제 구현 수용 기준을 완료 처리하지 않는다.

**후속까지 포함한 수용 기준 — 전체 완료 체크가 아니다. 현재 실행 결과는 [Phase 2](../TODO_Phase2.md)에 기록한다.**

- [ ] 열린 세션에 클랜원이 사이트로 접근해 같은 상태를 실시간 확인하고 기능별 권한에 맞게 참여할 수 있다. 방송용 화면의 읽기 전용 설정을 클랜원 참여 화면에 일괄 적용하지 않는다.
- [ ] 라운드가 바뀌어도 세션의 내전 날짜를 유지하고, 이전 라운드 결과·베팅·편성 이력이 새 라운드와 섞이지 않는다.

- [ ] 재접속·늦은 공유 화면 진입이 저장한 결과를 바꾸거나 종료된 추첨을 다시 시작하지 않는다.

**확정·적용한 사항:** 역할을 먼저 정하고 팀원을 선발한다. 프로필 기본 선호와 본인의 라운드 선호, 운영진 규칙 설정, 같은 저장 결과 공개를 QA에 적용했다. 세션·라운드·내전 날짜·클랜원 사이트 참여는 D-SESSION-01을 따른다. **남은 결정:** 불가 역할, 지명 시간, 경매 예외 규칙의 확장, 대리 입력 전환과 세밀한 사후 정정을 구체화한다.

**후속 범위:** 다팀 대회·출전자 선발·대진표·외부 공개 링크·연속판 기회 보정. 클랜원의 사이트 참여는 기본 요구이며 주장 직접 입력 등 개별 조작의 세부 권한·흐름은 후속 구체화한다. 현재 기준안과 연출 예시가 이 기능들의 구현·출시를 뜻하지 않는다.
