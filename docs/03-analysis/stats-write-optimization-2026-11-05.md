# 문체 검사 복구와 통계·엠블럼 쓰기 최적화 — 2026-11-05

공유 QA 계정·클랜·내전 기록에는 쓰기·시드를 실행하지 않았다. 적용과 검사는 전용 로컬 DB `clansync-automated-tests`(55431)와 검사 사이트 3010에서만 수행했다. 운영·공유 QA 마이그레이션은 적용하지 않았다.

## 변경

- 시스템 문구 51개 표현(소스 22개 파일)을 기존 격식체 규약에 맞췄다. 사용자 작성 글·기존 저장 데이터·영어 번역은 변경하지 않았다. 관련 화면 검사의 예상 문구 3곳도 갱신했다.
- 기간별 중간 집계에서 큰 출전자 JSON을 제외하고 출전 계산에서만 읽도록 했다. 원본 투영, 중복 슬롯의 팀 판정, 기간 경계, 연승 계산, 클랜 단위 잠금은 그대로다.
- 요약은 삭제/삽입 대신 변경된 값만 갱신한다. 같은 결과의 물리 행 위치와 버전이 유지되는지 DB 검사로 확인한다.
- 엠블럼은 갱신된 전체 요약으로 새 수상 후보를 확인한 뒤 필요한 멤버만 과거 기록을 정렬한다. 후보가 없으면 과거 기록 집계를 생략한다. 요약이 없으면 전체 계산으로 복구하며, 이미 획득한 이력과 최초 달성일은 보존한다.
- 새 마이그레이션은 함수 본문만 교체한다. 데이터 백필·삭제·테이블·권한 변경이 없다.

새 DB 검사는 동일 요약의 불필요한 재저장 억제, 수상 이력 누락/전체 요약 누락 복구, 새 승리·연승 기준 도달, 최초 획득일을 확인한다. 기존 회귀는 권한 거부, 환불·정정·삭제·방 종류/날짜 변경·동시 저장을 함께 검증한다. `npm run test:stats-write:db`로 집중 재실행할 수 있고 기본 DB 검사에도 포함했다.

기록 추가 UI에서 저장 후 조회 단계가 한 번 실패했다. 화면은 “저장은 완료됐지만 기록 조회 권한이 변경됐습니다”라고 표시했다. DB 저장과 RPC 정합성 검사는 통과했고, 진단 로그를 추가한 동일 시나리오와 진단 코드를 제거한 최종 코드 모두 재실행에서 통과해 원인은 확정하지 못했다. 이 현상을 수정 완료했다고 주장하지 않는다. 실패 실행·화면·추적 파일은 해당 실행 폴더에 보존한다.

후속으로 소속 조회의 일시 502와 권한 오류 오인을 재현하고, 저장 완료 후 읽기만 복구하도록 수정했다. 이 문단의 당시 미확정 상태와 구분한 [후속 원인·검증](match-record-read-recovery-2026-11-05.md)을 참조한다.

위 로컬 실행 6회 모두 완료 후 임시 계정·클랜·경기 0건을 확인했다. 검사 잠금과 3010 검사 서버는 종료됐고 기존 QA 3011·현황 3040은 유지했다. 최근 결과와 DB 설정·데이터는 산출물 정리 대상에서 제외한다.

브라우저 전체 358개를 이번에 다시 실행한 것은 아니다. 이번 관련 시나리오와 이전 [전체 누적 결과](pending-regression-2026-11-05.md)를 구분한다. 제품 보류 중인 커뮤니티 6개도 그대로다.

변경 전 실행은 `2026-11-05T07-01-28-259Z-cfb3f5f4`, 변경 후는 `2026-11-05T08-26-43-606Z-6aad0522`다. [집계 원수치](stats-write-optimization-metrics-2026-11-05.json)를 보존한다. 상세 로그·DB 전후 스냅샷은 `.local-tests/runs/{실행 ID}/`에 있다.

엠블럼 함수의 누적 실행은 34,793ms/139회에서 201ms/135회로 줄었다. 함수 통계와 SQL 호출 통계의 스냅샷 집계 건수가 달라, 전체 비교는 호출 수가 같은 142회의 SQL 수치를 기준으로 한다. 통계 본체는 52,561ms/139회 → 53,410ms/135회로 빨라졌다고 볼 수 없다. 주요 시간 절감은 불필요한 엠블럼 재계산 생략에서, 임시 쓰기 절감은 엠블럼 생략과 기간별 중간 행 축소에서 나온다. 원본 경기와 출전자 저장은 필요하므로 WAL까지 크게 줄었다고 해석하지 않는다.

1만 경기·출전자 10만 행·멤버 10명, 생성 250경기 묶음과 삭제 100경기 묶음, 단일 worker·자동 재시도 0으로 비교한다. 원본 전체 조회 비교 옵션도 양쪽에 동일하게 켠다. 계측 구간은 검사 내부의 생성·조회·정정·삭제와 빌드를 포함하며 바깥의 스택 초기화·시드는 제외한다.

임시 쓰기량은 `pg_stat_database.temp_bytes`, WAL은 `pg_stat_wal.wal_bytes` 차이다. 중첩 SQL/함수 시간은 포함 관계이므로 합산하지 않는다. 로컬 단일 표본이며 운영 응답 시간 보장이나 온라인 QA Disk I/O 예산 회복을 뜻하지 않는다.

전체 기간의 정확한 연승·정정을 위해 통계의 전체 이력 계산은 남아 있다. 극단적으로 큰 클랜은 멤버별 증분 집계 등 추가 설계가 필요하다. 이번 변경은 재계산 자료 크기·중복 저장·불필요한 수상 이력 계산을 줄인다.
