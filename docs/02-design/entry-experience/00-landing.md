# 랜딩 재기획 초안

작성일: 2026-10-24 · 갱신: 2026-10-30 · 상태: **방향 선택 완료 / 문구·배치 검토 중 / 구현 전** · 경로: `/`

상위: [진입 변경 기획](../../01-plan/entry-experience-redesign.md) · [공통 기준](README.md)

2026-10-30 사용자가 선택한 방향을 반영한다. 기존 클랜 홈·프로필 중심 제안을 대체하며 랜딩의 구도·시각 방향은 이 문서가 우선한다. 다른 진입 화면은 이번 범위에서 제외한다.

## 1. 목적과 결정 상태

| 관점 | 기획 요약 |
| --- | --- |
| 문제 | 클랜장·운영진이 내전 참가자를 모으고 균형을 고려해 팀을 나누는 일이 번거롭다. |
| 해결 방향 | 모집·편성·조정의 실제 서비스 화면으로 운영 도구의 쓰임을 설명한다. |
| 방문 경험 | 소개 → 실제 편성 화면 → 운영 흐름 → 결과 기록 → 이용 안내 → 시작하기 |
| 전달 가치 | 내전 준비를 한곳에서 진행하고 경기 이후의 기록까지 이어간다. |

**사용자 선택:** 클랜 운영의 편리함, 클랜장·운영진 중심, 참가자 모집과 팀 편성 문제, 실제 편성 화면 중심, 밝고 차분한 운영 도구의 분위기.

**검토할 제안:** 아래의 정확한 문구·중앙 배치·섹션 구성·이미지 크롭·시각 수치. 실제 운영자가 현재 사용하는 도구는 아직 확인하지 않았으므로 특정 채팅·문서를 쓴다는 가정이나 절약 시간 수치를 홍보에 사용하지 않는다.

## 2. 첫 화면과 문구 초안

**제목**

> 참가자 모집부터 팀 편성까지,
> 내전 준비를 한곳에서.

**설명**

> 참가 현황을 확인하고, 팀을 편성하고, 필요한 조정을 이어가십시오.

주 행동은 `무료로 시작하기`, 보조 행동은 `편성 화면 살펴보기 ↓`다. 보조 행동은 대표 이미지의 `#formation-preview`로 이동하며 실제 기능 체험을 의미하지 않는다.

```text
[ClanSync]                                    [테마] [로그인] [시작하기]

                참가자 모집부터 팀 편성까지,
                    내전 준비를 한곳에서.
                  짧은 설명 · 무료로 시작하기
                    편성 화면 살펴보기 ↓

       [ 참가자 명단 · A팀/B팀 · 실제 서비스 화면 ]
                     내전 편성 · 예시 화면

[ 참가자를 모으고 ]        설명 + 실제 화면 일부
[ 팀을 나누고 조정하고 ]   설명 + 실제 화면 일부
[ 경기가 끝나면 기록으로 ] 설명 + 실제 화면 일부
[ 지원 게임 · 무료 이용 범위 · 제공 상태 ]
[ 다음 내전을 준비하십시오.                무료로 시작하기 ]
[ 하단 정보 ]
```

큰 화면은 중앙 제목 아래 넓은 편성 화면을 배치한다. 1280×720에서 제목·버튼과 대표 화면의 시작 부분을 함께 볼 수 있도록 하며 화면 전체를 한 뷰포트에 억지로 축소하지 않는다. 모바일도 소개 → 버튼 → 화면 순서이며 390×844에서 버튼이 큰 이미지보다 먼저 보이게 한다.

헤더의 시작 버튼은 본문 버튼이 보이지 않는 스크롤 위치에서도 진입을 제공한다. 각 설명 구간에 가입 버튼을 반복하지 않고 마지막에 한 번 더 제공한다. 소개 위·옆에 부가 카드나 기능 목록을 두지 않는다.

## 3. 섹션별 내용

| 순서 | 제목 초안 | 설명 초안 | 장면 |
| --- | --- | --- | --- |
| 1 | 참가자를 모으고 | 내전 참여 현황을 한곳에서 확인하십시오. | 실제 참가자 목록 |
| 2 | 팀을 나누고 조정하고 | 팀을 편성하고 필요한 조정을 이어가십시오. | 실제 두 팀과 운영진의 조정 화면 |
| 3 | 경기가 끝나면 기록으로 | 경기 결과를 남기고 멤버별 기록을 확인하십시오. | 결과·통계의 대표 부분 |
| 4 | 이용 안내 | 지원 게임과 무료 이용 범위를 확인하십시오. | 간결한 정보 행 |
| 5 | 다음 내전을 준비하십시오. | 긴 설명 없이 시작 행동 제공 | 무료로 시작하기 |

모집·편성·조정은 하나의 운영 흐름으로 읽히게 한다. 완벽한 밸런스나 원클릭 완료를 약속하지 않는다. 역할·편성 방식의 세부 명칭은 실제 촬영 화면과 함께 검토한다.

PC는 이미지와 짧은 설명을 짝지은 좌우 교대 구도를 제안한다. 모바일은 설명 다음 이미지다. 일정은 준비 맥락에서 보조로 설명한다. 스크림·대진표·꾸미기·프로필은 독립 섹션에서 제외한다.

## 4. 시각 방향과 대안

선택한 방향은 **밝고 차분한 운영 도구**다. 흰색 또는 아주 옅은 중성 배경, 짙은 본문, 기존 브랜드 계열의 강조색 하나를 사용한다. 색상값은 기존 토큰과 함께 시안에서 검토한다.

- 큰 제목과 넉넉한 여백으로 위계를 만든다. 대표 화면에는 얇은 테두리와 약한 그림자만 제안한다.
- 섹션 전체를 각각 카드로 감싸지 않는다. 글로우·대형 그라데이션·입체 장식·게임 캐릭터 배경은 제외한다.
- 기본 표현은 라이트다. 기존 테마 선택은 유지하고 방문자의 테마를 강제로 바꾸지 않는다. 다크에서도 같은 위계와 대비를 제공한다.
- 본문 폭 1200~1280px, 모바일 좌우 16~20px, 제목 PC 48~64px·모바일 30~36px를 시안 검토의 출발점으로 삼는다.

| 대안 | 장점 | 판단 |
| --- | --- | --- |
| 실제 편성 화면 중심 | 도구와 사용 장면을 직접 이해할 수 있음 | 사용자 선택 |
| 단순화한 흐름 그래픽 | 작은 화면에서 흐름을 쉽게 읽을 수 있음 | 대표 표현에서 제외. 필요 시 보조로 재검토 |
| 기존 화면의 간격·카드만 정리 | 변경 범위가 작음 | 처음부터 재기획한다는 요청에 따라 제외 |

## 5. 이미지 제작 기준

- 실제 QA 화면에서 참가자 명단과 편성된 두 팀이 동시에 보이는 단계를 선정한다. 공개용 별도 예시 데이터와 촬영본은 준비 전이다.
- 사용자 테스트 명단을 수정하거나 시드를 재실행하지 않는다. 공개용 예시는 별도 임시 데이터로 준비하며 QA 계정명·실제 개인 정보를 홍보 자산에 포함하지 않는다.
- 이름·역할·팀 배치가 읽히도록 편성 영역을 중심으로 크롭한다. 새로 그린 그림을 실제 제품 화면처럼 제시하지 않는다.
- 모바일은 전용 크롭을 검토한다. 명단과 두 팀을 함께 읽기 어렵다면 두 팀을 대표 이미지로 두고 참가자 목록은 다음 설명 구간에서 보여준다.
- `내전 편성 · 예시 화면` 캡션과 대체 텍스트를 제공한다. 필요한 설명은 이미지 밖에도 쓴다.
- 자동 슬라이드·자동재생·실제 앱 임베드는 사용하지 않는다. 테마별 촬영본이 없으면 고정 프레임 속 예시로 표현하며 색을 강제로 반전하지 않는다.

## 6. 이용 안내와 이동

지원 게임은 이름·실제 제공 상태를 간단히 표시한다. QA 활성 상태만으로 운영 제공 상태를 단정하지 않는다. `회원가입은 무료입니다.`를 제안하며 무료 기능 범위는 실제 Free/Premium 정책을 확인한 뒤 작성한다. Premium은 필요하면 `Premium 구독 결제는 준비 중입니다.` 한 줄로 표시하고 큰 가격표·구매 버튼은 제외한다. 이용자 수·후기·효과 수치를 만들어 넣지 않는다.

| 상태 | 시작 행동과 목적지 |
| --- | --- |
| 비로그인 | 무료로 시작하기 → `/sign-up`, 로그인 → `/sign-in` |
| 로그인한 `/` 직진입 | 기존 `/games` 자동 이동 유지 |
| 로그인한 `/?from=logo` | 가입 버튼 대신 게임 선택으로 → `/games`. 기존 계정 메뉴 유지 |
| 세션 확인 실패 | 개인 정보를 추측하지 않고 시작하기 → `/games`의 인증 가드에서 재확인 |

로고 재방문·기존 인증 규칙은 유지한다. 정책 링크는 실제 존재하는 경로만 제공한다. 게스트를 보호된 편성 화면으로 바로 보내지 않는다.

## 7. 범위·실패 상태·완료 기준

이번 작업은 기획이다. 앱 코드·DB·가입 흐름·편성 알고리즘·운영 배포는 변경하지 않는다. 신규 데이터 집계 서비스도 추가하지 않는다.

| 진입·상태 | 처리 계획 |
| --- | --- |
| 대표 이미지 지연·실패 | 비율·캡션 공간 유지. 프레임 안에 `화면 예시를 불러오지 못했습니다.` 표시 |
| 지원 상태 조회 실패 | 영역 안에 `지원 정보를 불러오지 못했습니다.`와 재시도 제공. 실패를 미지원으로 표시하지 않음 |
| 화면 보기 앵커 | 대표 화면으로 이동. 키보드 초점·모션 감소 설정 처리 |
| 시작 버튼 | 로그인 상태에 맞는 실제 경로로 이동. 모의 가입 완료·체험 상태를 만들지 않음 |

구현 후 확인할 기준:

1. 첫 화면에서 대상·핵심 가치·시작 행동을 이해할 수 있는지 사용자 검토를 받는다.
2. 320/390/768/1024/1280px에서 제목·버튼·대표 화면이 겹치거나 가로로 넘치지 않는다.
3. 비로그인·로그인 직접 진입·로고 재방문의 목적지가 위 표와 일치한다.
4. 키보드·테마·모션 감소·이미지 실패·지원 상태 실패에서도 읽기 순서와 영역 크기를 유지한다.
5. 예시 화면과 설명이 현재 기능·실제 이용 범위와 일치한다.

현재 [랜딩 코드](../../../src/app/page.tsx)와 [진입 가드](../../../src/proxy.ts)는 변경 전이다. 문서 정합성과 로컬 링크만 확인하며 시안·촬영·앱 구현·브라우저 검증 완료를 뜻하지 않는다.
