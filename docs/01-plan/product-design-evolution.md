# 기획·디자인 고도화 논의

작성·갱신: 2026-09-16

## 이 문서의 역할

2026-09-15 기획·디자인 리뷰에서 나온 제안을 구체화하는 작업 문서다. 사용자는 2026-09-16 문서화 요청에서 당분간 이 내용을 이어서 논의하는 방식을 선택했다.

- **확정된 작업 방향:** 제안을 문서화하고, 주제별로 사용자 흐름·화면·정책을 구체화한다.
- **제안의 상태:** 아래 7개 주제는 초기 제안이다. 개별 정책 변경·화면안·개발 우선순위가 승인된 것은 아니다.
- **관찰 기준:** 2026-09-15 운영 대시보드·밸런스 화면, 정적 목업, 해당 상세 기획. 사용자 인터뷰나 사용성 실험 결과는 아니며, 기대 효과는 검증할 가설이다.
- **문서 관계:** 결정 상태·확정 내용은 [decisions.md](./decisions.md)의 `D-UX-01~07`로 추적한다. 이 문서는 문제·대안·질문을 구체화한다. 현재 구현 상태는 [Phase 2 현황](../TODO_Phase2.md)을 참조한다.
- 새 결정이 확정되기 전까지 기존 정책이 유효하다. 확정할 때 해당 기존 결정과 PRD·페이지·슬라이스·권한/플랜 표를 함께 갱신한다. 구현·검증 완료는 별도로 기록한다.

## 중심 가설과 유지할 장점

**“클랜원들이 모여 내전 한 번을 준비하고, 함께 플레이하고, 기록을 남긴다”는 경험을 연결하면 운영 부담과 구성원의 참여 부담을 줄일 수 있다.**

목업의 어두운 색감, 클랜 정체성을 드러내는 배너, 블루·레드 팀의 명확한 구분은 유지할 가치가 있다. 고도화에서는 역할과 상황에 따라 다음 행동이 눈에 들어오도록 정보 순서를 다듬는다.

첫 대상으로는 기존에 내전을 운영하는 클랜과 운영진을 제안한다. 신규 클랜 탐색·공개 커뮤니티까지 동시에 우선할지는 아직 결정하지 않았다.

## D-UX-01. 내전 전체 흐름

**현재 관찰**

내전 일정은 등록할 수 있지만 참석 응답(RSVP)은 스크림에만 허용한다. 내전 모집과 당일 팀 편성을 연결하는 흐름이 부족하다. 이는 현재 [이벤트 명세](./pages/11-Clan-Events.md)의 정책이며, 단순한 구현 누락으로 취급하지 않는다.

**개선 제안**

`일정 등록 → 참가 신청·희망 역할 → 당일 체크인 → 팀 편성 → 경기 → 다음 판 → 오늘의 기록`

일정 상세에서 참가 인원과 부족한 역할을 확인하고, 실제 출전자를 편성 화면으로 연결한다. 중간 합류·퇴장·대기자 교대를 고려한다.

예시 문구와 숫자는 화면 논의용이다.

> 오늘 21:00 정기 내전 · 참가 확정 8/10명 · 지원 역할 1명 부족
>
> 구성원: **참가하기** / 운영진: **팀 편성 준비**

**구체화할 질문**

- 일정 없이 즉석에서 여는 내전도 지원할까? 지원한다면 어떤 단계를 생략할까?
- 참가 신청·참가 확정·체크인·실제 출전을 어떻게 구분할까? 누가 각 상태를 바꿀까?
- 희망 역할은 하나만 받을까, 우선순위가 있는 복수 선택으로 받을까?
- 인원 미달·초과, 불참·취소, 중간 합류·퇴장을 어떻게 처리할까?
- 다음 판에는 로스터·역할·밴 옵션 중 무엇을 유지하고, 대기자는 어떤 순서로 교대할까?
- 편성 담당자가 중도 이탈하거나 운영진이 동시에 조작하면 진행 권한을 어떻게 넘길까?

**관련 기준:** `D-EVENTS-01`, `D-PERM-01` / [이벤트](./pages/11-Clan-Events.md), [밸런스메이커](./pages/09-BalanceMaker.md), [S04](./slices/slice-04-balance-maker.md), [S06](./slices/slice-06-events-manage-store.md).

## D-UX-02. 역할별 홈과 첫 사용

**현재 관찰**

홈은 공지·규칙·일정·배지·MVP 중심이다. 실제 기록이 없는 클랜에서는 큰 빈 카드가 반복되고, 내전 100회·500회·1주년처럼 먼 목표가 먼저 보인다. 현재 빈 상태 안내는 구현되어 있으나, 첫 행동을 단계적으로 이끌어 주는 경험이 약하다.

**개선 제안**

| 상황 | 상단에 우선 표시할 내용 |
|------|--------------------------|
| 새 클랜 운영진 | 멤버 초대 → 첫 일정 → 첫 경기 기록 |
| 내전 준비 중인 운영진 | 참가 인원·부족한 역할·팀 편성·필요한 운영 업무 |
| 일반 구성원 | 다음 일정·참가 응답·배정된 팀 |
| 경기 진행 중 | 현재 경기와 바로 돌아가기 |
| 경기 종료 후 | 오늘의 결과·다음 일정 |

활동이 쌓이면 시작 안내를 평소 홈으로 전환한다. 초대 링크에서는 허용된 클랜 소개와 초대 목적을 보여 주고, 인증 후 원래 목적지로 이어지는 경험을 검토한다.

**구체화할 질문**

- 홈이 역할과 상황에 따라 바뀌어도 고정해야 할 정보는 무엇일까?
- 첫 사용 안내의 완료 기준과 다시 보는 방법은 무엇일까?
- 진행 중 경기와 곧 시작할 일정이 겹치면 무엇을 먼저 보여 줄까?
- 미가입자에게 공개 가능한 초대 정보와 가입·인증이 필요한 행동은 어디까지일까?

**관련 기준:** `D-AUTH-01`, `D-SHELL-01`, `D-PERM-01` / [클랜 홈](./pages/07-MainClan.md), [클랜 가입](./pages/06-ClanAuth.md), [S02](./slices/slice-02-game-clan-onboarding.md), [S03](./slices/slice-03-main-clan-shell.md).

## D-UX-03. 납득할 수 있는 팀 편성

**현재 관찰**

기획은 M/A 점수와 점수 차이·승률 예측을 판단 보조로 사용한다. 자동 편성·자동 점수 산정·승률 예측은 현재 미구현 범위다. ‘맵 밴’은 실제 규칙상 득표를 가중치로 최종 맵을 추첨하므로 이름과 행동의 의미가 다르다.

**개선 제안**

- 점수 차이와 함께 희망 역할, 같은 팀의 반복, 대기자 교대를 편성 조건 후보로 검토한다.
- 추천 근거와 조건 충족 여부를 짧게 설명한다. 예: ‘희망 역할 9/10명 반영 · 대기자 2명 교대’.
- 한 명을 교체했을 때 달라지는 조건을 확인하고 운영진이 조정할 수 있도록 한다.
- 점수·승률을 제공할 때 표본 수와 불확실성을 표현한다. 기록이 부족한 상태를 별도로 설계한다.
- ‘맵 밴’을 ‘맵 투표’로, M/A를 ‘운영진 점수/자동 점수’처럼 이해하기 쉬운 표현으로 설명하는 안을 검토한다.

**구체화할 질문**

- 반드시 지킬 조건과 가능한 한 맞출 조건은 무엇일까? 서로 충돌하면 무엇이 우선일까?
- 친구와 같은 팀, 반복 팀 방지, 역할 선호 중 어떤 요구까지 초기 범위에 포함할까?
- 근거·표본·수동 보정 이유를 본인·구성원·운영진에게 각각 얼마나 보여 줄까?
- 신규 참가자에게 점수가 없으면 어떻게 편성할까? 승률을 표시할 충분한 근거는 무엇일까?
- 운영진 수정과 이의 제기, 최종 편성 책임을 어떻게 다룰까?

**관련 기준:** `D-PERM-01`, `D-PRIV-01` / [밸런스메이커](./pages/09-BalanceMaker.md), [S04](./slices/slice-04-balance-maker.md). 설명 가능한 편성이 정확한 승률 예측을 보장한다는 뜻은 아니다.

## D-UX-04. 시각적 우선순위

**현재 관찰과 제안**

데스크톱 대시보드와 밸런스 화면을 직접 확인한 인상이다. 접근성 적합 여부를 전수 측정한 결과는 아니다.

| 관찰 | 개선 제안 |
|------|-----------|
| 배너 면적에 비해 행동 버튼이 작다 | 배너 높이를 조절하고 오늘 일정·현재 경기와 연결 |
| 카드의 배경·크기·강조 수준이 비슷하다 | 현재 할 일, 일반 정보, 과거 기록의 시각적 강도 구분 |
| 세션을 열기 전에도 빈 슬롯이 크게 보인다 | 시작 전에는 경기 준비와 참가자 확보를 우선 표시 |
| 목업의 플레이어 선택 영역이 화면 아래로 밀린다 | 편성 중 참가자 목록과 팀 보드를 함께 볼 수 있게 배치 |
| 메뉴는 접힌 아이콘 중심이고 점수에는 약어를 쓴다 | 메뉴 고정 펼치기와 의미가 드러나는 라벨 검토 |

**구체화할 질문**

- 각 화면에서 가장 먼저 보여야 할 정보와 가장 중요한 행동은 무엇일까?
- 항상 필요한 편성 도구와 접어 둘 고급 설정을 어떻게 구분할까?
- 노트북 화면에서 스크롤 없이 함께 보여야 하는 영역은 어디까지일까?
- 글자 크기·텍스트 대비·키보드 초점·터치 영역을 어떤 기준으로 검증할까?

**관련 기준:** `D-SHELL-01` / [클랜 홈](./pages/07-MainClan.md), [밸런스메이커](./pages/09-BalanceMaker.md), [목업 기준](../02-design/mockup-spec.md), [목업](../../mockup/pages/main-clan.html).

핵심 조작과 고급 설정을 구분하는 참고 원칙: [NN/g — Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/). 구체적인 배치는 실제 작업 흐름으로 검증한다.

## D-UX-05. 모바일 참가 경험

**검증할 사용 가정**

운영진은 PC로 편성하고 구성원은 휴대전화로 참가와 배정 결과를 확인할 수 있다. 실제 기기 사용 분포는 아직 조사하지 않았다.

**개선 제안**

- 참가·취소, 준비 완료, 내 팀·역할·맵 확인, 투표를 우선한다.
- 내 상태와 현재 필요한 행동을 화면 아래에 고정하는 구성을 검토한다.
- 운영 도구는 필요할 때 펼치되, 모바일 운영진의 사용 범위도 별도로 정한다.

**구체화할 질문**

- 모바일에서 팀 편성·교체·결과 입력까지 모두 지원할까?
- 참여자·대기자·관전자마다 기본 화면과 버튼이 어떻게 달라질까?
- 게임 중 재접속, 다른 탭 전환, 투표 마감, 연결 끊김 뒤 복귀를 어떻게 안내할까?
- 고정 버튼이 본문·키보드·초점을 가리지 않도록 어떻게 검증할까?

**관련 기준:** `D-SHELL-01`, `D-PERM-01` / [클랜 홈](./pages/07-MainClan.md), [밸런스메이커](./pages/09-BalanceMaker.md), [이벤트](./pages/11-Clan-Events.md).

## D-UX-06. 함께한 기록과 공개 태그

**현재 관찰**

홈과 기획의 성취 표현은 승률·MVP·예측·코인 비중이 크다. 밸런스 기획에는 연패·슬럼프·노쇼 자동 태그가 있고, 경기 종료 결과는 일회성 팝업을 기본으로 한다. 태그는 기획된 항목이며 전체 자동 산정이 구현되었다는 의미는 아니다. 기존 경기 기록 열람과 별개로 ‘오늘 함께한 경험’을 돌아보는 흐름을 검토한다.

**개선 제안**

- 오늘 함께한 사람과 경기, 이번 달 참여한 날, 첫 내전, 클랜 공동 목표 등 참여 자체를 기념한다.
- 종료 팝업 이후에도 다시 볼 수 있는 오늘의 내전 요약과 다음 일정 연결을 검토한다.
- 공유 가능한 요약을 검토하되, 공개 범위는 별도로 정한다.
- 연패·슬럼프·노쇼를 공개 태그로 붙이는 방식은 재검토한다. 운영에 필요한 출석 정보와 공개적으로 축하할 성취를 구분한다.

공개 평가가 참여를 부담스럽게 만들 수 있다는 우려는 검증할 가설이다. 태그 제거·공개 범위 축소를 이미 결정한 것은 아니다.

**구체화할 질문**

- 일반 구성원이 다시 보고 싶은 기록은 무엇이며, 첫 성취는 무엇으로 정의할까?
- ‘오늘’의 집계 경계는 언제일까? 자정을 넘긴 내전을 어떻게 묶을까?
- 요약을 본인·클랜·외부에 각각 어디까지 공개할까? 공유는 누가 실행할까?
- 태그 유지·삭제·비공개 전환 중 어떤 방향이 적절하며, 기존 기록은 어떻게 처리할까?
- 기록 정정 시 요약·배지·통계에 어떻게 반영할까?

**관련 기준:** `D-ECON-03`, `D-ECON-04`, `D-PROFILE-04`, `D-STATS-02`, `D-PRIV-01` / [밸런스메이커](./pages/09-BalanceMaker.md), [통계](./pages/10-Clan-Stats.md), [프로필](./pages/14-Profile-Customization.md), [S05](./slices/slice-05-clan-stats.md), [S08](./slices/slice-08-player-profile-decorations.md).

## D-UX-07. 첫 방문 메시지와 Premium

**현재 관찰**

랜딩의 메시지는 ‘Archive Your History, Stay in Sync / 추억을 기록하고 클랜을 체계적으로 관리하세요.’다. PRD는 자동 편성·OCR·대진표·Discord 연동 등을 Premium으로 분류한다. 유료 결제와 여러 자동화 기능은 아직 별도 구현 범위다.

**개선 제안**

- 메시지 후보: **‘오늘 내전, 사람 모으기부터 팀 편성·기록까지.’**
- 실제 제공하는 기능으로 짧은 체험 흐름을 보여 주어 가입 전에 용도를 이해하게 한다. 위 메시지는 내전 참가 흐름이 구체화된 뒤 제공 범위와 맞춘다.
- Premium은 자동 편성·반복 운영·운영 자동화처럼 절약하는 시간으로 설명하고, 클랜 단위 혜택을 명확히 한다.
- 기본 참가 연결과 일정 전달을 무료로 어디까지 제공할지 재검토한다.

**구체화할 질문**

- 첫 방문에서 설득할 대상은 운영진일까, 일반 구성원일까?
- 구현된 기능만으로 보여 줄 수 있는 대표 체험은 무엇일까?
- 무료로 첫 내전을 끝내는 데 필요한 범위는 어디까지일까?
- 어떤 자동화에 지불 의사가 있으며, 이를 어떻게 확인할까?
- 무료/유료 경계를 바꿀 경우 기존 클랜의 사용 경험은 어떻게 전환할까?

**관련 기준:** `D-LANDING-01`, `D-EVENTS-03`, `D-NOTIF-02`, `D-STORE-02` / [PRD](./PRD.md), [랜딩](./pages/01-Landing-Page.md), [권한·플랜](./gating-matrix.md). 가격·알림 정책 변경은 아직 결정하지 않았다.

## 검증 방향과 범위

먼저 소규모 클랜의 운영진·구성원과 실제 내전 준비 과정을 확인한다. 인터뷰·시연에서는 도움 없이 참가하고 팀 편성을 끝낼 수 있는지, 어떤 단계에서 별도 메신저나 수작업이 필요한지 관찰한다.

| 지표 후보 | 알고 싶은 것 | 측정 전 정할 기준 |
|-----------|---------------|-------------------|
| 첫 내전 완료 클랜 비율 | 새 클랜이 핵심 경험까지 도달하는가 | 대상 클랜·관찰 기간·완료 정의 |
| 다음 주 재사용 클랜 비율 | 한 번 사용한 뒤 다시 내전을 여는가 | 첫 완료 클랜 집단·다음 주의 기간 |
| 팀 편성 소요 시간 | 운영진의 준비 부담이 줄었는가 | 시작/종료 시점·인원 대기 시간 분리 |
| 참가 응답률 | 구성원이 참가 의사를 쉽게 남기는가 | 응답 대상·마감·취소/미응답 구분 |

측정 수단·목표 수치·자동 수집 여부는 미정이다. 실제 조사 결과가 나오면 기대 효과와 분리해 해당 주제에 반영한다.

게임·언어 확장, 꾸미기 상품 대량 추가, 순위·배지 증가, 복잡한 대회 형식은 초기 논의 순서에서 뒤에 두는 안을 제안한다. 스크림 승패 통계·클랜 간 대회·개인 이미지 업로드는 현재 범위 밖이며, 이 문서로 추가하지 않는다.

## 이어서 구체화하는 방법

1. 한 번에 위 코드 하나 또는 밀접한 두 개를 선택한다.
2. 해당 절에 사용자 상황, 후보안과 장단점, 정상/예외 흐름, 남은 질문을 추가한다. 새 요약 문서를 매번 만들지 않는다.
3. 결정된 내용은 `decisions.md`에 일자·근거·영향받는 기존 정책을 기록한다. 일부만 정해졌으면 남은 범위는 `OPEN`으로 둔다. 채택하지 않은 안도 이유를 짧게 남긴다.
4. 확정 범위의 페이지·슬라이스·PRD 등을 갱신하고, 화면안·구현·검증의 다음 작업을 구분한다. 결정되었다는 이유만으로 구현 완료로 표시하지 않는다.
