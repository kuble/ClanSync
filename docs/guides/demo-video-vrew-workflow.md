# 실제 웹사이트 시연 영상 제작 — Vrew 문장 단위 내레이션

2026-10-01 · ClanSync 제작 경험을 바탕으로 정리한 재사용 가이드.

실제 서비스를 조작하는 화면에 설명을 붙이는 영상에 적용한다. 서비스 소개와 전체 화면 안내는 짧게 하고, 핵심 기능은 사용 목적·조작·결과가 이어지도록 설명한다. **완결된 발화 하나를 한 번에 음성으로 생성하고, 실제 음성 길이에 맞춰 해당 기능 화면을 유지하는 것**이 핵심이다.

이 문서 한 파일을 다른 프로젝트에 복사해서 사용할 수 있다. 아래 시간·문장 수·파일명은 예시이며 프로젝트에 맞게 정한다.

## 1. 가장 먼저 정할 것

| 항목 | 정할 내용 |
|---|---|
| 시청자 | 처음 보는 사용자, 기존 사용자, 운영자 등 |
| 영상 목적 | 서비스 소개, 주요 기능 시연, 특정 작업 안내 등 |
| 핵심 흐름 | 사용자가 시작해서 결과를 확인하기까지의 순서 |
| 설명 비중 | 전체 화면은 짧게, 핵심 작업과 결과는 자세하게 |
| 음성 | Vrew에서 사용할 사용자 목소리 또는 선택한 목소리 |
| 촬영 환경 | QA·데모 계정, 보여줄 예시 데이터, 화면 크기 |
| 목표 분량 | 대략적인 범위. 음성을 만든 뒤 실제 길이로 조정 |

실제 구현된 기능과 화면을 확인한다. 설정 화면만 보여주는 기능, 실제로 실행하는 기능, 앞으로 구현할 기능을 구분해서 대본에 반영한다. 시연용 데이터로 입력한 결과를 실제 서비스 이용 결과처럼 설명하지 않는다.

## 2. 대본의 기본 구성

| 순서 | 설명할 내용 | 작성 요령 |
|---|---|---|
| 소개 | 서비스 이름, 대상 사용자, 해결하려는 문제 | 2~3문장으로 서비스의 용도를 먼저 이해시킨다. |
| 전체 화면 | 대시보드·홈에서 확인할 수 있는 정보 | 항목을 짧게 소개한다. 화면의 숫자와 문구를 모두 읽지 않는다. |
| 핵심 작업 | 준비 → 설정 → 실행 → 결과 저장 | 사용자가 실제로 따라가는 순서로 보여준다. |
| 기록·분석 | 저장한 결과를 찾고 비교하는 기능 | 어떤 질문에 답할 수 있는지 설명한다. |
| 마무리 | 앞에서 보여준 기능의 연결 | 서비스가 돕는 일을 짧게 정리한다. |

서비스에 없는 단계는 생략한다. 대시보드가 없는 서비스는 첫 화면을 짧게 소개하고 핵심 작업으로 넘어간다.

각 기능은 **목적 → 화면에서 하는 일 → 확인할 수 있는 결과**로 쓴다. 모든 장면에 세 문장을 강제로 넣을 필요는 없다.

예시:

> 필요한 과거 기록을 찾을 때는 날짜와 참가자로 검색할 수 있습니다.
> 날짜를 선택하면 그날의 결과와 참여 명단이 표시됩니다.
> 참가자 조건을 추가하면 원하는 사람의 기록만 빠르게 살펴볼 수 있습니다.

‘다음은’, ‘확인할 수 있습니다’를 매 장면에 반복하기보다 기능의 목적과 결과를 구체적으로 쓴다. 화면에 없는 동작을 설명하거나, 기록을 미래 성적의 보장처럼 표현하지 않는다.

## 3. 음성 생성 단위와 자막 표시 단위

**음성 생성용 TXT의 한 줄과 SRT의 한 구간은 완결된 발화 하나로 맞춘다.** 보통 한 문장이며, 짧은 인사처럼 자연스럽게 이어지는 두 문장을 한 발화로 묶어도 된다.

- 쉼표, 글자 수, 화면에서 보이는 줄 길이 때문에 발화를 나누지 않는다.
- 음성 생성용 SRT 구간 안에는 강제 줄바꿈을 넣지 않는다. Vrew로 가져온 뒤에도 문장 중간이 별도 음성 클립으로 나뉘지 않았는지 확인한다.
- 서비스명·약어는 음성용 원고에서 읽기 쉬운 표기를 사용한다. 예: `ClanSync` → `클랜싱크`, `MVP` → `엠브이피`.
- 장면 제목, 시간, ‘2초 쉼’ 같은 편집 지시는 음성용 TXT와 자막 본문에서 제외한다. 장면표에 따로 적는다.
- 화면에 표시할 자막의 줄바꿈·크기는 음성을 만든 다음 조정한다. 짧은 표시용 자막마다 음성을 새로 생성하지 않는다.

예를 들어 다음 문장은 끝까지 한 번에 생성한다.

> 클랜싱크는 게임 내 클랜 시스템이 없는 경쟁형 멀티플레이 게임을 위한 클랜 기록 도구이자 웹 커뮤니티입니다.

이 문장을 ‘클랜싱크는 / 게임 내 클랜 시스템이 없는 / 경쟁형 멀티플레이 게임을 위한 / …’처럼 나누어 각각 생성하면 중간마다 문장이 끝나는 듯한 억양이나 쉼이 생길 수 있다.

이미 잘게 나누어 생성했다면 완결된 문장 전체를 다시 음성으로 생성한다. 자막 텍스트를 합치는 것만으로 기존 음성에 담긴 쉼과 억양이 자연스럽게 바뀐다고 가정하지 않는다.

### 음성 생성용 SRT 예시

아래 시간은 형식 설명용이다. 실제 작업에서는 생성한 음성 길이로 정한다.

```srt
1
00:00:00,600 --> 00:00:04,000
서비스의 주요 기능을 살펴보겠습니다.

2
00:00:04,600 --> 00:00:12,000
대시보드에서는 진행 중인 작업과 최근 활동을 한눈에 확인할 수 있습니다.
```

## 4. 촬영과 시간 배분

### 촬영

1. 장면마다 설명할 기능과 보여줄 조작을 정한다.
2. QA·데모 환경에서 읽기와 쓰기 시연을 준비한다. 기존 사용자의 테스트 데이터를 초기화하지 않는다.
3. 필요한 조작만 촬영하고, 설정 창·완성된 결과·그래프가 충분히 보이는 지점을 남긴다.
4. 장면 ID와 원본 구간을 기록한다. 수정이 생겨도 필요한 장면만 다시 편집할 수 있게 한다.
5. 편집용 원본에는 음성과 하단 자막을 미리 굽지 않는다. 상단 장면 제목을 넣었다면 최종 산출물 설명에 명시한다.

촬영 전에 대본을 확정하면 화면을 유지할 지점을 잡기 쉽다. 이미 촬영한 영상도 같은 장면표를 작성한 뒤 필요한 위치에 정지 시간을 넣어 사용할 수 있다.

### 음성이 준비된 경우

장면 길이는 **조작을 보여주는 데 필요한 시간**과 **해당 장면의 전체 발화·쉼에 필요한 시간**을 모두 확보하도록 정한다. 클릭과 설명이 동시에 진행되는 시간은 중복해서 더하지 않는다.

먼저 긴 문장 하나를 선택한 목소리로 생성해 발음과 호흡을 확인한다. 이후 나머지 발화를 생성하고, 실제 길이를 장면표에 기록한다. 음성 속도를 억지로 높이기보다 화면 유지 시간이나 대본 분량을 조정한다.

### 음성이 아직 없는 경우

예상 시간으로 초안을 만들 수 있다. ClanSync에서는 한글 약 5음절/초, 발화 사이 0.6초, 장면 시작 0.6초, 장면 끝 약 2초를 초안 기준으로 사용했다. **이 수치는 목소리마다 달라지는 추정치이며 공통 규격이 아니다.**

실제 음성을 만든 뒤 문장 길이와 여백을 다시 맞춘다. 자동으로 예측한 SRT 시간을 음성과 맞춘 최종 자막으로 표시하지 않는다.

### 설명이 영상보다 길 때

- 클릭·드래그·추첨 과정은 이해하기 쉬운 속도로 재생한다.
- 설명하는 설정 창이 열린 상태, 팀 구성이 확정된 상태, 그래프가 완성된 상태처럼 **내용과 맞는 화면**을 유지한다.
- 설정 창을 닫은 뒤의 배경, 로딩 화면, 이전 기능 화면을 장면의 마지막 프레임이라는 이유로 길게 유지하지 않는다.
- 한 장면에서 여러 기능을 설명하면 기능별로 유지 지점을 나눈다.
- 정지 화면이 지나치게 길어지면 중복 설명을 줄이거나 해당 기능을 추가 촬영한다.

예: 13초짜리 화면에 28초의 설명이 필요하다면 해당 화면에 약 15초의 유지 시간을 추가한다. 이 경우에도 설명이 가리키는 화면이 실제로 보이는 지점에 시간을 넣는다.

Vrew의 ‘정지 워드’는 직전 워드의 마지막 화면을 유지한다. 공식 안내의 경로는 **삽입 → 빈 클립 → 정지 워드**이며, 추가한 정지 워드에서 유지 시간을 조절한다. 메뉴 위치는 사용하는 버전에서 확인한다. [Vrew 정지 워드 안내](https://www.vrew.imweb.me/faq/?bmode=view&idx=168991738)

## 5. Vrew에서 작업하는 순서

1. 현재 프로젝트를 저장하고, 수정 전 영상과 원고를 보관한다.
2. 완결된 발화 단위의 TXT를 음성 생성 작업에 입력한다. 이미 준비한 SRT를 사용하는 경우에는 자막 전체를 담을 길이의 영상을 먼저 불러온 뒤 SRT를 가져온다. 실제 음성이 없을 때의 SRT 시간은 예상치이며 4단계에서 확정한다. 긴 문장이 중간에서 다시 나뉘지 않았는지 확인한다.
3. 선택한 목소리로 도입부 한 문장을 생성해 호흡을 확인한 뒤 나머지를 생성한다. 사용자 목소리를 만드는 기능은 [Vrew 내 목소리 안내](https://vrew.ai/ko/feature/ai-voice/)를 참고한다.
4. 같은 Vrew 프로젝트에서 실제 음성 길이에 맞춰 장면의 화면 유지 시간과 SRT 시간을 조정한다. 화면을 외부 도구로 편집한다면 생성한 음성도 별도 파일로 보관한다.
5. 외부에서 편집한 영상을 새 프로젝트에서 조합한다면 **자막 전체를 담을 길이의 영상을 먼저 불러오고, 그 영상 시간표에 맞춘 SRT를 불러온다.** 앞에서 생성한 음성도 함께 가져와 해당 장면에 맞춘다. 같은 프로젝트에서 편집을 마쳤다면 이 단계는 생략한다.
6. 음성의 흐름을 확인한 뒤 화면 자막의 표시 길이·줄바꿈·서식을 다듬는다.
7. 처음부터 끝까지 재생해 화면·음성·자막이 같은 기능을 설명하는지 확인하고 내보낸다.

Vrew에서 바로 편집하는 경우와 외부에서 화면 시간을 먼저 조정하는 경우 모두 원칙은 같다. 확정된 음성 길이에 맞춰 영상과 자막 시간을 함께 맞춘다. SRT 구간 수가 그대로 음성 클립 수가 된다고 가정하지 말고 가져온 결과를 확인한다.

## 6. 자주 생기는 문제

| 현상 | 확인할 점 | 처리 |
|---|---|---|
| 한 문장이 여러 조각처럼 들림 | 음성 생성용 자막이 쉼표·글자 수·줄바꿈으로 나뉘었는가 | 완결된 발화로 합친 뒤 문장 전체를 다시 생성한다. |
| ‘프로젝트 시간이 자막 파일보다 짧다’는 안내 | 마지막 자막 종료 시각이 영상 길이를 넘는가 | 영상 시간을 맞춘 뒤 원래 SRT를 다시 불러온다. 이미 잘린 뒷부분은 다시 가져와야 한다. |
| 문장은 이어지지만 설명과 화면이 다름 | 설명하는 기능 창이 이미 닫혔는가 | 그 기능이 보이는 지점에 유지 시간을 넣는다. |
| 자막은 맞는데 실제 목소리가 넘침 | 예상 낭독 시간만으로 편집했는가 | 실제 음성 길이로 장면과 자막 종료 시간을 조정한다. |
| 영상이 지나치게 느리게 느껴짐 | 모든 조작을 일괄 감속했는가 | 조작 속도를 복원하고 설명에 필요한 화면만 유지한다. |
| 한 문장의 자막이 화면에 너무 길게 보임 | 표시 길이와 음성 생성 단위를 함께 줄이려 하는가 | 생성된 음성의 연속성을 유지하면서 자막 표시만 조정한다. |

## 7. 다른 프로젝트에 복사할 장면표

프로젝트명, 시청자, 목표 분량, 사용할 목소리를 먼저 적는다. 아래 양식을 장면 수만큼 복사한다. 실제 음성 생성 전에는 길이를 ‘예상’으로 표시한다.

```text
장면 ID / 제목:
이 기능을 보여주는 목적:
실제 조작 또는 설정 화면 소개:
원본 파일 / 시작·종료 시각:

완결된 발화 1:
완결된 발화 2:
완결된 발화 3: (필요할 때만)

예상 발화 길이:
실제 생성된 음성 길이:
보여줄 조작과 설명 순서:
화면을 유지할 지점 / 그때 보여야 할 내용:
읽은 뒤 화면을 살펴볼 여유:
최종 장면 시작·종료 시각:
해당 자막 구간 번호:
```

## 8. 전달할 파일과 완료 확인

| 파일 | 용도 |
|---|---|
| `서비스명-원본-무음.mp4` | 다시 편집할 수 있는 원본 화면 |
| `서비스명-대본맞춤-무음.mp4` | 발화와 화면 확인 시간을 반영한 편집본 |
| `서비스명-음성대본.txt` | 한 줄에 완결된 발화 하나. 제목과 편집 지시 제외 |
| `서비스명-문장단위.srt` | 음성 생성에 사용할 완결 발화 단위 자막 |
| `서비스명-장면표.md` | 화면·발화·시간·유지 지점의 대응 관계 |
| `서비스명-표시용.srt` | 필요할 때만 생성. 짧게 나눈 화면 표시용이며 음성 재생성에 사용하지 않음 |
| `서비스명-최종.mp4` | 음성·자막을 확인한 공유용 영상 |

전달 전 확인:

- 모든 음성 생성 구간이 완결된 발화이고, 같은 문장 중간에 별도 생성 경계가 없는가?
- 프로젝트·영상 길이가 마지막 자막과 마지막 음성의 끝까지 포함하는가?
- 장면 순서와 자막 순서가 일치하고, 자막 시간의 역전·겹침이 없는가?
- 설정 창·결과·그래프를 설명할 때 그 화면이 실제로 보이는가?
- 첫 문장, 긴 문장, 기능 전환, 마지막 인사를 직접 듣고 확인했는가?
- 이름·역할·숫자·권한 등 서비스별 설명이 실제 구현과 맞는가?
- 최종 파일이 끝까지 재생되고, 요청한 음성·자막 포함 여부가 맞는가?

자동 합성을 사용한다면 영상 전체 디코딩, 실제 재생 길이, 음성 트랙 유무, 장면 경계와 SRT 종료 시간을 확인한다. 일정한 프레임 속도로 출력할 때는 인코더의 출력 프레임 속도까지 명시하고, 장면을 이어 붙인 최종 파일의 실제 길이를 검사한다. ClanSync의 FFmpeg 작업에서는 30fps 출력에 `-r 30 -fps_mode cfr`를 명시해 장면별 길이를 맞췄다.

파일명으로 원본·예상 시간표·최종 파일을 구분한다. 다른 프로젝트로 옮길 때는 문서뿐 아니라 필요한 원본과 확정 대본도 함께 복사한다. 임시 출력 폴더가 버전 관리에서 제외되어 있다면 문서에 파일명을 적는 것만으로 영상이 보존되지는 않는다.

## 9. 다른 프로젝트에서 바로 사용할 요청문

아래 내용을 복사하고 대괄호 부분을 채운다.

```text
[서비스명]의 실제 웹사이트 시연 영상을 제작해 주세요.

대상 시청자는 [시청자], 목적은 [목적], 목표 분량은 [대략적인 길이]입니다.
Vrew에서 [사용할 목소리]로 내레이션을 만들 예정입니다.
촬영할 주소·환경은 [QA 또는 데모 환경]이고 주요 기능은 [기능 목록]입니다.

서비스 소개로 시작하고 대시보드 또는 첫 화면은 보여주는 정보만 짧게 설명해 주세요.
핵심 기능은 실제 사용 순서대로 목적, 조작, 결과가 이어지게 자세히 설명해 주세요.
실제로 실행하는 기능과 설정 화면만 보여주는 기능을 구분해 주세요.

음성 생성용 TXT 한 줄과 SRT 한 구간에는 완결된 발화 하나를 넣어 주세요.
쉼표, 글자 수, 자막 표시 길이 때문에 한 문장을 여러 음성 구간으로 나누지 마세요.
음성용 SRT 구간 안에도 강제 줄바꿈이나 편집 지시를 넣지 마세요.
서비스명과 약어는 자연스럽게 읽을 수 있도록 발음 표기를 확인해 주세요.

실제 음성이 있으면 그 길이를 기준으로 편집하고, 없으면 시간을 추정치로 표시해 주세요.
설명이 길어질 때는 해당 설정 창이나 결과 화면이 보이는 지점에 유지 시간을 넣어 주세요.
클릭·추첨 등 조작 속도와 읽은 뒤 화면을 살펴볼 여유도 고려해 주세요.

원본과 대본에 맞춘 무음 영상, 음성용 TXT, 문장 단위 SRT, 장면별 시간표를 준비해 주세요.
상단 제목이나 하단 자막을 영상에 미리 넣는지는 [원하는 방식]을 따라 주세요.
영상 길이가 마지막 자막과 음성까지 포함하는지, 화면과 설명이 맞는지 확인해 주세요.
기존 작업과 데이터를 보존하고 [시연용 데이터 사용 조건]을 따라 주세요.
```

## 10. ClanSync 적용 사례

원본은 31장면, 약 7분 48초였다. 새 대본에 맞춰 화면을 유지하는 위치를 골라 11분 40초 영상으로 편집했고, 마지막 자막은 11분 37.2초에 끝나도록 맞췄다.

처음에는 화면 표시 길이에 맞춰 자막을 137개로 나눴다. 사용자가 그 구간으로 음성을 생성하면서 한 문장 중간의 흐름이 끊기는 문제를 경험했다. 완결된 발화 89개로 다시 합치고 구간 안의 강제 줄바꿈을 제거한 방식에 대해 사용자가 결과가 좋다고 확인했다.

재사용할 것은 **완결된 발화로 음성을 생성하고 실제 길이에 맞춰 화면을 유지하는 절차**다. 89개 구간, 11분 40초, 0.6초 쉼은 이 영상에 적용한 값이다.
