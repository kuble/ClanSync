# 클랜 통계 조회 모델

2026-10-10. QA 적용, 운영 DB·배포 미적용.

## 조회 비용을 경기 수에서 분리

기존 첫 화면은 `matches`, 완료 라운드, 내전 세션을 500개씩 모두 읽은 뒤 서버 JavaScript에서 전체·연도·월별 통계를 계산했다. 상세 UI를 늦게 열어도 서버는 전체 원본을 읽었다. 경기 수 N, 경기당 출전자 P에 따라 전송량과 집계 비용이 O(N×P) 이상 증가했다.

변경 후 결과를 저장·정정·삭제하는 트랜잭션에서 집계를 저장한다. 첫 화면은 전체·현재 연도·현재 월 요약과 기간별 건수만 읽는다. 기간 선택은 해당 요약, 경기 기록은 선택한 날짜, 개인 기록은 선택한 멤버만 읽는다. 닉네임과 권한은 매 요청 현재 값으로 결합한다.

- `private.clan_stats_records`: 원본과 같은 중복 제거 규칙을 적용한 경기 투영. `(clan_id, day, occurred_at, id)` B-tree와 `user_ids` GIN으로 날짜·멤버 조회 범위를 제한한다.
- `private.clan_stats_periods`: `(clan_id, period)` 기본 키. `all`, `YYYY`, `YYYY-MM`, `YYYY-MM-DD`별 승패·출석·연승·예측·맵·밴·투표 집계. 날짜는 한국 시간 기준이며 라운드는 부모 내전 시작일에 속한다.
- `private.clan_stats_refresh_queue`: 같은 트랜잭션의 여러 정산 변경을 클랜별로 합친다. 지연 제약 트리거가 커밋 직전에 한 번 반영하고 큐를 지운다. 경기와 통계가 함께 커밋·롤백된다.
- `read_clan_stats_summary`, `read_clan_stats_records`: 서비스 전용 조회 RPC. 클라이언트에서 직접 호출할 수 없다.

첫 화면 작업량은 경기 원본 수 대신 멤버 수·기간 수에 비례한다. 순위 정렬은 멤버 수 M에 대해 O(M log M), 날짜 선택 조회는 인덱스 탐색과 선택 날짜의 K건에 비례한다. 모든 요청이 O(1)이라고 주장하지 않는다.

## 정합성

경기·출전자·결과, 라운드·세션·방 종류, 맵 투표·승부예측 변경을 문장 단위 트리거로 감지한다. 이전 날짜와 새 날짜의 요약을 모두 갱신한다. 동일 ID의 명시적 경기(초안 포함)는 같은 클랜의 라운드를 가리고, 삭제하면 라운드가 다시 나타난다. 예측은 명시적 경기 날짜가 바뀌어도 원래 내전 날짜를 유지한다.

클랜별 advisory transaction lock을 투영 전에 잡아 동시 수정으로 갱신을 잃지 않도록 한다. 결과 확정 시 라운드와 예측이 함께 변경되어도 요약은 커밋당 한 번 계산한다. 집계되지 않는 미완료 경기 변경은 기록 목록만 갱신한다. 클랜 크기와 일괄 작업 크기에 맞는 쿼리 계획을 쓰도록 집계 함수에 `force_custom_plan`을 설정했다.

현재 최장 연승의 정확한 정정·삭제를 위해 쓰기 시 전체 기간 요약을 다시 계산한다. 따라서 쓰기 비용은 아직 경기 수에 비례하며, 수십만 경기 단계에서는 멤버별 증분 집계·연승 구간 병합 등의 후속 검토가 필요하다. 개인 상세도 선택 멤버의 전체 이력을 읽으므로 극단적으로 많은 개인 기록에는 별도 페이지네이션이 필요하다. 관리 화면의 전체 분석 경로는 이번 변경 범위에 포함하지 않는다.

## 공개 범위

조회 모델에는 닉네임·공개 설정을 저장하지 않는다. 앱은 매 요청 활성 멤버 여부·역할·공개 설정을 확인한 뒤 서비스 RPC를 호출한다. 경기 기록 권한, 점수 공개, 멤버 본인 기록 설정, 월·연 순위 공개 시점을 응답에 반영한다. 응답은 `private, no-store`이고 화면 내부 캐시는 해당 페이지 모델이 바뀌면 폐기한다.

세 테이블은 비공개 `private` 스키마에 있고 RLS를 활성화하며 일반 사용자 권한·정책이 없다. 요약·투영의 서비스 SELECT와 고정 search_path의 트리거 실행만 허용한다. Advisor의 `rls_enabled_no_policy` INFO는 이 의도적인 일반 사용자 차단에 해당한다. 작은 QA 표본에서 사용되지 않는 GIN 인덱스는 큰 클랜의 멤버 조건 조회용으로 유지한다.

## 경기 기록 추가·정정·제거

경기 기록 탭은 달력으로 날짜를 선택하며 기간·연도·월 필터를 중복 표시하지 않는다. `view_match_records`와 `correct_match_records`를 모두 가진 활성 멤버에게 추가·수정·제거를 제공한다. 기본 정정 권한은 리더이며 클랜 권한 설정을 따른다. 날짜·한국 시간·맵·결과·출전자·역할을 기록하고 양 팀에 한 명 이상, 팀당 최대 다섯 명을 요구한다. 중복 출전자는 거부하며 기존 기록의 탈퇴자는 보존할 수 있다.

- `private.clan_match_record_corrections`: 원본 ID별 정정 투영 또는 삭제 표식. RLS로 일반 사용자 접근을 차단한다. 실제 라운드·승부예측 원장·정산 결과를 수정하지 않는다.
- `edit_clan_match_record`: 서버 액션이 로그인 사용자와 현재 권한을 확인한 뒤 서비스 RPC를 호출한다. DB에서도 소속·설정·대상 클랜·출전자·입력을 재검증한다. 같은 트랜잭션에서 이전/새 날짜와 전체 기간 요약을 갱신한다.
- 읽은 기록의 내용 해시를 수정 버전으로 전달하여 덮어쓰기 충돌을 `PT409`로 반환한다. 생성 ID는 편집 창에서 한 번 만들고 재시도에도 유지하여 응답 유실 후 중복 저장을 막는다. 충돌 시 최신 기록을 다시 확인한다.
- 원본 변경 트리거가 다시 실행되어도 정정·삭제 표식이 우선한다. 서비스 전용 `read_clan_match_record_corrections`를 전체 분석·관리 조회에도 적용하여 날짜별 빠른 조회와 같은 결과를 유지한다.

저장 후 새 날짜 목록과 선택 날짜의 경기만 다시 읽어 왼쪽 기록과 오른쪽 당일 전적을 함께 갱신한다. 페이지 모델도 새로 읽어 다른 통계의 캐시를 폐기한다. 당일 표의 승/무/패는 `1/2/3` 한 열로 표시하며 승 수 기준 정렬을 제공한다.

## 데이터 변경 시 화면 유지

기간·날짜·필터 변경과 기록 저장 시 카드·제목·선택기·그래프 영역을 유지하고 숫자·그래프·목록만 갱신한다. 기간을 React key로 사용하거나 화면 전체를 로딩 카드로 교체하지 않는다. 로딩 상태는 기존 영역 안에 표시하며 이전 기간의 수치를 새 기간 값으로 표시하지 않는다. 권한·페이지 모델이 바뀌면 캐시와 지연 응답을 폐기한다. 이 원칙은 [프로젝트 작업 지침](../../AGENTS.md)에 추가했다.

맵별 경기·영웅 밴·선호 맵은 같은 높이의 그래프와 224px 목록 공간을 유지한다. 목록은 스크롤바를 숨겨 스크롤하며 빈 데이터에서도 영역을 유지한다. 경기 상세와 당일 표는 각각 560px로 고정하고 내부를 스크롤한다. 당일 표는 앱의 배경·보조 글자 색을 스크롤바에 사용한다.

## 검증 진입점

QA 서울 DB·로컬 Node에서 임시 명시적 경기 10,000건, 출전자 100,000행, 멤버 10명으로 측정했다. 날짜는 2024-01-01부터 시간당 한 경기로 분산했다.

| 측정 | 결과 |
|---|---|
| 기존 전체 원본 조회 | 94,138ms 후 PostgreSQL `57014` statement timeout |
| 첫 화면 서버 통계 모델 조회 3회 | 725 / 257 / 209ms |
| 첫 화면 모델 JSON | 38,285 bytes (약 37.4KiB) |
| 선택 날짜 24경기 | 235ms, 32,456 bytes |
| 결과 1건 정정과 요약 커밋 | 3,334ms |

네트워크·DB 부하를 포함한 소규모 표본이며 SLA가 아니다. 브라우저 전체 로딩 시간이나 운영 환경 측정으로 해석하지 않는다. 전송 모델에는 경기 원본이 없고 선택 날짜의 데이터만 상세 응답에 포함된다.

- `e2e/clan-stats-read-model.spec.ts`: 기존 계산과 요약 비교, 정정·삭제·날짜 이동·라운드 가림·환불·방 종류 변경·직접 RPC 차단·탈퇴·공개 시점.
- `e2e/clan-stats-periods.spec.ts`: 기간별 기존 수치 비교, 기간·날짜 변경 중 카드/SVG 유지, 빈 데이터 높이·목록 스크롤·승/무/패 표시·개인 엠블럼.
- `e2e/clan-match-record-editing.spec.ts`: 추가·수정·제거 UI, 당일 전적 자동 갱신, 정정/삭제/날짜 이동의 요약·전체 조회 일치, 권한·충돌·출전자 검증·원본 라운드 보존.
- `e2e/security-fix-boundaries.spec.ts`: 멤버·운영진 공개 범위와 정산·점수 경로.
- `e2e/clan-stats-scale.spec.ts`: 임시 클랜의 1만 경기·출전자 10만 행 비교. 실행과 정리는 [E2E 안내](../../e2e/README.md)를 따른다.
- `scripts/prediction-pool-db.test.mjs`, `scripts/session-round-db.test.mjs`: 집계 트리거를 포함한 정산·반환·동시 요청·세션 수명 검증.

QA 마이그레이션은 `db:test:push` → `db:test:types`로 적용한다. 기존 데이터를 투영·집계하는 백필만 수행하며 사용자 QA 명단을 다시 시드하지 않는다. 운영 반영 전에는 별도 승인과 전체 회귀가 필요하다.
