# 편성 방식과 공유 화면 — 기준안 v0.1

작성: 2026-09-16 · 관련 논의: [D-UX-03](../01-plan/product-design-evolution.md#ux-03)

**상태: 역할 선고정과 세션·라운드·사이트 참여 정의는 사용자 확정이다. 아래 실제 적용 범위는 QA 구현 기준이며, 지명 시간 제한·정정 등 후속 제안의 구현 완료를 뜻하지 않는다.** 확정한 수동 명단 입력 UI를 유지하면서 라운드의 편성 시작·진행·결과 공개를 구체화한다.

## 실제 페이지 적용 범위 (2026-09-16)

- **맵 투표 자동 확정·화면 배치 (2026-10-09):** 운영진 화면에서 서버 마감 시각이 지나면 맵 확정을 자동 요청하며, 같은 투표의 중복 요청은 처음 저장된 맵을 유지한다. 득표 비율 추첨 후 다른 후보를 제거하고 확정 맵을 가로 전체로 650ms 확대한다. 결과를 1.2초 보여준 뒤 영웅 밴 또는 경기 현황으로 진행한다. 동작 줄이기에서는 확장 없이 바로 결과를 표시한다. 운영진이 접속하지 않았다면 다음 접속에서 마감된 투표를 처리한다. 투표 인원·수동 확정 행은 제거하고 예측 승률은 세션 종료 바로 위에 둔다. 실패 시에만 재시도 버튼을 표시한다. 맵·영웅 투표 시간은 증감 버튼 없이 직접 입력하고 팀 점수 합계 제목은 양 팀 수치와 같은 행 중앙에 배치한다.

- **화면 표시·밴픽 미리보기 (2026-10-09):** 화면 표시 설정은 `닉네임 카드`와 `팀 비교`로 나눈다. 카드 점수·닉네임 아래 전적/연속 기록·호버 상세를 한 그룹에 두고 보조 정보가 켜졌을 때만 내용 선택을 표시한다. 예시 카드는 실제 카드·상세 팝업·팀 그래프 구성요소를 사용하며 초안 변경을 즉시 반영한다. 밴픽은 맵 투표·영웅 밴별로 묶고 켠 기능의 시간·개수만 표시한다. 미리보기 진행 순서도 켠 단계만 포함하고 시간·팀별 밴 개수를 반영한다. 예시 맵 투표·영웅 선택은 실제 투표나 경기 맵을 변경하지 않는다. 데스크톱은 왼쪽 보드, 작은 화면은 옵션 위에 배치하며 저장은 기존 `설정 적용`으로 수행한다.

- **수치 편집 위치 강조 (2026-10-09):** 팀 크레딧·최소/증액 단위·입찰 시간·입찰 연장 시간·낙찰 후 준비 시간·전략 준비 시간 입력에 포커스하거나 값을 변경하면 해당 미리보기 장면으로 이동해 멈춘다. 실제 크레딧 행·입찰 버튼·타이머·준비 안내만 테두리와 배경으로 강조하며 요소 크기와 미리보기 높이를 유지한다. 팀 크레딧은 A팀 카드의 `팀 크레딧 · 값 cr` 행을 강조한다. 초기 값 → 편집 값과 단위는 화면 낭독기에 제공하고 연장 0초는 `연장 끔`으로 읽는다. 재생·다시 보기·구간 이동·방식 변경 시 강조를 해제하며 동작 줄이기에서도 수치 편집 위치를 정적으로 확인한다. 저장은 기존 `설정 적용`으로 수행한다.

- **설정 미리보기 (2026-10-09):** 데스크톱(폭 1100px 이상)은 설정창 왼쪽의 블러 배경 위에 큰 예시 보드를 표시하고, 작은 화면은 팀원 선발 선택 아래에 배치한다. 편성 탭에서 재생 버튼을 조작한다. 화면 표시·밴픽 탭은 별도의 미리보기를 제공한다. 역할 배정 명칭은 `수동 배정 / 자동 배정`으로 표시한다. 자동 배정은 선호·추첨 순서·역할 자리 배정을, 팀 추첨은 역할별 자리 이동을 나눠 보여준다. 지명은 선픽 추첨과 A → B → B → A 순서의 8회 선택을 보여준다. 경매는 A팀 주장 시점에서 내 팀·상대 팀, 양 팀 잔액, 설정한 제한 시간의 카운트다운, 내 입찰·상대 입찰 알림·재입찰·막판 시간 연장·마감·낙찰 이동·크레딧 차감을 보여준다. 조작 표시는 자동 시연이며 실제 입찰 버튼이 아니다. 경매 화면은 선수 공개 전후에도 같은 높이를 유지하며 전략 아이템을 켜면 준비·구매 단계를 포함한다. 모든 컷을 4초로 재생하며 설정한 입찰·연장·준비 카운트다운과 연속 추첨을 같은 비율로 압축해 보여준다. 반복 재생·일시정지·다시 보기를 지원한다. 단계별 타임라인(클릭·드래그·방향키)과 화면별 구간 버튼으로 이동하면 선택한 장면에서 멈추며 재생 버튼으로 이어 간다. 동작 줄이기에서도 수동 구간 이동은 가능하다. 동작 줄이기에서는 완성된 팀을 정적으로 표시한다. 실제 라운드·명단·설정 저장에는 영향을 주지 않는다.

`codex/live-session-formation`의 QA 앱에 실제 저장·권한·실시간 연동을 적용했다. 운영 반영은 보류한다. 전체 검증 결과와 DB 적용 상태는 [Phase 2](../TODO_Phase2.md)를 따른다.

- **자동 배정 + 역할별 추첨 미리보기 (2026-10-09):** 본인 선호 선택 → 지원 1순위 변경 → 10명 편성 대기 → 공유 추첨 발표 → 완성 라인업의 별도 화면으로 전환한다. 발표 화면은 실제 보드와 같은 공격·공격·돌격·지원·지원 행으로 양 팀을 표시한다. 추첨 발표는 타임라인의 한 단계로 묶어 4초 안에 이름 섞기·공통 순서에 따른 10명 공개·결과 대기를 보여준다. 발표 중 단계 번호·제목은 유지한다. 동작 줄이기에서 발표 구간을 선택하면 10명의 결과를 즉시 표시한다. 본인 결과와 확정된 자리를 강조하며 일시정지 시 이름 회전도 멈춘다. 수동 배정도 역할 배치 → 현재 팀 유지/역할별 추첨/주장 선정으로 전환하고, 자동 배정+지명/경매는 역할 발표 후 주장 선정으로 이어진다. 지명은 차례·후보 선택 화면, 경매는 주장 입찰 → 낙찰 화면, 전략 아이템은 준비 → 선택 화면으로 전환하며 마지막에는 실제 보드의 행 순서로 결과를 보여준다. 선호 선택·추첨 시작·선수 지명·입찰 표시는 자동 시연이며 실제 저장·편성에는 영향을 주지 않는다.

- **명단:** 선택·우클릭·드래그·되돌리기를 자동 저장한다. 편성·설정 적용 전 미완료 저장을 기다리며 동시 편집은 로컬 변경 보관과 명시적 충돌 해결로 처리한다.
- **클랜원 목록 배치·참여자 추가 (2026-10-09):** 기본은 참여자 목록 왼쪽이며 제목 왼쪽의 손잡이를 위·왼쪽·오른쪽·아래 부착 영역으로 끌어 이동한다. 손잡이 클릭으로 부착 영역을 열거나 방향키로도 옮긴다. 넓은 화면의 좌우 배치는 두 목록을 나란히 보여주고, 추가할 클랜원이 없어도 패널 높이를 참여자 목록에 맞춘다. 좁은 화면에서는 세로로 쌓는다. 배치 조작은 화면 상태만 바꾼다. 클랜원을 원하는 참여자 자리로 끌어 추가하고, 채워진 자리에 놓으면 기존 참여자를 클랜원 목록으로 돌려보낸다. 10명이 찬 명단도 교체할 수 있으며 클릭/터치로는 클랜원과 교체할 자리를 차례로 선택한다. 참여자끼리의 자리 교환·우클릭/Delete 제거·되돌리기·자동 저장은 유지한다.
- **선호:** 프로필의 게임별 선호를 기본으로 쓰고 본인이 이번 라운드만 변경할 수 있다. 역할명 목록 대신 역할 아이콘 3개와 순위 숫자를 표시하고 드래그·두 아이콘 클릭·좌우 방향키로 교환한다. 이름은 툴팁과 접근성 이름으로 제공한다. 프로필 복귀와 명시적 `선호 없음`을 구별하며 화면을 보기만 해서는 순위를 저장하지 않는다. 미설정/선호 없음은 자기 차례에 남은 역할 자리에서 추첨하며 운영진에게 순위표를 공개하지 않는다. 체크인·선호 제출 완료 대기는 없다.
- **라운드 선호 표시:** 평소에는 `내 선호` 메뉴와 세 역할 아이콘만 표시한다. `프로필 기본값`·`선호 없음`·`프로필에서 기본값 설정`은 메뉴 안에 모으고 선택 즉시 닫는다. 설명은 접근성 안내에 두며 저장 중에는 스피너, 실패 시에는 오류를 표시한다. 빈 순위와 프로필 상속은 메뉴의 선택 상태로 구분한다.
- **규칙:** 직접 역할 배정/공통 추첨순서와 현재 팀 유지/역할별 팀 추첨/주장 지명/경매를 조합한다. 설정 패널에서 같은 역할 주장, 경매 예산·최소/증액 단위·제한 시간, 맵/영웅 밴을 저장한다. 역할 추첨을 쓰면 추첨으로 탱커가 된 두 명이 주장이 된다. 다음 라운드에는 규칙·밴픽을 이어 쓰고 개별 주장 지정·라운드 선호는 초기화한다.
- **저장·동기화:** 설정 적용은 부모 화면이 저장 이후 버전을 받으면 완료하며 적용 중에는 패널을 닫지 않는다. 편성 시작은 클릭 당시 명단·규칙·밴픽·추첨 이력 길이를 대조한 뒤 최신 비공개 선호를 해석하고 revision CAS로 저장한다. 선호만 갱신된 버전은 허용하되 초기화 전의 오래된 시작은 거부한다. 실시간 구독 준비 시 누락을 재조회하고 활성 라운드는 2초마다 작은 revision 상태를 비교한다. 개별 투표·예측 등의 복구는 30초 전체 갱신을 사용한다.
- **공개 화면:** 역할 추첨은 별도 팝업이나 화면 전환 없이 현재 편성판에서 운영진·클랜원에게 함께 공개한다. 저장된 순서대로 역할과 자리를 약 9초간 보여 주며, 역할 직접 배정 뒤 팀만 추첨하면 기존 4초 보드를 사용한다. 직접 배정+현재 팀 유지에는 추첨 연출을 넣지 않는다. 결과 다시 보기·상시 안내 패널은 두지 않는다.
- **안내·기록:** 안내 아이콘으로 단계별 강조 설명을 연다. 클랜장·운영진은 최근 30세션의 기록을 조회하고, 일반 멤버는 기록 아이콘을 숨긴다. 예외로 깜짝 개설자는 열린 자기 세션 기록만 조회하며 서버도 같은 범위를 검사한다. 깜짝 내전 종료 시 임시 기록은 삭제한다. 편성 이력에는 추첨 순서·시각·운영 규칙·초기화가 남고 개인 선호·베팅은 제외된다.

역할 손들기 채팅 수집·불가 역할·실력 자동 균형·지명 시간 제한·클랜별 세션 간 편성 설정 보존은 후속이다. 경매 자동 마감과 클랜 전략 아이템은 아래 2026-09-18 규칙을 적용한다. 기존 승부예측은 기존 자격/5분/5코인 보상 정책을 유지한다.

### 주장 조작·자동 경매·전략 아이템 (2026-09-18)

- 지명 후보와 현재 경매 선수·가격·시간은 참가자 표 위의 주요 영역에 표시한다. 경매 가격은 왼쪽 `-100`, `-10`, 오른쪽 `+100`, `+10` 버튼 또는 숫자 입력으로 조절하며 저장 시 설정한 증액 단위와 남은 선수 최소 비용을 검증한다.
- 주장을 겸하는 세션 관리자는 자기 팀의 지명·입찰·아이템 선택만 가능하다. 상대 팀 조작은 UI와 서버 양쪽에서 거부한다. 어느 팀의 주장도 아닌 관리자는 기존 대리 입력을 사용할 수 있다. 일시정지·재개·초기화는 관리 권한을 유지한다.
- 첫 선수 공개, 마감·재경매, 낙찰 후 다음 선수 공개는 별도 버튼 없이 진행한다. 연결 중인 클랜원이 서버 시각 확인을 요청하며 서버가 기한·역할·예산·저장 버전을 확인한다. 같은 기한의 중복 요청은 한 번만 반영하고, 변화 없는 요청은 활동 시각과 버전을 갱신하지 않는다. 재접속하면 저장된 상태와 마감 시각부터 이어간다.
- 낙찰은 팀 색상·이름·가격을 최소 2.5초 표시하고 낙찰 후 준비 시간이 끝난 뒤 다음 선수로 이동한다. 마지막 선수도 같은 연출을 거친 후 아이템 선택 또는 편성을 완료한다. 타이머는 기본 20초, 설정에서 10~60초이며, 입찰 연장은 기본 5초이며 0~30초로 설정한다(0은 연장 없음). 추가 30초 상한은 유지한다. 낙찰 후 준비는 기본 5초, 0~60초로 설정하며 낙찰 시점부터 측정한다. 다음 선수가 없으면 준비 대기 없이 2.5초 낙찰 연출만 유지한다. 일시정지는 준비·경매·낙찰 연출의 남은 시간을 보존한다.
- 라운드 설정의 `전략 아이템 사용`은 기본 꺼짐이다. 켜면 `아이템 3개 무작위 공개 → 전략 준비 → 팀원 경매 → 아이템 구매/구매 안 함 → 편성 완료`로 진행한다. 전략 준비는 기본 30초, 10~120초로 설정한다. 활성 아이템이 3개 미만이면 시작을 거부한다.
- `클랜 관리 > 내전 관리 설정`에서 활동 중인 클랜장·운영진이 아이템 이름·설명·가격·사용 여부를 추가·변경·삭제한다. 예시 3개는 명시적 추가 버튼으로만 등록한다. 경매 시작 시 무작위 3개의 이름·효과·가격을 복사하므로 도중의 목록 수정은 현재 경매에 영향을 주지 않는다.
- 초기 구매 규칙은 팀당 최대 1개, 양 팀 동일 아이템 구매 가능, 선수 영입 후 남은 포인트 사용이다. 구매하지 않기도 명시적으로 선택한다. 양 팀이 모두 선택을 마쳐야 편성이 완료된다. 아이템 비용은 클랜코인과 무관한 해당 편성 예산에서만 차감한다.
- 양 팀의 아이템 선택은 독립적으로 저장한다. 상대 선택으로 화면 버전이 달라져도 같은 편성인지 확인해 최신 잔액·구매 내역에 합치며, 초기화 전 요청이나 자기 팀 중복 구매는 거부한다.
- 아이템은 커스텀 경기 규칙을 설명하는 텍스트 권한이다. 구매 내역은 경기 준비·진행 화면에 표시하고 효과는 운영진이 직접 적용한다. 게임 내 체력이나 사이트 맵·밴 규칙을 자동 변경하는 연결은 포함하지 않는다.

## 경기 시작 전 밴픽 설정 (2026-09-16)

- 역할·팀 편성 규칙과 밴픽 설정은 편성 진행 전에 정한다. 직접 배정은 **다음 단계**, 추첨은 **추첨 시작**, 지명·경매는 **편성 진행** 한 번으로 시작한다.
- 각 투표 제한 시간은 5~300초 정수이며 기본 맵 15초·영웅 20초다. 서버의 마감 시각을 기준으로 투표를 닫으며 다음 라운드에도 설정을 이어 쓴다.
- 직접 배정은 한 번의 **다음 단계**로 편성을 저장하고 맵 전용 화면으로 이동한다. 추첨은 현재 편성판의 공개 연출이 끝나면 자동으로 이동한다. 지명·경매도 편성이 완성되는 즉시 자동 이동하며, 실패한 경우에만 다시 시도 버튼을 제공한다. 적용 상태는 기존 편성 데이터에 저장되어 클랜원·재접속 화면에도 반영된다.
- 편성·공개 연출이 끝나면 첫 완료 확인을 즉시 요청한다. 서버 응답을 기다리는 동안 기존 편성 보드·맵·설정과 제목을 유지하고, 화면 위에 옅은 블러와 `경기 준비 중…`를 겹친다. 배경의 클릭·키보드 조작을 막고 실패 시 오버레이 안에서만 재시도한다. 맵이 이미 선택됐다면 경기/영웅 밴 시작 확인까지 같은 배경을 유지한다. 같은 상태의 재시도만 1.5초 간격을 두며, 서버 적용 확인 후 기존 맵 선택·밴픽·경기 진입을 이어간다.
- 맵 투표는 **편성 진행 → 필요 시 현재 편성판 추첨 공개 → 맵 유형 선택 → 맵 투표** 순서다. 운영진이 **전체 / 쟁탈 / 밀기 / 화물 / 혼합**을 고르고 **유형 선택 완료**를 누르면 즉시 후보 3개와 투표가 열린다. 전체는 단독 선택, 나머지는 복수 선택이며 별도의 맵 투표 시작 화면은 없다.
- 수동 맵 선택은 **편성 진행 → 유형 선택 → 이미지 아코디언에서 맵 선택 → 경기 시작** 순서다(영웅 밴을 켜면 경기 시작 전 영웅 밴 진행). 선택한 맵을 넓게 펼쳐 강조하며 저장 성공 후 다음 버튼을 활성화한다. 맵 선택은 자동 저장되어 모든 클라이언트·라운드 기록에 반영된다. 투표 카드에도 같은 실제 전장 이미지를 사용한다.
- **맵 확정하기** 한 번으로 본문 추첨 연출 후 영웅 밴을 자동 시작한다. 영웅 밴을 사용하지 않으면 경기로 바로 진행한다. 영웅 밴 화면의 **경기 시작**은 밴 확정과 경기 진입을 한 번에 저장하며 별도 결과 화면은 두지 않는다. 자동 진행 실패 시 다시 시도할 수 있고 재접속 시 저장된 맵에서 이어 간다.
- 설정 변경 시 영향받는 투표·결과를 초기화하고 준비 화면으로 돌아간다. 맵 설정 변경은 맵·영웅 투표를 초기화한다. 영웅 설정만 바꾸면 확정된 맵을 보존한다. 브라우저가 표시한 마감 시각을 함께 검증해 재시작 전 투표의 지연 제출을 거절한다. 수동 맵을 실제로 바꾸면 기존 영웅 밴을 다시 진행한다.
- 실제 맵 추첨은 본 화면 카드 강조가 득표 비율에 따라 빠르게 이동하다 감속하여 서버의 확정 맵에 멈춘다. 0표 맵은 흐리게 표시하고 연출에서도 제외하되 전부 0표면 세 후보를 균등하게 취급한다. 별도 팝업·확인 버튼·QA 가상 연출 기능은 제거했다. 재접속 시 연출을 반복하지 않으며 동작 줄이기 설정은 즉시 결과를 표시한다.

### 팀별 영웅 밴

- 편성 설정에서 팀당 1명/2명을 고른다(기본 2명). 각 출전자는 설정 개수까지 같은 가중치로 선택하며 초상화 클릭/취소를 즉시 저장한다. 관전자는 선택할 수 없다.
- 역할별 초상화 그리드와 양 팀의 득표 현황을 표시한다. 팀별 상위 1명/2명을 확정하며 동률은 영웅 ID 고정 순서, 무투표 팀은 밴 없음이다. 양 팀 중복 영웅은 한 번만 제외하며 부족한 자리를 임의로 채우지 않는다.
- 영웅 밴 단계에서는 M/A 토글을 숨긴다. 마감 후 **경기 시작**으로 밴·분석 맥락·경기 단계를 한 번에 저장한다. 기존에 밴만 확정한 열린 라운드도 같은 버튼으로 이어 간다.
- 라운드의 hero_ban_context에 버전·팀별 개수·팀별 영웅/역할/득표를 기록한다. 기존 라운드의 명단·포지션·맵·결과와 결합해 향후 숙련도 영향 분석에 활용할 수 있다. 깜짝 내전은 기존 삭제 수명을 유지한다.
- 예측 입력 키에 밴 영웅을 포함해 밴 변경 전 예측 재사용을 막는다. 영웅 밴 단계에는 샘플 확률을 만들지 않으며 모델 준비 상태를 표시한다. 실제 숙련도 데이터·밴 전후 확률·설명 모델은 후속이다.

## 1. 범위와 전제

- **세션은 당일 내전 전체, 라운드는 경기 한 판**이다. 내전 날짜는 세션 개설일로 고정하고 종료 시점까지의 라운드·회차를 기록한다([D-SESSION-01 용어 기준](../01-plan/glossary.md#내전-운영-용어)).
- 편성 대상은 **해당 라운드 출전자 10명·2팀**, 각 팀 **탱1·딜2·힐2**다. 관전자 명단 입력·출전자 선발은 이 편성의 범위에 포함하지 않는다. 세션에 사이트로 참여할 수 있는 클랜원을 10명으로 제한한다는 뜻은 아니다.
- 손들기·선호 추첨은 **역할 배정**, 주장 지명·경매는 **팀 구성**이다. `손들기 → 지명`, `선호 추첨 → 경매`처럼 조합한다.
- **사용자 확정:** 역할을 먼저 정하고 팀원을 선발한다. 지명·경매 중에는 역할을 변경하지 않는다.
- 지명·경매 시작 전에 전체 역할 **탱2·딜4·힐4**, 같은 역할의 주장 2명 포함, 팀별 목표 **탱1·딜2·힐2**를 검증한다. 이 조건에서는 남은 역할 자리에만 영입하면 끝까지 정원을 채울 수 있다.
- 역할 배정만 마치면 팀 구성은 아직 미완료다. 수동 배치 또는 별도로 선택한 자동 밸런스 단계로 이어진다. 자동 밸런스 알고리즘을 이 문서에서 확정하지 않는다.
- 세션이 열리면 클랜원은 사이트에서 실시간으로 참여하고 기능별 권한·진행 상태에 맞는 조작이나 베팅을 할 수 있다. 웹을 사용하지 않는 출전자에 대해서는 게임·디스코드 의사를 운영진이 대신 반영할 수 있다. 매 라운드 로그인·체크인을 강제하지 않는 방향과 사이트 참여 기능은 함께 유지한다.
- 같은 세션의 다음 라운드에는 저장한 방식을 불러오며, 이번 10명·역할·주장·시간·예산은 시작 전에 운영진이 확인한다. 세션 간 클랜 기본 설정 저장은 후속이다.
- 프로필 선호, 불가 역할, 개인 점수는 공유 화면에 기본 노출하지 않는다. 경매 포인트를 실력 점수·선수의 가치로 표현하지 않는다.

## 2. 운영 화면·클랜원 참여 화면·공유 화면

| 구분 | 운영진 조작 화면 | 클랜원 참여 화면 |
|---|---|---|
| 목적 | 세션·라운드 운영, 입력·중지·정정 | 사이트에서 실시간 확인·참여 |
| 기본 내용 | 설정, 가능한 후보, 접수 결과, 변경 이력 | 내전 날짜·현재 라운드, 같은 편성 진행, 본인에게 허용된 행동 |
| 개인 정보 | 권한에 맞는 선호·배정 조건 | 본인의 입력·접수 상태와 허용된 정보 |
| 조작 | 부여된 운영 권한과 대리 입력 | 해당 기능·역할·차례에 허용된 조작 및 라운드 베팅 |
| 접속 | 운영 권한이 있는 클랜원 계정 | 열린 세션에 클랜원 계정으로 접근 |

- 방송용 모달과 진입 버튼은 제거했다. 클랜원 전용 화면의 공개 내용과 기능별 참여 권한을 유지한다.
- 날짜·라운드 번호는 편성 카드 헤더에 통합한다. 일반 관전자에게 설정·편집/초기화·운영 가이드·내전 기록 아이콘을 숨긴다. 깜짝 개설자는 자기 세션 기록만 볼 수 있다.
- 세션 종료는 편성 시작 왼쪽의 기존 방식 설명 위치에 빨간 버튼으로 배치한다. 경기 현황에서는 무승부·무효/재경기 행의 왼쪽에 두고 결과 확정 뒤에는 다음 경기와 한 행에 배치한다. 미확정 경기에서는 결과/무효 기록 후 활성화한다. 종료 확인창은 깜짝 기록 삭제와 정규 기록 보존을 구분해 알린다.

### 점수·예측 비교 UI (2026-09-16)

- 정규 내전의 운영진 화면에 점수 토글을 제공한다. 2026-09-18부터 M의 사용자용 명칭은 **평가 점수**(운영진 평가), A는 **분석 점수**(분석용 추정값)다. Free는 평가만, Premium은 평가/분석 중 하나를 표시한다. 멤버와 깜짝 방에는 점수·예측 비교 영역을 전달하지 않는다.
- 평가 점수는 최근 정규 라운드 100개에서 사용자별 가장 최근 값을 읽고 현재 라운드 값을 우선한다. 분석 점수는 아래 2026-10-09 V1 집계를 사용하며 전적이 없는 값은 `—`로 표시한다. 토글은 개인 점수와 팀 합계에 적용한다. 카드의 M/A 접두사는 제거하고 `+1.75점`처럼 부호·단위를 붙여 닉네임/전적과 분리한다. 팀 제목 아래에 배정된 인원의 합계를 복원하며, 미등록 점수가 섞이면 합계를 `—`로 표시한다. 팀 간 차이와 카드의 중복 역할 이름은 표시하지 않는다.
- M/A 토글은 기존 출전 인원 표시 자리에 둔다. 2026-10-09부터 두 팀 제목 사이의 `VS` 대신 비교 그래프를 표시한다. `화면 표시 > 팀 비교 그래프`에서 점수 합계(기본) 또는 Premium 정규 내전의 예측 승률을 선택하고, 평가·분석 토글에 따라 합계·예측 기준을 갱신한다. 음수 합계도 막대 비율로 비교하되 승률로 해석하지 않는다. 제목의 합계에 마우스를 올리거나 키보드로 포커스하면 예측 승률 첫 행, 평가·분석 합계 둘째 행의 팝업을 유지한다. 팝업 표시 설정은 중앙 그래프와 별개다. 팀 제목은 `1팀`·`2팀`만 표시하고 점수·승률은 중앙 그래프에만 표시한다. 맵 선택·투표 단계에서는 선택된 맵이 반영된 승률을 본문에 한 줄로 유지하며, 맵이 바뀌면 이전 맵/일반 예측값을 재사용하지 않는다. 실제 모델 미연결 상태는 빈 막대와 `—`, ‘예측 준비 중’으로 표시하고 미완성 명단은 ‘10명 편성 후 확인’으로 표시한다. 토글 옆 샘플 안내는 제거하고 승률의 작은 샘플 표시는 유지한다. 그래프 선택은 편성 규칙과 분리해 완료된 편성을 초기화하지 않고 저장하며 다음 라운드에 이어진다.
- QA 운영진 화면에는 요청에 따라 미등록 평가 점수·승률을 결정적인 샘플 값으로 표시하고 샘플임을 명시한다. 2026-10-09부터 편성 중 A는 실제 집계 값만 표시한다. 기존 저장 점수가 우선하며 선수 교환·토글·맵 변경에 따라 샘플 승률을 갱신한다. 샘플 값은 DB·점수 편집 폼에 전달하지 않고 실제 기록·모델과 분리한다. 운영 환경에는 적용하지 않는다.
- 수동 맵 클릭 즉시 선택 맵과 비교 영역을 함께 갱신하고 저장 실패 시 이전 맵으로 복구한다. 향후 예측 결과는 명단·점수 종류/값·맵 식별값이 현재 상태와 일치할 때만 표시하므로 이전 맵의 늦은 결과를 재사용하지 않는다. 실제 팀 승률 예측·학습은 후속이다. 2026-10-09 분석 V1의 역할/맵 보정은 아래 별도 규칙을 따른다.

### 참가자 정보·무승부 (2026-09-18)

- 점수 표시 토글은 편성 화면에만 둔다. 맵 유형 선택·맵 투표·영웅 밴·경기 현황에서는 숨기며, 경기 현황의 출전 라인업은 이름과 권한에 따른 평가 점수를 표시한다. 팀 합계·보조 정보·상세 팝업은 편성 화면 설정과 관계없이 노출하지 않는다. 플레이어 카드 숫자에서 `점` 단위는 생략한다.
- 경기 현황의 참여자 점수를 눌러 평가 점수를 직접 입력한다. 위아래 증감 버튼과 별도 점수 조정 드로워는 제공하지 않는다. 편집 중에는 팀 승리 강조를 해제하고 다른 조작을 차단하며 키보드 포커스를 입력·저장·취소 안에 유지한다. 입력 뒤 체크 또는 Enter로 저장하고 X·Escape·바깥 클릭으로 취소한다. 바깥 클릭은 저장이나 다른 버튼 동작 없이 편집만 취소한다. 분석 점수는 경기 시작 시 고정된 자동 계산 참고 값이며 수정하지 않는다. 범위는 소수를 포함해 **-10~10**이며, 입력·서버 저장 모두 범위를 넘는 값은 거절한다. 기존 점수 조회·수정 권한을 유지한다.
- 라운드 설정 `밴픽 > 승부예측 사용`으로 경기 시작 전에 참여 기능을 켜거나 끈다. 켰을 때 세부 설정 `마감 시간(분)`을 직접 입력하며 기본값은 2분, 허용 범위는 1~10분 정수다. 끄면 입력을 숨기되 초안 값은 유지하고 미리보기·드로워 안내도 설정한 시간을 표시한다. 기존 라운드와의 호환을 위해 사용 기본값은 켜짐이며 Premium 정규 내전에서만 실제 동작한다. Free 토글은 잠기고 서버·DB도 시간 변경을 거부한다. 설정은 다음 라운드에 이어지며 편성 결과는 초기화하지 않는다.
- 승부예측은 우측 중앙 내전 기록 탭 아래의 버튼으로 드로워를 연다. 데스크톱은 내전 기록처럼 호버로 열고 포인터가 창 밖으로 나가면 닫으며, 모바일은 탭으로 연다. 클릭·키보드 열기와 닫기 후 버튼 포커스 복귀를 지원하고 점수 편집 중에는 호버도 차단한다. 코인 풀 경기에서는 편성 편집부터 참여할 수 있으며 경기 현황 진입부터 공통 마감 시간을 적용한다. 경기 현황의 맵 행 높이를 유지하면서 카드 오른쪽 테두리에 검은 바탕·초록 글씨의 `승부예측 마감까지 m:ss` 디스플레이를 걸쳐 배치하고 1초마다 갱신한다. 시간은 안내 문구보다 크게 표시한다. 시간이 지나면 회색 `승부예측 마감`으로 바꾸며 결과가 확정되면 경기 결과 표시로 대체한다. 우측 드로워 버튼에는 시간 배지를 붙이지 않는다. 늦게 연 드로워도 경과한 서버 기준 시간을 사용하며 표시 변경은 마감 시각을 수정하지 않는다. 기록 조회 권한이 없는 멤버에게는 예측 버튼만 표시한다. 꺼진 경기의 제출·수정은 서버와 DB에서 거부하며 출전자는 관전자 전용 안내와 집계·순위를 확인한다.

- 참가자/대기 클랜원 카드에 마우스를 올리거나 키보드로 포커스하면 현재 세션의 승·무·패, 승률, 연승/연패, 공개 권한이 있는 두 점수와 마이크 상태를 보여 준다. 기존 드래그·클릭 명단 편집을 유지한다.
- 라운드 설정은 `편성 / 화면 표시 / 밴픽` 탭으로 나눈다. 화면 표시에서 카드 점수·보조 정보·팀 비교 요약·플레이어 세션 정보 팝업을 각각 켜고 끄며, 보조 정보는 세션 전적 또는 현재 연승·연패 중 하나를 선택한다. 점수를 숨기면 닉네임과 보조 정보를 카드 중앙에 두고, 숨긴 영역은 빈 공간을 남기지 않는다. 표시 설정은 편성 규칙과 분리해 편성 이후에도 바꿀 수 있다.
- 전적은 운영진 또는 열린 깜짝 세션 생성자에게만 제공한다. 현재 `series_id`의 모든 라운드만 집계하며, 일반 멤버에게 전적 DTO/점수를 보내지 않는다. Free 분석 점수도 서버에서 제거한다.
- 결과 입력에 `draw`(무승부)를 추가한다. 무승부는 출전/무승부 수에 포함하고 연승·연패를 끊는다. 세션 승률은 `승 / (승 + 무 + 패)`이며 소수 첫째 자리까지 표시한다. 무효/미정은 집계하지 않는다. 2026-10-09 이전 경기는 기존 적중 5코인 지급을 유지하며 새 경기의 승부예측은 아래 코인 풀 규칙을 따른다.
- 프로필에는 아직 마이크 저장 필드가 없으므로 **미설정**으로 표시한다. 다른 파티 신청서의 마이크 선택을 현재 프로필 상태로 재사용하지 않는다. 실제 분석 모델과 마이크 입력·저장 연결은 후속이다.
- UI 참고: [NN/g 점진적 공개](https://www.nngroup.com/articles/progressive-disclosure/)에 따라 자주 쓰는 순위 변경은 바로 제공하고 부가 옵션만 메뉴로 옮긴다. 메뉴의 키보드·포커스 동작은 [WAI Menu Button](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/) 기준과 기존 Base UI 컴포넌트를 따른다.
- 주장 지명·입찰·아이템 선택의 입력 권한은 위 2026-09-18 규칙을 따른다. 동시에 들어온 대리 입력과 직접 입력을 중복 반영하지 않는다. 세션 접근만으로 전체 명단 편집 권한을 주지 않는다. 주장 이탈 시 대리인 지정 전환은 후속이다.
- 베팅은 경기 승부예측이며 팀원 경매의 입찰과 다르다. Premium 정규 내전·해당 경기 비출전·마감 조건을 유지한다. 새 코인 풀 경기의 접수는 편성 편집부터 시작한다.
- 역할 배정 중에는 중앙에 현재 사람/역할, 하단에 미배정 인원과 역할별 남은 정원을 보여 준다. 역할만 정해진 사람을 특정 팀에 확정된 것처럼 놓지 않는다.
- 팀 구성 중에는 좌우 팀의 **딜·딜·탱·힐·힐**을 고정하고 가운데에 현재 지명·경매 대상을 둔다. 남은 후보는 하단에 둔다.

### 관전자 코인 풀·공개 순위 (2026-10-09)

- 내전을 처음 연 `balance_session_series.host_user_id` 계정은 관전 중 승부만 예측하며 코인을 걸거나 배당을 받지 않는다. 다른 운영진에게는 이 제한을 적용하지 않는다. 개설자도 출전 중이면 기존 관전자 조건에 따라 예측할 수 없다. 선택 저장·변경·취소와 같은 마감 규칙을 적용하고 코인 풀·코인 참여 인원에는 포함하지 않는다. 실제 승패·무승부 적중률과 순이익 0은 현재 내전 순위에 공개한다. 코인을 건 적중자가 없어 반환하는 경기라도 개설자의 무코인 예측은 실제 결과를 집계하며 무효는 제외한다. 기존 미정산 개설자 코인은 반환하고 선택은 무코인으로 보존하며 정산된 과거 기록은 바꾸지 않는다. 클라이언트에서 금액 입력을 숨기고 DB RPC에서 양수 코인 요청을 거부한다.
- 개인 잔액에서 원하는 양의 정수 코인을 건다. 제출 즉시 원금을 예약 차감하고 마감 전 선택·금액 변경은 차액만 처리한다. 취소 시 전액 반환하며 잔액 부족·음수·소수·중복 차감은 DB 트랜잭션에서 차단한다.
- 경기별 `match_live` 전환 시 서버가 설정한 마감 시간(기본 2분)을 확정한다. 편성·밴픽 동안에는 접수하며 재접속·새로고침으로 시간을 연장하지 않는다. 이미 시작한 경기의 마감 시각은 유지하고 시간 설정 변경은 시작 전에만 허용한다. 마감 후 예측 변경·취소는 거부한다.
- 확정 결과의 적중자에게 `전체 풀 × 본인 참여 코인 / 적중자 참여 코인 합계`를 원금 포함 배당으로 지급한다. 코인 단위 내림 후 남는 코인은 소수 나머지가 큰 순서, 동률이면 사용자 UUID 순서로 배분해 전체 풀을 남김없이 정산한다. 수수료·클랜 코인 차감·추가 발행은 없다.
- 무승부는 별도 적중 선택지다. 무효·재경기 또는 코인을 건 적중자 없음은 전액 반환하며 코인 참가자의 적중률 집계에서 제외한다. 관전자가 명단에 편입되거나 사용 설정을 끄거나 미시작 경기를 종료·삭제하면 예약 코인을 반환하고 미정산 무코인 선택도 취소한다.
- 현재 내전(`series_id`)의 닉네임·적중률(적중/정산 경기)·누적 순이익(배당−원금)을 같은 클랜 멤버에게 공개한다. 다른 사람의 잔액과 개별 실시간 선택·금액은 공개하지 않고 선택지별 총 코인·예상 배수만 제공한다. 다른 내전은 순위에 섞지 않는다.
- `prediction_pool_enabled`는 새 경기부터 켜지고 기존 경기·기존 원장은 유지한다. QA 마이그레이션만 적용했으며 운영 반영은 보류한다. 제출·환불·정산 RPC는 경기 → 예측 → 개인 잔액 순서로 잠그고 중복 결과 확정을 차단한다.

## 3. 공통 진행 상태와 변경 규칙

아래는 **라운드 안 편성 과정**의 상태다. 편성 완료·라운드 종료·세션 종료는 서로 다르며, 결과 기록 후 같은 세션에서 다음 라운드를 진행할 수 있다.

| 상태 | 허용되는 행동 | 공유 화면 |
|---|---|---|
| 준비 | 명단·선호·역할·주장·규칙 점검, 시작 | 방식과 참가자, 시작 대기 |
| 진행 | 현재 차례에 맞는 배정·지명·유효 입찰 접수 | 현재 단계, 확정 결과, 남은 시간 |
| 중지 | 시간 정지, 원인 확인, 재개 또는 정정 | `진행 중지`와 마지막 확정 상태 |
| 완료 | 공개 연출 종료 후 맵 선택·밴픽/경기로 자동 전환 | 확인 중에는 기존 화면 위에 블러·준비 표시, 이후 최종 라인업 |
| 정정 | 수정 범위 미리 보기, 변경 사유 기록, 다시 검증 | `정정 중` 후 바뀐 이름·역할·예산만 짧게 표시 |

- 실제 결과는 서버가 확정하고 공유 화면은 이를 표현한다. 애니메이션 종료가 결과 접수·타이머의 기준이 되지 않는다.
- 지명·입찰은 편성 식별자·진행 버전·요청 식별자를 검증한다. 중복 요청, 이전 차례의 클릭, 정지 중 요청은 적용하지 않고 조작자에게 이유를 보여 준다.
- 재접속은 최신 확정 상태로 복구하며 이미 공개한 결과를 다시 추첨하거나 장면 전체를 재생하지 않는다. 공유 화면 연결이 끊기면 연결 상태와 마지막 갱신 시점을 표시한다.
- 시간제 진행 중 조작 연결이 끊기면 서버에서 중지 처리하는 경로를 마련한다. 연결 상태 판정 전 만료된 단계는 서버 이력을 기준으로 복구하며 소급 접수하지 않는다.
- 시작 후 명단·역할 변경은 진행 중지와 정정을 거친다. 이후 선택에 영향을 주면 **영향받는 단계 이후를 취소**할 범위를 먼저 보여 준다.
- 다시 보기 버튼은 제공하지 않는다. 명단 수정 후 새 편성은 새로운 추첨이며, 서버 이력에 이전 시작·초기화·다음 시작을 모두 보존한다. 세밀한 정정 사유 입력·영향 범위 확인은 후속이다.
- 최종 팀 구성 완료 조건은 중복 없는 10명, 양 팀 5명, 팀별 역할 정원 충족이다. 미배정자가 남았는데 완료로 표시하지 않는다.

## 4. 기존 방식 — 게임 채팅 손들기

아래는 기존 클랜 운영 방식과 후속 수집 UI 제안이다. 현재 앱에서는 게임 채팅 순서를 운영진이 확인해 확정한 수동 명단에 직접 반영하며, 별도 역할 모집 화면이나 채팅 자동 수집은 제공하지 않는다.

**시작 조건:** 출전자 10명과 역할 정원이 있고 운영진이 모집 순서를 선택했다. 기존처럼 역할별로 모집하는 방식을 유지하며 특정 순서를 공정성 개선으로 설명하지 않는다.

1. 운영진이 모집 역할을 열면 공유 화면 중앙에 `딜러 모집 · 4자리`처럼 표시한다.
2. 게임 채팅의 `손` 순서를 운영진이 확인하고 해당 이름을 한 번씩 선택한다. 해당 역할에 순차 배정하며 정원이 차면 다음 역할로 넘어간다.
3. 이미 배정된 사람은 후보에서 빠진다. 다른 역할로 변경하려면 기존 배정을 취소한 뒤 다시 반영한다.
4. 역할 10명 배정 완료 후 선택한 팀 구성 단계로 이어진다.

**예외:** 채팅 도착 순서가 다르게 보이거나 동시 지원이 있으면 운영진이 확인한 순서를 기준으로 결정한다. 앱이 채팅을 자동 읽거나 선착순을 검증한 것처럼 표시하지 않는다. 지원자가 부족하면 해당 역할을 남겨 두고 모집을 이어가며 남은 사람을 강제로 배정하지 않는다.

**공유 연출:** 확정한 이름이 역할 영역으로 약 **400ms**에 이동하고 남은 정원만 갱신한다. 선착순 순위표·낙선 연출은 만들지 않는다. 마지막 사람까지 배정되면 역할별 결과를 한 화면에 정리한다.

## 5. 선호 추첨 — 공통 무작위 순서

**시작 조건:** 확정된 출전자 10명의 프로필 기본값 또는 본인이 저장한 이번 라운드 선호를 사용한다. 선호가 없어도 시작할 수 있다. 미설정/명시적 `선호 없음`인 사람에게 임의 순위를 만들지 않고 그 사람의 차례에 남은 역할 자리를 추첨한다.

1. 운영진이 시작하면 **10명의 무작위 순서와 그 순서로 계산한 역할 결과를 저장**한다.
2. 순서가 앞선 사람부터 남은 정원 중 가장 선호하는 역할을 받는다. 정원은 전체 탱2·딜4·힐4다.
3. 계산이 완성됐으면 저장한 추첨 순서에 따라 역할 결과를 공개한다. 화면 연출은 저장된 결과를 표현하며 계산·접수·재추첨을 실행하지 않는다.
4. 역할 결과 확인 후 선택한 팀 구성 단계로 이어진다. 팀 재구성만 실행할 때는 역할 추첨 결과를 유지한다.

**공정성 설명:** 모두 같은 무작위 순서 기회를 갖는다. 모든 1지망을 먼저 채우는 규칙은 아니며 앞사람의 2지망 때문에 뒷사람의 1지망이 마감될 수 있다. 기본안은 독립 추첨이며 연속판 보정·점수 보정은 포함하지 않는다.

**불가 역할:** 첫 기준안은 세 역할을 모두 수용할 수 있는 경우의 단순 순차 배정이다. 불가 역할을 허용하면, 가능한 전체 배정이 있어도 단순 순차 배정이 막힐 수 있다. 해결 알고리즘을 별도로 정하기 전에는 불가 역할이 있는 상태에서 자동 추첨을 시작하지 않고 수동 합의로 연결한다. 동순위 선호도 임의 순서로 해석하지 않는다.

**예외:** 정원·선호 변경으로 완료할 수 없으면 결과 공개 전에 중지한다. 역할 부족을 강제 배정·무통보 재추첨으로 해결하지 않는다. 이미 추첨한 뒤의 수정은 이전 순서·사유를 기록한다.

**공유 연출:** 역할 추첨 시작 시 현재 편성판의 자리들을 추첨 순서대로 공개한다. 처음 잠깐은 순서를 섞는 상태를 보여 주고 이후 역할·자리·전체 진행 수를 약 9초 동안 표시한다. 1·2·3지망 여부나 비공개 선호는 공개하지 않는다. 모든 클라이언트는 같은 저장된 추첨 ID와 시작 시각을 사용하며 연출이 끝나면 맵 단계로 자동 이동한다. 재접속은 현재 시점에 합류하고 완료 뒤에는 연출을 다시 시작하지 않는다. 동작 줄이기 설정에서는 결과를 바로 표시한다.

## 6. 주장 지명 — 두 주장과 8번의 선택

**시작 조건:** 전체 역할 정원이 맞고 같은 역할의 주장 2명을 선정했다. 두 주장도 10명에 포함되며 자기 팀의 해당 역할 1자리를 차지한다. 주장 선정은 운영진 지정이 기준안이고 자동 실력 균등 선정을 가정하지 않는다.

1. 먼저 지명할 팀 A를 추첨·저장한다. 다른 팀은 B이며 화면에는 실제 팀 이름과 함께 순서를 표시한다.
2. 남은 8명 지명 순서는 **A → B → B → A → A → B → B → A**다. 각 팀이 4명씩 선택한다.
3. 현재 주장이 팀원을 선택한다. 어느 팀의 주장도 아닌 운영진은 대리 선택할 수 있으며, 주장을 겸하는 운영진에게는 상대 팀 대리 선택 권한이 없다.
4. 자기 팀에 남은 역할 자리와 맞는 후보만 선택할 수 있다. 불가능한 후보는 가리고 넘어가기보다 선택 불가 이유를 명확히 표시한다.
5. 확정 후 다음 순번으로 이동한다. 같은 팀의 연속 차례도 `다시 A팀 차례`로 구별한다. 8번 선택하면 최종 팀을 공개한다.

**시간 제안(미구현):** 지명당 **30초**와 시간 초과 시 중지는 후속 제안이다. 현재는 시간 제한 없이 현재 주장 또는 운영진이 선택하고, 자동 무작위 지명은 하지 않는다. 선택 가능한 사람이 한 명뿐이어도 한 번의 확정으로 진행한다.

**예외:** 주장 이탈은 중지 후 같은 팀의 대리인 지정 또는 진행 취소를 결정한다. 마지막 선택 취소는 공개 이력에 남기고, 이전 지명 정정은 그 이후 선택까지 영향 범위를 검토한다. 같은 역할 주장·스네이크 순서가 실력 균형을 보장하지 않는다.

**공유 연출:** 현재 팀 테두리와 중앙 차례 안내를 함께 강조한다. 지명 확정 시 이름 카드를 약 **700ms**에 해당 팀 역할 자리로 이동한다. 다음 후보 정보가 읽힐 수 있게 연속 효과를 짧게 유지한다. 지명 번호를 실력 순위처럼 표시하지 않는다.

## 7. 포인트 경매 — 동일 예산으로 8명 영입

**시작 조건:** 고정 역할과 같은 역할의 주장 2명, 각 팀 4자리, 예산·입찰 규칙을 준비 화면에서 확인했다. 주장 영입 비용은 0P로 동일하게 시작한다.

| 항목 | 기준안의 예시값·규칙 |
|---|---|
| 시작 예산 | 기본 각 팀 **1,000P**, 설정에서 변경; 이번 편성 전용이며 클랜코인·현금·계정 자산과 분리 |
| 최소 낙찰가 / 증분 | 기본 **10P / 10P**, 설정한 단위 이상으로 최고 유효 입찰 갱신 |
| 경매 순서 | 주장 제외 8명의 순서를 사전 추첨·저장·공개 |
| 최초 제한 시간 | 기본 한 사람당 **20초**, 설정에서 10~60초로 변경 |
| 막판 입찰 | 남은 설정 연장 시간 이내 유효 입찰이면 해당 시간을 다시 확보하되 **설정 시간 + 30초**가 최종 마감; 중지 시간 제외 |
| 총 연장 한도 | 기본 20초 + 최대 30초(50초); 설정 시간에도 추가 연장은 최대 30초 |
| 입력 경로 | 주장 본인의 팀 조작, 어느 팀의 주장도 아닌 운영진의 대리 조작 |

1. 현재 후보의 이름·역할, 최고 유효 입찰, 양 팀 남은 예산·역할 자리를 공유 화면에 크게 표시한다.
2. 해당 경매의 입력 권한자가 팀·가격을 제출하면 서버가 권한·예산·역할·접수 시각을 검증한다. 주장 직접 입력과 운영진 대리 입력은 그 경매에 정한 입력 규칙을 따른다. 유효 입찰만 최고가를 갱신하고 마감 연장을 적용한다.
3. 마감 시 최고 유효 입찰 팀에 영입을 확정하고 비용을 한 번 차감한다. 낙찰 시점부터 설정한 준비 시간이 끝나면 다음 후보가 자동으로 열린다. 낙찰 결과는 최소 2.5초 유지한다.
4. 팀이 정원·역할을 채우면 관련 입찰이 불가능하다. 전체 8명 영입 완료 후 아이템 사용 시 양 팀 구매/기권을 기다리고, 이후 편성을 완료한다.

**입찰 상한:** `남은 예산 − 최소 낙찰가 × (남은 자리 수 − 1)`. 남은 자리 수에는 지금 영입할 자리를 포함한다. 예를 들어 1,000P·4자리이면 상한은 970P다. 이 제한과 별개로 현재 후보의 역할 자리가 있어야 한다. 한 팀의 최고 입찰 예약액과 이미 차감한 금액을 중복 계산하지 않는다.

**동시 입력:** 서버에 접수된 순서대로 원자적으로 처리한다. 같은 금액이면 먼저 유효하게 접수된 요청만 인정하고 뒤 요청에는 현재 최고가를 알려 준다. 거절한 요청을 공유 화면에서 접수된 것처럼 띄우지 않는다. 음성·방송에서 들린 순서를 자동 판별하는 기능은 없으며 대리 입력 기준을 시작 전에 안내한다.

**무입찰:** 설정한 최소가(기본 10P)로 한 번 재상정한다. 다시 무입찰이면 역할·정원·최소 예산을 만족하는 팀 중 추첨으로 최소가에 배정한다. 가능 팀이 하나면 해당 팀에 배정한다. QA 앱에는 이 기본안을 적용했으며 다른 처리 방식은 후속 규칙 검토 대상이다. 누구도 영입할 수 없으면 정합성 오류로 중지한다. 유찰을 참가 탈락으로 처리하지 않는다.

**중지·정정:** 중지 중 새 입찰은 거절하며 재개 시 저장한 잔여 시간을 사용한다. 낙찰 취소 시 예산·자리·후보를 함께 복구하고 이후 영입에 미치는 영향을 검증한다. 운영진이 임의로 타이머만 늘리지 않으며 시간 규칙 변경은 중지·공개 안내 후 새 단계에 적용한다.

**공유 연출:** 최고 입찰 팀은 팀 색상·팀명으로 표시한다. 낙찰은 이름·팀·가격을 **최소 2.5초** 보여 주며 참가자 표에도 해당 역할 자리를 반영한다. 무입찰에는 실패 효과음·불쾌한 낙인 문구를 쓰지 않는다. 최종 팀 화면에서 가격은 보조 정보이며 선수 이름보다 크게 표시하지 않는다.

## 8. 공유 화면의 시각·연출 규칙

- **16:9 공유 화면**, 1280×720·1920×1080에서 이름·현재 차례·가격·남은 시간을 읽을 수 있게 검증한다. 긴 이름은 최소 한 번 전체를 확인할 수 있게 하며 팀 표에서 필요한 이름을 말줄임만으로 구분하지 않는다.
- 기존 다크 화면과 팀별 파랑·빨강을 이어 쓰고 현재 차례는 중립색·골드 테두리로 강조한다. 팀명·역할 아이콘·텍스트를 함께 써서 색만으로 상태를 구분하지 않는다.
- 최종 결과는 양 팀을 함께 약 **1.5초**에 드러낸 뒤 고정한다. 한 팀만 오래 감추거나 승패를 암시하는 연출을 넣지 않는다.
- 연출 강도는 `간결 / 기본 / 방송용` 후보로 둔다. 간결은 약 **200ms**, 기본은 각 모드의 위 시간, 방송용은 이름·전환 강조를 키운다. **방송용 선택만으로 지명·입찰 제한 시간을 늘리지 않는다.**
- 기본 무음. 소리는 선택 기능으로 두고 볼륨·미리 듣기를 제공한다. 빠른 점멸·연속 화면 흔들림은 쓰지 않는다.
- 동작 줄이기 설정에서는 이동·확대 연출 대신 확정 결과를 표시한다. 별도의 건너뛰기·다시 보기 버튼은 제공하지 않는다.
- 공유 화면 타이머는 서버 마감 시각에 맞춘다. 디스코드·방송의 전달 지연은 있을 수 있으므로 주장 직접 입력 시 자신의 조작 화면을 마감 기준으로 삼는다. 공유 지연을 이유로 마감 후 입찰을 되살리지 않는다.
- 공개 연출은 저장한 결과의 표현이며 다시 뽑기가 아니다. 재접속·공유 화면 진입은 현재 단계에 합류하고 지난 입찰·지명을 대량 재연출하지 않는다.
- 정정은 변경된 사람·팀·가격과 `정정됨` 상태를 보여 준다. 개인 선호·민감한 사유는 공개 로그에 자동 노출하지 않는다.

### 공유 화면 배치 기준안

1280×720을 기준으로 한다. 대화 안의 축소 시연과 실제 방송 화면의 크기를 구분하며, 1920×1080에서는 같은 비율로 확장한다.

| 요소 | 기준안 |
|---|---|
| 화면 여백 / 열 간격 | 바깥 32px / 열 사이 24px |
| 팀 구성 배치 | 좌측 1팀 / 중앙 현재 대상 / 우측 2팀, 하단 남은 후보 |
| 팀 명단 | 슬롯 높이 최소 66px, 이름 20px 이상, 긴 이름은 두 줄 허용 |
| 현재 대상 / 가격·시간 | 이름 36px, 가격 40px, 시간 32px; 이름과 역할을 가장 먼저 읽게 배치 |
| 보조 정보 | 16px 이상; 압축된 방송에서도 읽히는지 실제 공유로 검증 |
| 차례 강조 | 팀 색은 유지하고 현재 팀에 골드 테두리 + `현재 지명` 문구 |
| 작은 조작 화면 | 팀 2열의 역할 위치는 유지하며 중앙 진행 정보를 위로 이동 |

### 대화 시연의 범위

**초기 연출 비교 시연:** 네 방식과 `간결 / 표준 / 방송` 속도를 비교하며 정해진 명단·결과를 재생한다. 기존 방식은 마지막 역할 입력, 선호 추첨은 10명 결과 공개, 주장 지명은 8번의 확정 장면, 경매는 마지막 5초부터 한 선수의 영입까지를 보여 준다.

시연의 재생·일시정지·마지막 장면 이동은 비교용 제어다. 실제 운영에서 `건너뛰기`가 미입력 지명·입찰을 대신 결정할 수 있다는 뜻이 아니다. 실제 화면에서는 저장된 확정 결과의 표현만 건너뛴다.

**세션 참여 시안(2026-09-16):** 세션 개설·고정 내전 날짜·라운드 기록을 바탕으로 운영진/클랜원/방송의 관점을 전환한다. `손들기 또는 선호 추첨 → 주장 지명 또는 경매`를 조합하고, 권한에 따른 직접 지명·입찰, 비출전자 베팅, 라운드 결과 기록·다음 라운드·세션 종료를 로컬 상태로 시연한다. 다음 라운드는 출전자·배치·주장을 유지하고 이전 베팅은 그 라운드의 개인 기록에 남긴다. 재편성은 지명 차례·경매 잔액 등을 새로 시작한다.

관점·시작 장면 선택과 `마감 시점 보기`는 시안 비교 도구로 제품 화면 밖에 둔다. 마감 시점 이동은 실제 운영진의 조기 마감 기능을 확정하는 것이 아니다. 클랜원 관점과 방송 관점은 동일한 시연 상태를 보되 개인 베팅 내역은 방송에 표시하지 않는다.

선호 추첨 결과·최초 지명 팀·경매 상정 순서·무입찰 배정은 고정된 예시다. 지명·입찰·베팅의 세부 조작은 검토안이며, 실제 다중 접속 동기화·서버 권한 검증·추첨 알고리즘·코인 정산·DB 저장·종료 후 세션 재개는 구현하지 않았다. 시안을 통과한 검증은 아래 실제 구현 수용 기준을 완료 처리하지 않는다.

## 2026-10-09 경매 시간 설정·미리보기

- `낙찰 후 준비 시간(초)`는 다음 선수에 사용할 금액을 정하는 시간이며 기본 5초, 0~60초 정수다. 낙찰 공개와 동시에 시작하고 최소 2.5초 결과 연출은 유지한다. `전략 준비 시간(초)`는 아이템 공개 직후 팀원 경매 전 단계 전용이다.
- `입찰 연장 시간(초)`는 기본 5초, 0~30초 정수다. 막판 유효 입찰은 남은 시간을 설정값으로 확보하며 기본 입찰 시간+30초 상한은 유지한다. 0이면 연장하지 않는다. 중지/재개는 두 타이머의 잔여 시간을 보존한다.
- 설정 입력 순서는 팀 크레딧 → 최소/증액 단위 → 입찰 시간 → 입찰 연장 시간 → 낙찰 후 준비 시간이다.
- A팀 주장 미리보기는 입찰·낙찰 한 세트와 남은 선수 요약으로 구성한다. 설정한 준비/연장 시간을 시연하고 아이템 예시는 `영웅 밴 1장 100cr / 맵 선택권 1장 50cr / 영웅 밴 2장 200cr`로 표기한다. 실제 클랜 아이템 카탈로그는 그대로 사용한다. 설정창에서 미리보기와 중복되는 설명은 제거한다.

### 2026-10-09 — 주장 입찰·편성 맵·분석 점수

- 입찰은 해당 팀 주장만 가능하다. 주장인 운영진은 자기 팀만 입찰하며, 주장이 아닌 운영진은 관리·시계 제어만 한다. 최고가 팀은 상대 팀이 올릴 때까지 증액할 수 없다. UI·Server Action·DB CAS 모두 제한한다.
- 낙찰 결과 2.5초 뒤부터 남은 준비 시간에는 다음 경매 선수의 이름·역할을 표시한다. 준비 시간은 기존대로 낙찰 시점부터 계산하며 0초 설정이면 결과 공개 후 바로 다음 입찰로 넘어간다.
- 맵 투표를 끄면 출전 명단 편집 화면에서 경기 맵을 먼저 고른다. 미선택 상태로 편집 화면을 열면 쟁탈 유형과 맵 이미지가 펼쳐진 팝업을 제공하고, 선택 즉시 닫아 맵 사진·이름을 클랜원 목록 위 배너에 표시한다. 배너를 눌러 변경하며 저장 전 미완료 명단 저장을 기다린다. 배너와 클랜원 목록은 네 방향으로 함께 이동하고 점수 토글은 참여자 목록 왼쪽 위에 표시한다. 이미 고른 맵의 팝업은 자동으로 다시 열지 않는다. 지명·추첨 등 편성 완료 후 미리 선택한 맵이 있으면 별도 준비 화면 없이 경기로 이동한다. 영웅 밴을 사용하면 밴 투표로 이동한다. 미선택 상태로 편성을 마쳤으면 선택 화면에서 맵을 고르고 바로 같은 흐름을 진행한다. 투표 사용 여부와 DB 필드·단계 이름은 그대로 보존한다.
- 분석 V1은 이 라운드 이전의 정규 내전 전적만 사용한다(무효 제외, 무승부 0.5승). 전체 승률은 중립 50%의 10경기로 보정하고, 역할 승률은 전체 전적의 10경기, 맵+역할 승률은 역할 전적의 10경기로 보정한다. 점수는 `20 × (보정 승률 − 0.5)`, 소수 둘째 자리, -10~10이다. 기존 match 기록은 역할 정보가 없으므로 전체/맵 기준만 사용한다. 중복 ID의 명시 match 기록이 우선한다.
- 맵+역할 → 해당 맵 전체 역할 → 해당 역할 전체 맵 → 전체 전적 순으로 선택한다. 전적이 없는 참가자는 A=null이며 임의 샘플 A를 만들지 않는다. 이 점수는 조건별 승률의 보정값이며 개인 기여도나 보정된 실력·실제 팀 승률 모델은 아니다.
- 맵/역할 변경 시 분석만 갱신하며 평가 점수는 유지한다. 경기 시작 시 서버가 A를 확정하고 이후 평가 저장·부분 RPC 입력은 A를 변경하거나 삭제할 수 없다. 기존 완료 기록은 재작성하지 않는다. 집계 모델은 Premium 정규방의 기존 점수 열람 대상에게만 제공한다.

- 사용자 화면의 라운드 표기는 `경기`로 통일한다. DB의 세션·round 식별자는 유지한다. 내전 제목과 호스트는 카드 전체의 중앙에 맞추고 제목 아래의 내전 유형·미확정 경기의 `경기 진행 중` 배지는 생략한다. 경기 현황의 맵 사진 배너는 맵 행 왼쪽에 둔다. 팀 위에 포인터를 올리면 개별 선수 대신 팀 영역 전체를 강조한다. 팀 제목이나 팀 영역을 누르면 왕관 미리보기와 결과 확인 팝업을 열며 팝업의 `확정`으로 저장한다. 취소·닫기는 선택을 취소하고 별도 인라인 결과 확정 버튼은 제공하지 않는다. 무승부는 `=`와 양 팀 강조, 무효·재경기는 회색 팀 영역과 회전 아이콘으로 표시하며 두 결과도 확인 팝업으로 저장한다. 무효는 전적·예측 보상에서 제외하며 다음 경기에서 재경기를 진행한다.
