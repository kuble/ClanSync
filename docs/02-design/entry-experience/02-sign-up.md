# 회원가입·이메일 확인 안내 상세 설계

작성일: 2026-10-24 · 상태: **2026-10-30 시각 개선 실제 적용 / 추가 필드·상태 개선은 후속**

관련: [공통 규칙](README.md) · [로그인](01-sign-in.md) · [게임 선택](04-game-select.md) · [게임 인증](05-game-auth.md) · [기존 명세](../../01-plan/pages/03-Sign-Up.md)

## 1. 목적과 경계

ClanSync 로그인 계정을 만든 뒤 게임을 고르고 게임 계정을 연결하도록 안내한다. 경로는 `/sign-up`이다. 게임 ID를 이 단계에서 받지 않고 공통 닉네임·클랜 정보·꾸미기를 추가로 요구하지 않는다.

출생연도 필수, 성별 선택·기본 비공개, 기존 비밀번호 정책과 필수 동의 범위를 유지한다. 입력 순서·정보 강조·피드백을 바꾸는 안이며 수집 항목·가입 연령·보호자 동의 정책을 확정하거나 개정하는 안이 아니다.

## 2. 화면 구성

```text
PC
[홈 로고]                                                     [테마]
      함께하게 되어 반갑습니다.       함께하는 플레이,
      계정을 만들고, 함께할 클랜을     함께 쌓아가는 기록.
      만나보세요.                    [실제 클랜 앨범의 예시 사진]

      이메일
      [you@example.com]
      비밀번호
      [비밀번호                           보기]
      영문·숫자·특수문자 모두 포함, 8~72자

      추가 정보
      출생연도 (필수)                  ← 작은 화면에서는 1열
      [선택]
      성별 (선택)
      ( ) 남성  ( ) 여성  (●) 비공개
      [기존 연령 관련 안내]

      [ ] 이용약관 및 개인정보 처리방침에 동의합니다. (필수)
          이용약관 보기 · 개인정보 처리방침 보기
      [공통 오류: 있을 때]
      [계정 만들기]
      이미 계정이 있으신가요? 로그인
```

- 로그인과 같은 400~440px 폼 폭을 사용한다. 큰 카드 안에 추가 정보 카드·동의 카드를 겹치지 않고 제목·간격으로 구분한다.
- 이메일 → 비밀번호 → 부가 정보 → 동의 → 제출 순서로 읽는다. PC에서도 출생연도와 성별을 억지로 좁은 한 줄에 압축하지 않는다.
- 폼은 헤더 아래에서 시작하고 내용 높이만큼 스크롤한다. 짧은 모바일 높이에서 맨 위와 제출 버튼에 모두 접근할 수 있어야 한다.
- `게임을 연결하면 게임별 ID로 활동해요.`는 부제 다음 보조 설명으로 한 번만 사용한다. 오버워치의 배틀태그 이름만 언급하는 기존 안내는 제거한다.
- 모바일/태블릿에서는 소개 장면을 숨기고 제목·입력·동의·제출의 순서를 유지한다.

## 3. 입력·검증 계약

| 입력 | 현재 계약 | 새 화면의 표시·동작 |
| --- | --- | --- |
| `email` | 이메일, 필수, 서버에서 정규화 | 이메일 자동완성, 예시 `you@example.com`, 오류를 라벨과 연결 |
| `password` | 영문·숫자·특수문자 포함 8~72자 | 새 비밀번호 자동완성, 기본 숨김, 한 줄 규칙 + 보기 토글 |
| `birth_year` | 1950년~현재 연도-10, 필수 | 기본 `선택`, 필수임을 텍스트로 표시, 고정 연도 배열로 문서화하지 않음 |
| `gender` | `male/female/undisclosed`, 누락·잘못된 값은 비공개 | 선택, 기본 비공개, 단일 선택 라디오 그룹 |
| `terms` | `on` 필수 | 현재 한 체크의 범위를 보존, 체크 자체와 문서 보기 링크 분리 |
| `next` | 안전한 내부 경로, 기본 `/games` | 숨김 값, 가입↔로그인 링크에서도 유지 |

클라이언트와 서버가 서로 다른 비밀번호·출생연도 기준을 쓰지 않는다. 검사 기준은 [인증 액션](../../../src/app/actions/auth.ts)과 [비밀번호 정책](../../../src/lib/auth/password-policy.ts)이다. 출생연도만으로 정확한 생일/만 나이를 확인한 것처럼 새로운 설명을 붙이지 않는다.

### 동의·문서 보기

- `이용약관 보기`·`개인정보 처리방침 보기`를 실제 읽을 수 있는 문서에 연결한다. 현행 라우트가 준비됐는지 확인한 뒤 구현한다.
- 문서를 보고 돌아와도 가입 초안이 유지되도록 별도 탭 열기를 기본안으로 삼고, 링크 이름에 새 탭 동작을 알린다. 링크 클릭이 동의 체크를 바꾸거나 폼을 제출하지 않게 한다.
- 문서를 열어봤다는 이유로 동의 체크를 자동 선택하지 않는다. 현재 필수 한 체크의 범위를 임의로 확대·분할하지 않는다.
- 기존 미성년 관련 안내는 조건과 문구를 실제 정책에 맞춰 확인한다. 새로운 보호자 확인·가입 차단 정책을 화면 작업 중 추가하지 않는다.

## 4. 상태별 화면과 문구

| 상태 | 표시·동작 | 다음 행동 |
| --- | --- | --- |
| 초기 | 빈 이메일/비밀번호, 출생연도 미선택, 성별 비공개, 동의 미체크 | 입력 |
| 필드 누락 | `이메일을 확인해 주세요.` / `출생연도를 선택해 주세요.` / 비밀번호 규칙 / `필수 동의를 확인해 주세요.` | 첫 오류에 초점, 각 필드에 설명 연결 |
| 제출 중 | 입력·선택 잠금, 버튼 `가입 중…` | 결과 대기, 중복 생성 차단 |
| 일반 가입 실패 | 현재 중립 오류 `가입하지 못했습니다. 이메일 주소를 확인하거나 잠시 후 다시 시도해 주세요.` | 같은 폼에서 수정·재시도 |
| 이미 존재하는 주소로 보일 수 있는 응답 | 실제 제공자/서버가 준 결과만 처리 | 임의 `이미 가입된 이메일` 사전 판정 금지. 항상 로그인 링크는 이용 가능 |
| 세션 발급 성공 | 별도 축하 모달 없음 | 안전한 `next` 또는 `/games` |
| 확인 메일 필요 | 아래 확인 안내로 같은 영역 전환 | 확인 후 로그인 |
| 계정 생성 후 프로필 준비 실패 | `계정은 만들어졌지만 프로필을 준비하지 못했어요.` 등 구분된 결과 | `로그인하기`로 기존 프로필 복구 경로 안내. 새 계정 생성 재시도를 기본으로 삼지 않음 |
| 통신 결과 불명 | 성공 여부를 추측하지 않고 중립 실패 안내 | 재시도/로그인 선택, 내부 오류값·인증정보 노출 금지 |

현재 결과 타입은 `error/ok` 문자열이다. 필드 오류·프로필 부분 성공을 확실히 분리하려면 결과 계약을 보완해야 한다. 문자열에 특정 단어가 들어 있다는 이유로 계정 생성 여부를 추측하는 구현은 하지 않는다.

## 5. 이메일 확인 안내

```text
[동일한 헤더·폼 폭]
이메일을 확인해 주세요
입력한 주소로 온 가입 안내 메일을 확인해 주세요.
확인을 마친 뒤 로그인하면 게임 계정을 연결할 수 있어요.
[로그인으로]
메일이 보이지 않으면 스팸함과 입력한 주소를 확인해 주세요.
```

- 현재 제공자가 실제 발송/전달 완료를 보장한 것이 아니라면 `메일 발송 완료`·`수신 완료`로 단정하지 않는다.
- 확인 안내에서 로그인 링크에도 `next`를 유지한다. 자동으로 인증을 완료하거나 대기 시간을 둔 뒤 게임 선택으로 이동하지 않는다.
- 이메일을 표시하려면 제출한 주소를 같은 폼의 상태로만 사용한다. 현재 `ok` 결과에 주소가 포함돼 있지 않으므로 표시용 계약 추가가 필요하다. 주소 표시가 없어도 위 안내는 완결돼야 한다.
- 재전송·이메일 변경 버튼은 실제 기능을 구현하기 전에는 표시하지 않는다. 브라우저의 외부 메일함을 대신 열거나 확인 링크를 새로 만드는 동작도 추가하지 않는다.
- QA의 임시 이메일/SMTP 여건 때문에 실제 수신 검증이 불가능한 경우, UI 분기 검증과 실제 메일 검증을 구분해 기록한다.

## 6. 이동·초안·제거 요소

- 기존 계정 로그인은 `/sign-in?next=...`로 이동한다. 가입이 이미 완료됐을 수 있는 실패에서는 재가입보다 로그인을 보조 행동으로 제공한다.
- 같은 폼의 오류에서는 이메일·출생연도·성별·동의 선택을 보존한다. 비밀번호는 메모리 내 상태만 유지하며 영구 저장·주소 전달을 하지 않는다.
- 로그인으로 경로를 바꾼 뒤 가입 초안이 모두 자동 복원된다고 약속하지 않는다. 약관 별도 탭 열기처럼 동일 폼을 유지하는 작업과 구분한다.
- 비밀번호 확인 칸, 별도 공통 닉네임, 게임 ID 입력, 추가 꾸미기, 강도 계기판, 마케팅 동의, 소셜 가입을 일괄 추가하지 않는다.
- 계정 생성 직후 세션은 기존 기본 24시간/자동 로그인 OFF를 유지한다. 로그인 화면의 자동 로그인 선택이 가입에 자동 적용된 것처럼 설명하지 않는다.

## 7. 구현 지점과 완료 조건

진입점: [페이지](../../../src/app/sign-up/page.tsx), [가입 폼](../../../src/app/sign-up/sign-up-form.tsx), [인증 셸](../../../src/components/entry/auth-shell.tsx), [액션](../../../src/app/actions/auth.ts).

1. 입력 순서·필수/선택 표현이 PC와 모바일에서 같고 현재 서버 검증과 맞는다.
2. 오류·요청 중·메일 확인·프로필 부분 성공에서 폼 영역이 불필요하게 전체 로딩으로 교체되지 않는다.
3. 비밀번호 보기·붙여넣기·자동완성이 가능하고 오류에 연결된 설명과 초점 순서가 올바르다.
4. 동의 문서가 실제로 열리고 초안을 잃지 않으며 링크 클릭만으로 체크/제출되지 않는다.
5. 세션 발급 여부에 따른 두 성공 분기, 로그인 왕복의 `next`, 잘못된 목적지의 기본 이동을 확인한다.
6. 응답 불명/부분 성공 뒤 이중 생성·잘못된 가입 완료 표시를 하지 않는다.
7. [온보딩](../../../e2e/onboarding.spec.ts)·[인증 회귀](../../../e2e/auth-performance.spec.ts)를 필요한 임시 데이터 시나리오로 검증한다. 기존 14계정·공유 QA 명단을 재생성하지 않는다.

## 8. 2026-10-30 시각 개선 적용

- 로그인과 같은 공용 인증 셸·초록색·폼 카드·클랜 앨범 장면을 사용한다. 이메일·비밀번호 다음에 출생연도와 성별을 배치하고, 480px 이하에서는 추가 정보도 한 열로 표시한다. 확인 메일 안내와 처리 중·오류도 같은 스타일을 사용한다.
- 입력 이름·수집 항목·비밀번호/연령 검증·필수 동의 문구·안전한 `next`·가입 액션은 유지한다. 약관 문서 링크·추가 필드 오류/초점·처리 중 입력 잠금 등의 제안은 아직 후속이며 이번에 적용됐다고 보지 않는다.
- [검증 결과](../../TODO_Phase2.md#2026-10-30-회원가입-시각-개선)를 기록했다. QA의 실제 메일 수신과 가입 성공 분기는 이번 시각 변경의 검증 범위에 포함하지 않는다.
