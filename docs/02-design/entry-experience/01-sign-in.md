# 로그인 상세 설계

작성일: 2026-10-24 · 상태: **검토용 상세 설계안 / 구현 전**

관련: [공통 규칙](README.md) · [회원가입](02-sign-up.md) · [게임 선택](04-game-select.md) · [기존 명세](../../01-plan/pages/02-Sign-In.md)

## 1. 목적과 진입

기존 사용자가 이메일·비밀번호로 계정에 들어가 원래 하던 활동을 이어간다. 경로는 `/sign-in`이며 보호된 링크에서 들어오면 검증된 `next`를 보존한다. 이미 로그인된 사용자는 현재 가드대로 유효한 목적지로 보낸다.

게임 인증은 [별도 화면](05-game-auth.md)이다. Battle.net/Riot의 ID·비밀번호를 이 폼에서 받거나, 이메일 로그인 대신 게임 연결 버튼을 표시하지 않는다.

## 2. 배치와 정확한 정보 순서

```text
PC 1024px 이상
[ClanSync 홈 로고]                                      [테마]
      [폼 최대440px]                 [작은 클랜 홈 대표 장면]
      로그인                        일정과 기록을 이어가세요.
      계정으로 활동을 이어가세요.
      이메일
      [이메일 입력]
      비밀번호
      [비밀번호 입력                         보기]
      자동 로그인                           [토글]
      약 30일 동안 유지돼요. 공용 PC에서는 꺼 주세요.
      [공통 오류: 있을 때만]
      [로그인]
      계정이 없으신가요? 회원가입

모바일/태블릿
[홈 로고] [테마]
[제목 → 동일한 폼 → 회원가입 링크]  ← 보조 장면은 숨김
```

- 공통 헤더 아래 48~72px 여백에서 시작한다. 짧은 PC 화면에서도 폼 상단이 잘리지 않게 자연스럽게 스크롤한다.
- 보조 장면은 폼보다 낮은 강조로 두고 한 문장만 사용한다. 장면 때문에 추가 로그인·가입 버튼을 만들지 않는다.
- 이메일과 비밀번호를 같은 정보군으로 묶고, 자동 로그인·제출·가입 링크는 순서대로 구분한다.
- 입력 설명과 오류는 해당 필드 아래에 둔다. 인증 공통 오류 영역은 자동 로그인 설명과 제출 버튼 사이에 둔다.
- 별도 비밀번호 찾기, Discord 로그인, 후기 인용, 구독 배너, 이용 통계는 추가하지 않는다.

## 3. 입력과 버튼 계약

| 요소 | 표시·기본값 | 제출/동작 |
| --- | --- | --- |
| 이메일 | 라벨 `이메일`, 예시 `you@example.com` | `email`, 필수, 이메일 자동완성. 값의 최종 검증은 기존 인증에 따름 |
| 비밀번호 | 라벨 `비밀번호`, 기본 숨김 | `password`, 필수, 현재 비밀번호 자동완성. 로그인 시 가입 강도 규칙을 새로 강제하지 않음 |
| 보기 버튼 | `비밀번호 보기` / `비밀번호 숨기기` | 제출하지 않고 표시 상태만 변경, 초점·입력 값 유지 |
| 자동 로그인 | 기본 OFF | `remember=on`일 때 약 30일, OFF는 기존 24시간 세션 기준 유지 |
| 목적지 | 숨김 값 | `next`, 기존 `safeNextPath` 검증 유지 |
| 제출 | `로그인` | 요청 중 `로그인 중…`, 중복 실행 차단 |
| 회원가입 | 보조 링크 `회원가입` | `/sign-up?next=<검증한 목적지>` |
| 홈 로고 | 접근성 이름 `ClanSync 홈` | 기존 랜딩 로고 경로, 비밀번호 초안은 경로 이동 뒤 복원하지 않음 |

토글은 필수 동의가 아니므로 체크박스로 바꾸지 않는다. 설정 변경만으로 로그인 요청을 보내지 않는다.

## 4. 상태·문구·초점

| 상태 | 표시와 가능한 행동 | 다음 전환 |
| --- | --- | --- |
| 최초 진입 | 기본 폼, 자동 로그인 OFF | 입력 → 제출 |
| 이메일 누락/형식 오류 | `이메일을 확인해 주세요.`를 입력 아래 연결 | 해당 입력으로 초점, 서버 요청 전 수정 |
| 비밀번호 누락 | `비밀번호를 입력해 주세요.` | 해당 입력으로 초점 |
| 요청 중 | 입력·토글·제출 잠금, 버튼 `로그인 중…` | 실제 응답까지 같은 폼 유지 |
| 자격 불일치/반복 실패 | 현재 공통 문구 `이메일 또는 비밀번호가 올바르지 않거나, 잠시 후 다시 시도해 주세요.` | 폼 공통 오류에 초점, 재시도 |
| 네트워크 실패 | `로그인하지 못했어요. 연결 상태를 확인한 뒤 다시 시도해 주세요.` | 입력·선택 유지, 재시도. 실제로 분류할 수 있을 때만 사용 |
| 설정/프로필 준비 실패 | `로그인 설정을 저장하지 못했습니다…` 등 서버의 구분 가능한 결과에 맞춘 공통 오류 | 인증 성공으로 임의 이동하지 않음. 부분 인증 상태 확인 후 복귀 규칙 적용 |
| 성공 | 별도 축하 화면 없이 이동 | 안전한 원래 목적지 또는 `/games` |
| 요청 중 세션 만료/계정 변경 | 이전 응답·민감 입력 폐기 | 새 세션 기준으로 재진입 |

현재 액션은 자격·잠금 오류를 통일하고 설정 저장/프로필 준비 오류를 따로 반환한다. 네트워크 분류·필드 오류 초점·요청 중 입력 잠금은 **새 UI 구현 사항**이며 이미 제공된 상태로 보지 않는다. 서버 오류의 내부 상세나 잠금 횟수·남은 시간은 화면에 새로 노출하지 않는다.

로그인 호출이 인증 세션을 만든 뒤 설정 저장에서 실패할 수 있으므로, 화면을 다시 읽었을 때 이미 로그인됐다고 즉시 성공 화면을 추측하지 않는다. 해당 부분 성공의 재시도/가드 동작은 구현 시 확인한다. 기존 보안을 약화하거나 잠금 정책을 바꾸는 해결은 범위 밖이다.

## 5. 이동·실패 후 값 보존

- 로그인↔회원가입 왕복은 `next`를 유지한다. 이메일 전달은 새 쿼리에 넣지 않고 기본적으로 빈 폼으로 시작한다.
- 같은 화면의 제출 실패는 이메일·자동 로그인 선택을 보존한다. 비밀번호는 같은 폼 메모리에만 남기며 로그·주소·영구 저장소에 기록하지 않는다.
- 원래 목적지가 게임 인증·클랜 소속을 요구하면 해당 가드가 이어서 판단한다. 성공을 무조건 클랜 홈으로 보내지 않는다.
- 새로고침·뒤로가기 후 인증 결과는 서버 세션으로 판단한다. 로그인 성공 후 뒤로가기로 폼에 와도 기존 로그인 사용자 가드를 유지한다.

## 6. 데이터와 변경 경계

현재 진입점은 [페이지](../../../src/app/sign-in/page.tsx), [폼](../../../src/app/sign-in/sign-in-form.tsx), [인증 액션](../../../src/app/actions/auth.ts), [비밀번호 입력](../../../src/components/entry/password-input.tsx), [목적지 검증](../../../src/lib/auth/safe-next-path.ts)이다.

기본 인증·세션 유지 규칙을 바꾸지 않고 셸·간격·문구·필드 오류·로딩 표현을 정리한다. 필드별 결과 분류를 추가한다면 액션 결과 타입과 보안상 통일해야 할 오류를 함께 검토한다. 소셜 로그인·비밀번호 복구·잠금 정책 개정은 별도 기능이다.

## 7. 완료 조건

1. 320px·가로가 짧은 화면에서 제목·입력·버튼이 잘리지 않고 보조 장면 없이도 이해된다.
2. 키보드로 이메일 → 비밀번호 → 보기 → 자동 로그인 → 로그인 → 회원가입 순서에 접근한다. Enter 제출·보기 토글이 서로 충돌하지 않는다.
3. 누락·인증 실패·서버 실패에서 오류가 보이고 이메일·선택이 유지되며 실패를 토스트에만 표시하지 않는다.
4. 요청 중 중복 제출을 막고 입력값과 실제 제출 데이터가 달라지지 않는다.
5. 자동 로그인 ON/OFF의 실제 세션 동작과 프로필 설정 기록이 유지된다.
6. 안전한 `next`, 잘못된 목적지, 가입 왕복, 로그인 후 재진입을 각각 확인한다.
7. [인증 회귀](../../../e2e/auth-performance.spec.ts)·[세션](../../../e2e/session-cookies.spec.ts)의 필요한 시나리오를 임시 데이터로 검증한다. 문서 작성만으로 실행 완료 표시하지 않는다.
