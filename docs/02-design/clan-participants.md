# 미가입 참가자와 계정 연결

2026-10-15 개정 요구: 가입 없이 닉네임만 등록해 반복 출전·기록 누적, 가입 승인 시 기존 기록 추천·검색·연결, 잘못된 연결 해제. 별칭 필수 입력과 별도 연결 링크 발급 절차는 새 화면에서 제거한다.

## 구현 경로

- 클랜 관리 → 구성원 → **미가입 참가자 기록**, 또는 내전 참가자 목록에서 닉네임만 입력해 추가한다. 같은 닉네임도 별도의 참가자로 등록할 수 있다.
- **가입 요청 → 가입 승인** 창은 신청자의 배틀태그 이름·#번호·성별·출생연도를 표시한다. 성별 비공개 선택은 그대로 표시한다. 첫 단계에서 **이전 기록 연결 / 연결 없이 가입** 중 하나를 선택한다. 선택 전에는 승인할 수 없고 후보 검색 목록도 표시하지 않는다.
- 비슷한 이전 이름이 있으면 연결 선택지에 **추천 기록 있음**을 표시한다. 대소문자·문자 폭·공백을 정규화한 이름 일치는 추천용이며 자동 선택·자동 연결하지 않는다. 배틀태그가 없는 기존 계정에는 태그를 지어내지 않는다.
- 연결을 선택하면 두 선택지를 숨기고 이전 닉네임 검색, 최근 참가일·경기 수·최근 3경기의 날짜/맵 목록만 보여주는 기록 선택 단계로 이동한다. 검색창에 포커스를 두며 하단 **이전**으로 연결 여부 선택 단계에 돌아간다. 돌아가면 검색·선택·오류를 초기화한다. 기록을 직접 선택해야 **연결 후 가입 승인**을 누를 수 있다. 선택한 기록 → 연결 계정을 하단에 표시하며 가입·연결은 같은 트랜잭션으로 처리한다. **연결 없이 가입**은 즉시 **가입 승인**을 활성화하고 기존 미가입 기록을 변경하지 않는다.
- 구성원의 **이전 기록 연결 / 연결된 기록 N**에서 가입 후에도 기록을 연결하거나 해제한다. 연결 해제는 확인 창에서 한 번 더 확인하며 별도 사유 입력을 강제하지 않는다. 처리자·시간과 처리 내용을 DB 이력에 남긴다.
- 기존 별칭·연결 요청·처리 이력은 삭제하거나 일괄 갱신하지 않는다. 기존 초대 링크의 본인 신청 API는 호환을 위해 남기되 새 화면은 가입 승인·구성원 관리로 통합한다.

## 기록과 권한

- 참가자 ID는 변하지 않는다. 기존 회원의 참가자 ID는 기존 user ID를 유지하여 원본 명단을 이관하지 않는다. 미가입 참가자에는 별도 UUID를 발급한다. 닉네임·별칭·프로필 이미지는 식별 키가 아니다.
- 원본 라운드/경기·평가 점수는 참가자 ID로 남기고 조회 모델에서 승인된 계정으로 연결한다. 연결/해제는 조회 모델을 같은 트랜잭션에서 다시 만든다. 코인·승부예측과 기존 역할은 변경하지 않는다. 가입 승인 작업만 기존 정원·인증·게임 소속 검사를 거쳐 일반 멤버십을 생성한다.
- 신규 편성은 활동 회원 또는 명부의 미가입 참가자를 선택한다. 연결된 참가자가 활동 회원이면 다음 내전부터 회원 항목을 사용한다. 연결 당시 진행 중인 내전에 참가했다면 종료 후 승인/취소한다.
- 같은 경기에서 이미 두 참가자로 출전한 기록이 있으면 연결을 거부한다. 자동으로 두 출전을 합치지 않는다. 운영진이 경기 기록을 정정한 뒤 다시 신청/승인한다.
- 별칭 필수 제약만 완화하며 닉네임 중복은 허용한다. 기존 별칭은 보존하고 새 입력·수정 화면에서는 닉네임만 편집한다. 동명이인 선택 화면은 최근 참가일·경기 수·최근 경기로 구분한다.
- 기존 기록 조회·연결·해제는 해당 클랜 운영진만 가능하다. 가입 승인 대상은 클라이언트가 보낸 사용자 ID 대신 해당 클랜의 대기 신청에서 결정한다. 이미 연결된 참가자·다른 클랜의 기록·동시 처리된 신청은 거부한다.
- OCR, 닉네임만으로 자동 연결, 임의 계정 생성, 자동 소유권 인정은 이번 범위에 포함하지 않는다.

## 배틀태그 이름과 계정 구분 (2026-10-15)

- 신규 홈페이지 가입에는 닉네임 입력이 없다. 연동 전 표시 이름은 `새 회원`이며 이메일 앞부분을 닉네임으로 노출하지 않는다. 오버워치 연동 시 `battle_tag`의 # 앞 이름을 표시 이름에 동기화한다. 동명 닉네임을 허용하며 관리 화면은 전체 태그도 표시·검색한다.
- `game_uid`는 제공자의 불변 계정 ID, `battle_tag`는 변경 가능한 표시 정보다. 전체 태그는 게임별 인증 계정에서 대소문자를 무시해 중복 연결을 막는다. 이름 변경·재연동도 사용자/참가자 ID와 경기·코인을 바꾸지 않는다.
- 태그·게임 인증은 서버만 기록하고 표시 이름의 직접 수정도 금지한다. 기존 QA 이름·레거시 UID는 일괄 변환하지 않는다. 실제 Battle.net OAuth는 미구현이며 현재 입력 폼은 개발·QA 시뮬레이터에서만 제공한다. 운영 환경에는 이 수동 인증 경로를 노출하지 않는다.
