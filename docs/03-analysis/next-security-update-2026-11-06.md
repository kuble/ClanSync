# Next.js 보안 업데이트·호환성 확인

2026-11-06 작업 브랜치 기준. Next.js와 전용 ESLint 설정을 `16.2.0`에서 `16.4.5`로 고정 업데이트했다. 운영 DB 적용·실제 배포·Git 연결 변경은 실행하지 않는다.

## 영향과 버전 선택

- [공식 11월 보안 수정 공지](https://nextjs.org/blog/november-2026-security-release), [16 버전 업그레이드 안내](https://nextjs.org/docs/app/guides/upgrading/version-16), npm 배포 메타데이터를 대조했다. `16.4.5`는 확인 시점의 안정 배포본이며 canary를 사용하지 않는다.
- 이전 npm 감사에서 `next`는 직접 보안 권고 34건과 연결됐다. 이는 버전 범위 대조 결과이며, 프로젝트에서 각 공격의 성공을 재현했다는 뜻은 아니다. 업데이트 후 npm 감사에서 `next` 항목은 없어졌다.
- App Router·Server Actions·Proxy·이미지 최적화를 사용하는 프로젝트이므로 관련 보안 수정은 적용 대상 검토 범위다. [Proxy 우회 권고](https://github.com/vercel/next.js/security/advisories/GHSA-26hh-7cqf-hhc6)와 [이미지 최적화 라이브러리 권고](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw)를 확인했다. Next가 실제 해석하는 `sharp`는 `0.35.5`, libvips는 `8.18.7`이다.
- Cache Components·`use cache`·Edge Route Handler·`next/og`의 사용은 현재 소스에서 발견하지 못했다. 이번 작업에서 새 캐시·런타임·실험 기능을 활성화하지 않았다.
- 배포 메타데이터의 Node 요구 사항은 `>=20.9.0`이며 검증 호스트는 `24.14.0`이다. 기존 React/React DOM `19.2.4`, TypeScript `5.9.3`, ESLint `9.39.4`는 호환 범위여서 유지했다. 이미 Next 16이므로 이전 메이저 버전용 codemod는 실행하지 않았다.

## 호환성 수정

- 설치된 `error.md`와 `ErrorInfo` 타입에서 `retry`가 16.3부터 안정화된 것을 확인하고 게시판 오류 경계의 `unstable_retry`를 변경했다. 서버 데이터를 다시 읽는 복구 동작을 유지한다.
- 새 React Hooks 린트 규칙에 맞춰 알림의 미읽음 수 변경 시 배지 초기화를 렌더 단계의 조건부 상태 보정으로 옮겼다. HoF 댓글은 최초 로딩 상태를 유지하고 수동 갱신 이벤트에서 로딩·오류 상태를 초기화한다. 요청 취소·범위별 상태 분리·응답 처리는 유지한다.
- 새 Next 린트 안내에 맞춰 클랜 생성 후 환영 페이지 이동을 `router.push`·`router.refresh`로 바꿨다. 새 소속을 재조회하고 기존 저장·사진 처리·실패 시 복구 흐름을 유지한다.
- 첫 프로덕션 회귀에서 가입 안내 2건이 실패했다. 네트워크·DOM 추적에서 가입 완료 이후 문서 전체 재로드와 토스트 소실을 확인했다. 가입 액션은 이미 현재 경로를 `revalidatePath`로 갱신하므로 성공 직후의 중복 `router.refresh`를 제거했다. 진단 검사에서는 전체 재로드 없이 토스트가 표시되고 대기·취소까지 통과했다. 가입·교체 액션의 권한 검사·DB 저장·재검증은 유지한다.
- 기존 테스트·실행 명령·DB 분리·운영 전 `test:all` 범위는 변경하지 않는다. 앞서 중단한 전체 회귀를 반복하는 대신 프레임워크와 호환성 수정에 관련된 검사를 선택한다.

## 남은 보안 범위

전체 npm 감사는 39개에서 36개로 줄었으며 2 critical·15 high·17 moderate·2 low가 남는다. 전체 보안 문제가 해소된 상태가 아니다. 루트 `sharp@0.34.5`의 업로드 처리, `shadcn` 도구 의존성, `proxy-addr`, Supabase CLI의 `tar`, 린트 도구 의존성은 별도 영향 확인·호환성 검증이 필요하다. 이번에는 관련 없는 패키지의 강제 업데이트·다운그레이드나 `audit fix --force`를 실행하지 않았다.

후속 사용자 요청으로 이 잔여 범위를 별도 검토·업데이트했다. 현재는 치명·높음·중간 0·낮음 3이며, 위 36건은 Next 단독 갱신 직후의 이력이다. [후속 영향·버전·검증 및 수정판 없는 잔여 항목](../TODO_Phase2.md#2026-11-06-잔여-의존성-보안-업데이트)을 참조한다.

## 검증

- 전체 린트 오류·경고 0, 타입 검사 통과.
- 서버·DB 없는 로직 113개와 검사 실행기 3개 통과.
- 첫 관련 프로덕션 E2E는 17개 중 15 통과·가입 안내 2 실패였다. 실행 ID: `2026-11-06T09-47-54-800Z-226e0d68`. 기존 단언을 유지한 임시 진단 검사는 수정 전 실패(`2026-11-06T09-53-33-627Z-bd9843bd`), 중복 갱신 제거 후 통과(`2026-11-06T09-56-13-704Z-3268155f`)했다. 실제 프로덕션 빌드를 포함하며 실행 후 전용 임시 데이터를 정리한다. 최종 원본 시나리오 재검증 결과는 아래에 기록한다.
- 최종 원본 가입·홍보·문의 4개는 모두 통과했다(`2026-11-06T09-58-10-118Z-4046a6e1`). 앞선 15개와 최종 결과를 대조해 관련 프로덕션 시나리오 17개 모두 확인했다. 별도의 전체 DB 회귀·전체 브라우저 회귀를 실행한 것으로 집계하지 않는다. 각 프로덕션 실행에 빌드가 포함됐으며 임시 진단 파일은 제거했다.
- 모든 실행 뒤 전용 데이터 정리를 확인했다. 최종 계정·클랜·경기는 각각 0건이다. npm 감사 전후 JSON은 최종 실행의 `artifacts/npm-audit-before.json`, `artifacts/npm-audit-after.json`에 보관했다.
- 스키마·권한/RLS·정산 SQL은 변경하지 않는다. 사용자의 3011 QA 계정·내전 기록을 검사에 재사용하지 않는다.
- 기존 3011 QA 서버는 중지·재시작하지 않았다. 새 버전의 실행 확인은 별도 3010 검사 서버에서 수행하며 운영 서비스 반영 완료를 뜻하지 않는다.
- 마이그레이션·기존 QA/운영 연결·배포·검증 설정 243개의 해시는 변경 전과 같다. 검사 전용 `.env.test-local`은 기존 실행기가 생성하며 로컬 전용 연결 가드를 유지한다. 테스트 시나리오·명령·운영 반영 전 전체 검증 범위는 축소하지 않았다.
