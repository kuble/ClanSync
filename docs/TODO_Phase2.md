## 2026-10-16 디자인 불일치 6항목

일정 등록·편집을 고정 헤더/하단 작업과 본문 스크롤의 우측 패널로 통일했다. 날짜 입력·캘린더 날짜 구분·상세 표시는 한국 시간이며 UTC 저장과 매주/매월 반복 규칙을 유지한다. 일정·통계 토글 정렬, 구독 카드, 로비 생성 버튼과 부가 정보 크기·모바일 행 배치도 정리했다. [점검 보드와 검증 범위](03-analysis/alpha-review-2026-10-16/README.md)에 D1–D6을 완료로 갱신했다.

## 2026-10-16 알파 성능·운영 점검

로비는 기존 publication·RLS 아래 방/예약/참석 변경을 구독하고 120ms로 합친다. 전체 조회는 30초 보완, 숨김·오프라인 중단과 복귀 재조회로 정리했다. 경기 설정/안내는 지연 로딩, 클랜 표시 점은 LIMIT 1을 사용한다. QA 프로덕션 빌드·집중 E2E 5건과 타입/린트를 확인했다. 측정 방법·반례·디자인 제안과 화면 링크·OCR 및 1개 클랜/100명 알파 손익은 [별도 보고서](03-analysis/alpha-review-2026-10-16/README.md)에 둔다. 운영 DB·배포·상시 워커 연결은 실행하지 않았다.

## 2026-10-16 예약 내전 자동 생성

- `내전 자동 종료`로 표기를 바꾸고 `예약된 내전 자동 생성` 토글과 들여쓴 분 입력을 추가했다. 기본 On·10분 전이며 1~1,440분을 자동 저장한다. Off는 예약 시각이 지나도 자동으로 열지 않으며 수동 열기는 유지한다([기준](02-design/session-lobby.md#3-예약반복참여-응답)).
- 후속 UI는 두 카드 아래 저장 상태 하나를 공유한다. 한 설정의 실패나 진행 중 저장을 다른 설정의 완료로 덮지 않으며 재시도는 실패 항목만 처리한다. Off의 빈 하단 여백과 도움말 기본값 문장을 제거하고 공통 카드·제목·들여쓰기와 맞췄다. 신규 클랜의 두 토글은 DB 기본 On을 사용하며 기존 클랜의 선택은 유지한다. 집중 E2E 3건·린트·타입과 320/390px를 확인했다.
- QA에 `20261016010956_balance_room_automatic_open.sql` 적용·타입 동기화. 기존 분 단위 워커는 클랜별 사용 여부·선행 시간을 반영하며, 검증 호출은 임시 클랜만 처리한다. 권한·범위·동시 워커·중복 방/경기 방지·참석 투표 마감, 저장·오류·Off/On 선택 복원과 320/390px를 확인했다. 관련 E2E 11건·방 DB 9건·린트/타입·빌드 통과. 보안 진단은 기존 28건으로 새 경고가 없다. 운영 DB/배포 보류.

## 2026-10-16 내전 생성·참석 투표 예약

- 생성 창을 공통 설정 카드·제목 툴팁·하단 고정 버튼·모바일 전체 너비로 정리했다. 날짜 휠은 분 단위이며 초·조작 안내·요약 문장을 제거했다. 깜짝 예약의 참석 투표 자동 개설은 날짜·시각으로 지정하고 이벤트의 공개 참석/불참 투표와 로비 참여 현황을 함께 갱신한다([기준](02-design/session-lobby.md#3-예약반복참여-응답)).
- QA에 `20261016010532_balance_room_attendance_polls.sql`을 적용하고 타입을 동기화했다. 개설 전/마감 후 차단·방 권한·동시 선택·토글 복원·예약 변경/취소·조기 개장·출전 명단 분리를 확인했다. 기존 일수 기반 QA 예약은 보존하며 신규 투표만 방과 연결한다.
- 관련 E2E 11건(예약 자동 생성 포함)과 기존 방 DB 9건, 린트·타입·프로덕션 빌드 통과. 화면 검증은 프로덕션 서버와 후속 Webpack 서버에서 수행하고 320/390/1304px 배치를 확인했다. 보안 advisor는 기존 28건이며 새 경고는 없다. 공유 QA 시드·운영 DB·배포는 수행하지 않았다.

## 2026-10-16 Discord 내전 알림 구분

- 내전 카드의 구분 줄에 정규/깜짝 내전을 표시한다. 발송 직전 현재 방 정보를 조회해 열린 방은 시작·진행 중, 예약은 시작 예정 시각과 실제 남은 분으로 안내한다. 갤러리·설정 설명도 같은 기준으로 정리했다([기준](guides/discord-bot-setup.md#종류별-발송)).
- 격리 QA의 두 종류×예약/즉시 방 모의 발송, 기존 라우팅·설정/모바일 갤러리 3건과 카드·시간·링크/길이 단위 검사 4건, 린트·타입 검사를 통과했다. 오래된 공지 링크 기대값은 현재 상세 경로로 갱신했다. 실제 외부 발송·전체 빌드·운영 배포는 수행하지 않았으며 기존 QA 명단·DB 스키마를 보존했다.

## 2026-10-16 깜짝 내전 설정·미리보기

- 깜짝 내전에서는 선수 카드 점수·팀 비교·예측 승률·관전자 승부예측 설정을 숨긴다. 예시 카드와 상세 정보에서도 점수를 제외하고, 편성·경기 안내와 종료 설명을 실제 동작에 맞췄다. 세션 전적·맵 투표·영웅 밴·전략 아이템은 유지한다([기준](02-design/formation-modes.md#실제-페이지-적용-범위-2026-09-16)).
- 멤버 호스트·클랜장 양쪽의 실제 점수 응답 차단·미리보기·툴팁·설정 저장·경기 안내와 320/390px 배치를 격리 UI 회귀로 확인했다. 정규 내전 미리보기 2건·깜짝 내전 전략 아이템 1건을 포함해 4건, 린트·타입 검사·프로덕션 빌드 통과. 기존 QA 명단·스키마·운영 배포는 변경하지 않았다.

## 2026-10-16 Discord 알림 하위 설정 표시

- 전체 사용 토글을 `Discord 알림 사용` 제목 오른쪽으로 옮겼다. 켠 경우에만 기본 채널과 종류별 알림을 들여쓰기·연결선·배경으로 묶어 표시하며, 끌 때 선택값을 보존한다([설정](guides/discord-bot-setup.md#공용-앱과-연결)).
- 변경 파일 린트·타입 검사와 격리 UI 회귀 1건을 통과했다. Off 저장/재진입·On 복원·채널/종류별 선택 보존·운영진 읽기/멤버 접근 차단·390px 배치와 갤러리를 검증하고 실제 QA 화면을 확인했다. UI 검증은 별도 Webpack 서버에서 수행했으며 기존 QA 설정·DB 스키마·운영 배포는 변경하지 않았다.

## 2026-10-16 클랜 구성원 최근 활동 갱신

- 클랜 방문 RPC가 방문일만 기록하고 `last_activity_at`을 갱신하지 않아 가입일 기준으로 비활성 처리되던 누락을 수정했다. 현재 열람자는 첫 화면부터 활성으로 표시하고 기존 방문 기록으로 활동 시각을 보완한다. 과거 일자의 입력 시각은 해당 KST 일자 말일로 제한하며 탈퇴·강퇴자는 갱신하지 않는다.
- QA 마이그레이션·공개 타입 동일 확인, 린트·타입·빌드, 격리 활동/계정 분리 회귀 4건과 탈퇴·재가입 DB 6건을 통과했다. 본인만 갱신·익명/타 클랜/탈퇴/강퇴 차단·5분 간격·당일 중복 방지와 실제 QA 새벽별 활성 표시를 확인했다. 기존 QA 명단 보존·운영 DB/배포 보류.

## 2026-10-16 클랜 탈퇴·재가입과 이전 구성원

- 프로필의 내 클랜에서 자진 탈퇴하며 구성원 관리를 현재/이전으로 분리한다. 이전 구성원도 개인 기록 링크를 유지하고 최근 탈퇴·강퇴일과 재가입 차단/허용을 표시한다. 같은 계정의 신청은 기록 선택 없이 기존 참가자·멤버십을 재사용하여 승인하고 일반 멤버로 복귀한다([정책](02-design/clan-participants.md#탈퇴강퇴와-같은-계정의-재가입-2026-10-16)).
- 강퇴 시 대기 신청을 취소하고 DB에서도 재신청·승인을 차단한다. 운영진의 재가입 허용은 차단만 해제하며 본인 신청과 승인이 필요하다. 클랜장 탈퇴, 진행 중 출전자와 예정/진행 깜짝 내전 호스트의 탈퇴·강퇴는 정리 전 차단한다. 기존 권한·정원·게임 인증·게임별 소속 제약을 유지한다.
- QA에 `20261015170527_clan_membership_returning_members.sql` 적용 후 공개 타입을 동기화했다. 기존 QA 행·탈퇴일을 일괄 갱신하거나 시드하지 않았다. 별도 임시 계정·클랜에서 DB 6건과 기존 권한/승인 DB 9건, 집중 UI 1건과 기존 기록 연결/온보딩 3건을 통과했다. 원본 기록·점수·코인 보존, 같은 계정의 이름 변경 후 복귀, 중복 승인, 직접 API 차단, 운영진 역할 미복원, 차단 해제 후 재신청·승인과 390px 화면을 확인했다.
- 변경 소스 ESLint·타입 검사·Webpack 프로덕션 빌드 통과. QA DB 보안 advisor 경고는 기존 28건이며 새 소속 변경 함수의 지적은 없었다. 임시 검증 데이터는 정리했다. 전체 회귀·운영 DB·배포는 미실행이다.

## 2026-10-16 내전별 전략 아이템 구성

- 주장 선택을 2열로 배치하고 전략 아이템을 켜면 좌측 구성 화면을 연다. 모바일에서는 설정 패널 안에 배치한다. 클랜 공통 카탈로그 편집은 클랜 관리에서 정규 내전의 경기 설정으로 옮겼다.
- 깜짝 내전 호스트는 기본 아이템을 선택해서 쓰고 해당 방 전용 아이템을 추가·수정·삭제한다. 기본 내용·가격은 읽기 전용이다. 전용 구성은 설정 적용 시 저장하고 같은 방의 다음 경기로 이어진다. 다른 방과 분리하고 편성 시작 뒤에는 잠근다([기준](02-design/formation-modes.md#실제-페이지-적용-범위-2026-09-16)).
- QA에 `20261015163412_balance_round_auction_catalog.sql`을 적용하고 타입이 기존 공개 타입과 동일함을 확인했다. 기존 QA 행을 갱신하거나 시드하지 않았다. DB는 malformed/중복/가격/개수/기본 ID 충돌·정규 전용 항목 위조·비호스트/외부/탈퇴 계정·stale revision·시작 후 잠금·다음 경기 상속을 검증했다.
- 변경 소스 ESLint·타입 검사·Webpack 프로덕션 빌드, 집중 편성 로직/UI 32건과 관련 DB 11건 통과. 실제 편성 시작에서 선택한 기본/전용 아이템과 가격이 반영되고 제외 항목은 추첨되지 않는 것을 확인했다. 기존 미리보기 회귀의 누락된 팀 조정 단계를 기대값에 반영했다. QA 브라우저와 390/1244px 배치도 확인했다. DB advisor의 아이템 관련 신규 지적은 없었다. 전체 회귀·운영 DB·배포는 미실행이다.

## 2026-10-16 경기 설정 도움말·좌측 미리보기

- 경매 아이템 목록의 사용 상태를 공통 디자인의 토글로 바꾸고 하단 안내 문구를 제거했다. 저장·실패·중복 입력 차단은 기존 액션 흐름을 유지한다.
- 경기 설정의 편성·화면 표시·밴픽 미리보기는 840px부터 좌측 공간을 사용하고 더 작은 화면에서는 패널 안에 배치한다. 정적인 옵션·미리보기 설명을 제목의 우측 우선·충돌 회피 툴팁으로 옮겼다. 키보드로 포커스한 도움말에서 Escape를 누르면 설정창·초안을 유지하고 도움말만 닫는다. 잠금·동시 수정·투표 초기화 경고는 유지한다([기준](02-design/formation-modes.md#실제-페이지-적용-범위-2026-09-16)).
- 선수 카드와 상세 정보의 마이크 표시를 제거했다. 기록·승률·점수와 원본 데이터는 유지한다. 기존 실제 내전 회귀의 기대 문구도 변경했다.
- 변경 소스 ESLint·타입 검사와 격리 UI 회귀 2건(경매 토글 저장·새로고침, 설정 초안/저장·툴팁·Escape·마이크 미표시·840/1054/1244px 좌측 배치·320/390px 모바일)을 통과했다. 실제 QA 브라우저에서도 확인했다. 테스트는 별도 Webpack 서버에서 실행했고 시드·기존 QA 데이터 변경·DB 스키마 적용·전체 회귀·빌드·배포는 하지 않았다.

## 2026-10-16 구성원 작업 아이콘과 미가입 명부 정리

- 구성원 행의 기록 연결·승격·강등·강퇴와 참가자 추가·닉네임 수정을 아이콘으로 통일했다. 접근성 이름·마우스 설명·기존 확인과 권한 처리는 유지한다. 연결된 기록은 미가입 목록에서 제외하고 구성원 쪽에서 관리하며 해제하면 목록에 복귀한다. 명부에서 불필요해진 연결 계정 정보 조회도 제거했다([정책](02-design/clan-participants.md#구현-경로)).
- 변경 소스 ESLint·타입 검사와 격리 승인/연결/해제 회귀 1건을 통과했다. 아이콘의 접근성 이름·편집 창 진입, 연결 후 검색 제외·해제 후 복귀·재연결 후 제외와 390px 화면을 확인했다. 실제 QA 브라우저에서도 아이콘과 기존 연결 관리 진입을 확인했다. 검증은 기존 Turbopack 작업자 오류를 피한 별도 Webpack 서버에서 실행했고 기존 QA 명단·운영 DB·배포는 변경하지 않았다.

## 2026-10-16 클랜 관리 메뉴 재배치

- 구성원 관리의 항목을 구성원 → 가입 요청으로 정렬하고 분류 첫 진입도 구성원으로 연결한다. 운영 통계는 클랜 운영의 클랜 꾸미기 다음으로 옮긴다. 기존 `?tab=` 주소와 서버 권한 검사는 유지한다([배치](01-plan/pages/12-Clan-Manage.md#사용자-흐름)).
- 변경 소스 ESLint·타입 검사와 격리 관리 회귀 1건(메뉴 순서·분류·뒤로 가기·새로고침·모바일·운영진/멤버 권한)을 통과했다. 실제 QA 브라우저에서도 확인했다. 테스트 서버의 Turbopack CSS 작업자 오류로 해당 실행만 Webpack을 사용했고, 닫히는 툴팁을 제외하도록 테스트 선택자를 보정했다. 기존 QA 명단·운영 DB·배포는 변경하지 않았다.

## 2026-10-15 가입 승인 선택과 플레이어 기본 정보

- 후속 UI 조정: ‘이전 기록 연결’을 누르면 선택지 두 개를 숨기고 검색·기록 목록만 표시한다. 검색에 포커스를 두고 ‘취소’ 대신 ‘이전’으로 선택 단계에 돌아가며 검색·선택·오류를 초기화한다. 집중 가입 승인/연결/해제 E2E 1건, 변경 소스 ESLint·타입 검사와 실제 브라우저의 단계 이동을 확인했다.
- 가입 승인 창에서 먼저 ‘이전 기록 연결 / 연결 없이 가입’을 명시적으로 선택한다. 선택 전에는 승인할 수 없고 검색·후보 목록은 숨긴다. 비슷한 이전 이름이 있으면 연결 선택지에 추천 배지를 표시한다. 연결은 기록을 지정해야 승인할 수 있고, 연결 없이 가입은 즉시 승인 가능하다. 방식 변경은 검색·선택을 초기화하며 기존 승인·연결 트랜잭션은 유지한다.
- 개인 기록 배너는 해당 게임의 전체 배틀태그를 우선 표시하고 성별·출생연도를 함께 표시한다. 신청 카드·승인 창에도 같은 기본 정보를 제공한다. 성별 비공개는 그대로 유지하고, 태그가 없는 기존 계정은 기존 이름과 미등록 상태를 표시한다. 미가입자의 기본 정보는 추정하지 않는다.
- 전체·초기·상세 통계 조회는 기존 개인 기록 열람 권한으로 허용된 대상 ID만 서버에서 조회한다. 이메일을 조회·전달하지 않으며 다른 클랜·권한 미달 대상의 정보는 반환하지 않는다. DB 스키마·기존 QA 명단·기록·코인은 변경하지 않았다.
- 최종 빌드와 격리 E2E 6건(관리 2·가입 승인/연결/해제/동시성 2·통계 필터 1·게임별 태그/기본 정보/권한 1), 변경 소스 ESLint·타입 검사 통과. 실제 브라우저에서 두 선택지와 승인 활성화 조건·시연 계정 배너를 확인했다. 기간 키보드 회귀는 앞선 휠/호버의 간섭을 제거하고 팝업·첫 옵션 포커스를 기다리도록 보정했다. 시드·운영 DB 적용·수동 배포·전체 회귀는 실행하지 않았다.

## 2026-10-15 배틀태그 이름과 가입 승인 디자인

- 신규 가입의 닉네임 입력·검증·메타데이터를 제거했다. 연동 전에는 이메일 앞부분 대신 `새 회원`을 사용하고 오버워치 연결 후 전체 배틀태그의 이름을 동기화한다. 표시 이름 중복은 허용하고 전체 태그는 게임별 대소문자 무시 중복을 차단한다. 태그와 불변 제공자 ID를 분리하며 재연동·이름 변경은 ID·경기·코인을 유지한다. [정책](02-design/clan-participants.md#배틀태그-이름과-계정-구분-2026-10-15).
- 가입 승인 창은 배틀태그 이름·#번호, 이전 기록 검색·선택, 연결 결과와 승인 순서로 정리했다. 연결하지 않을 때는 ‘가입 승인’, 선택하면 ‘연결 후 가입 승인’으로 구분한다. 해제 화면은 분리되는 기록과 유지되는 가입 후 기록·코인을 안내한다. 구성원의 전체 태그 표시·검색과 연결된 기록의 계정 정보도 통일했다.
- 가입 오류의 입력값을 유지하고 이메일 확인이 필요한 경우 안내 화면을 제공한다. QA에는 별도 SMTP가 없어 실제 확인 메일 수신은 미검증이다. 새 Auth 계정은 관리자 API로 테스트 범위 안에서만 생성하며 전역 이메일 확인 정책·기존 QA 계정은 변경하지 않는다. 실제 Battle.net OAuth와 운영 적용은 후속이다.
- 검증: 최종 빌드와 가입 폼 오류/입력 유지·새 프로필 이름·동명 태그·대소문자 중복 거부·재연동 ID 유지·로그인/잠금 회귀 6건 통과. 승인/연결/해제·원자성/권한 회귀 2건, 기존 참가자 3건·클랜 관리 2건·격리 온보딩 1건도 통과했다. 관련 DB 권한/정산 회귀 9건, ESLint·타입 검사 통과. QA 보안 진단 28건은 기존 경고이며 새 이름 동기화 관련 지적은 없다. 390px 기록 관리와 실제 브라우저 승인/가입 화면을 확인했다.

## 2026-10-15 가입 승인과 기존 기록 연결 통합

- 미가입 참가자 추가·수정은 닉네임만 입력한다. 닉네임 중복을 허용하고 기존 별칭·원본 기록은 보존한다. 별도 별칭·연결 링크 발급·요청 처리 화면은 가입 승인과 구성원 화면으로 통합했다.
- 가입 승인 창은 신청자의 닉네임·등록된 배틀태그로 후보를 추천하며 자동 선택하지 않는다. 이전 닉네임 검색, 경기 수·최근 참가일·최근 3경기 날짜/맵으로 기록을 확인한다. 기록 연결과 가입 승인은 같은 트랜잭션이며, 후보가 이미 처리되었거나 연결이 실패하면 가입도 되돌린다. 새 참가자로 승인하면 기존 미가입 기록은 그대로 둔다.
- 구성원의 이전 기록 관리에서 가입 후 연결·해제를 지원한다. 해제는 원본 귀속을 복원하고 가입 상태·가입 후 경기·코인을 유지한다. 사유 입력은 강제하지 않되 처리자·시각·처리 내용을 감사 이력에 남긴다. 이전 초대 링크 API와 이력은 호환 보존한다([설계](02-design/clan-participants.md)).
- QA에 `db:test:push` → `db:test:types` 적용·타입 동기화. 최종 프로덕션 빌드와 격리 E2E **8건**(추천/검색·연결/해제/재연결, 중복/동시 승인·실패 시 가입 롤백, 기존 연결/원본/평가 점수, 내전 전체 흐름, 관리 권한, 통계 정합성), DB 가입·권한 회귀 **9개 검사**, 변경 소스 ESLint·타입 검사 통과. 모바일 넘침과 신청일 시간대의 hydration 오류도 확인·보정했다. QA 보안 진단 28건 중 새 참가자 함수 관련 지적은 없다. 모든 쓰기 검증은 별도 임시 클랜/계정으로 수행하고 정리했으며 시드·기존 QA 명단 변경·운영 DB 적용·수동 배포·전체 회귀는 실행하지 않았다.

## 2026-10-15 미가입 참가자와 계정 연결

- QA에 클랜별 참가자 명부·별칭·본인 연결 신청·운영진 승인/거절/취소와 처리 이력을 적용했다. 기존 회원 ID는 유지하고 미가입자만 별도 참가자 UUID를 발급한다. 명부/내전에서 같은 참가자를 반복 선택하며 이메일·가짜 로그인 계정은 만들지 않는다. 동명이인은 별칭으로 구분하고 신청자 계정 구분 코드를 본인과 운영진에게 동일하게 표시한다.
- 운영진이 발급한 30일 링크에서 로그인한 본인이 신청한다. 클랜 가입은 신청 조건이 아니며 계정 연결은 가입·역할·게임 인증·코인 권한을 부여하지 않는다. 새 링크는 이전 링크를 무효화하고 승인 시 폐기한다. 같은 경기의 두 출전을 한 계정으로 합치는 연결과 진행 중 내전의 신원 변경은 거부한다. [정책·사용 경로](02-design/clan-participants.md).
- 원본 라운드/경기·점수와 경제 기록을 변경하지 않고 통계 조회 모델을 승인/취소 트랜잭션에서 갱신한다. 연결 상태에서 경기 내용을 정정한 뒤 취소해도 미가입 기록의 귀속을 복원한다. 과거 내전 통계·분석 관측·최근 평가 점수/참여순도 연결 계정을 따른다. 연결된 참가자의 자기 경기 승부예측은 차단한다.
- 최종 프로덕션 빌드와 격리 E2E **5건**(새 시나리오 3건·기존 내전 전체 흐름·통계 조회 모델) 통과. 별도 구성원/기록 정정/명단 회귀 3건, 세션·코인 풀 DB 회귀와 편성 DB 9개 검사, 변경 소스 ESLint·타입 검사도 통과했다. 모바일 명부를 실제 렌더로 확인했다. QA 보안 진단에서 새 참가자 관련 지적은 없었다.
- `db:test:push` → `db:test:types`로 QA만 적용·타입 동기화했다. 테스트는 `E2E_SKIP_SEED=1`과 실행마다 임시 클랜/사용자를 사용하고 정리했다. 기존 QA 명단·경기·코인을 초기화하지 않았다. 전체 회귀와 운영 DB·배포는 수행하지 않았다.

## 2026-10-15 구성원 인증 표시와 개인 기록 연결

- 구성원 목록은 이메일을 조회·전달·검색·표시하지 않는다. 해당 클랜 게임의 인증 여부를 표시하고 닉네임은 `stats?player=` 개인 기록으로 연결한다. 직접 링크는 기존 개인 기록 열람 범위에서만 대상을 선택하며 잘못된 대상은 허용된 목록으로 돌아간다. 구성원별 통계 자동 프리페치는 끈다.
- 변경 소스 ESLint·타입 검사와 격리 구성원/통계 회귀 2건 통과. 인증 완료·미인증·프로필 없음·다른 게임만 인증, 이메일의 HTML/화면/검색 제외, 새로고침·개인 기록 직접 이동·권한 제한·모바일을 확인했다. 통계 부문/기간의 좌측 정렬과 320px 넘침도 보정·검증했다. 전체 빌드·전체 회귀는 실행하지 않았다.

## 2026-10-15 연도·월 팝업 선택기 통일

- 필터 아래 중복 합계와 경기 기록 도움말·당일 표 설명을 제거하고 경기 설정의 `밴픽` 탭을 `경기 구성`으로 변경했다. 집중 Playwright 1건에서 번개 제외 누적 회차·고유 출전·자정 이후 활성 시간·필터 유지·세 탭 저장·등재 경계·390px 넘침을 확인했다. 변경 파일 ESLint·타입 통과, 전체 회귀·빌드·DB 스키마 변경 없이 임시 픽스처만 정리했다. 사용자 QA 데이터·운영 DB·배포는 보존한다.

- ESLint·TypeScript·집중 E2E 4건 통과. 팝업 선택/닫힘·배너 이미지·부착/높이·명단 드래그/저장·분석 갱신·사전 선택 유지·팀 정렬·모바일을 확인했다. 테스트 서버의 방 생성/단계 갱신 대기를 보완했으며 사용자 QA 명단·DB 스키마·운영 배포 변경 없음.

## 2026-10-09 중앙 팀 비교 그래프

- 편성 화면의 중앙 VS를 평가/분석 점수 합계 그래프로 바꿨다. `화면 표시 > 팀 비교 그래프`에서 합계 또는 Premium 정규 내전의 예측 승률을 선택하며 기존 점수 토글·선수 교체에 따라 갱신한다. 설정은 편성 이후에도 결과 초기화 없이 저장한다. 미완성 명단·미등록 점수·실제 모델 미연결을 구분하고 QA 승률의 샘플 표시를 유지한다.
- 변경 파일 ESLint·TypeScript·빌드, 집중 UI 1건·점수/예측 로직 4건·관련 DB 8건 통과. QA 마이그레이션·타입 생성과 보안 오류 진단도 확인했다. 기존 QA 명단과 운영 DB·배포 보류를 유지한다.

## 2026-10-09 클랜원 목록 부착·플레이어 드래그

- 클랜원 목록을 기본 왼쪽에 두고 제목 왼쪽의 손잡이로 위·왼쪽·오른쪽·아래에 부착한다. 손잡이 클릭·방향키와 좁은 화면의 세로 배치도 지원한다. 좌우 패널은 빈 목록에서도 참여자 목록과 높이를 맞춘다. 클랜원을 참여자 자리로 끌어 추가/교체하며 기존 참여자는 목록으로 돌아간다. 가득 찬 명단의 클릭/터치 교체와 기존 자리 교환·제거·되돌리기·자동 저장을 유지한다.
- 변경 파일 ESLint·TypeScript·임시 클랜 집중 E2E 1건과 자동 저장 로직 8건 통과. 실제 네 방향 드래그/배치, 추가/교체·중복 없는 10명 유지, 자동 저장·새로고침 복원, 모바일 검색/추가 및 충돌·실패 복구를 확인했다. 기존 QA 명단·DB·운영 배포는 보존한다.

## 2026-10-09 미리보기 4초 재생·수치 요소 강조

- 모든 미리보기 컷을 4초로 맞추고 긴 카운트다운·추첨 발표를 비례 재생한다. 입력 순서는 입찰 연장 → 낙찰 후 준비로 변경했으며 크레딧 행·버튼·타이머 등 실제 요소만 강조하고 화면 높이를 유지한다. 전후 값은 화면 낭독기에 제공한다.
- 변경 파일 ESLint·TypeScript·미리보기 E2E 1건 통과. 4초 전환/반복, 연속 10명 발표, 카운트다운, 입력 순서, 강조 범위·정지/재개·모바일·동작 줄이기와 설정 미저장을 확인했다. QA 명단·DB·운영 배포 변경 없음.

## 2026-10-09 편성 완료 후 사전 선택 맵 유지

- 주장 지명·추첨 완료 뒤 미리 선택한 맵이 있으면 별도 준비 요약 없이 경기 또는 영웅 밴으로 이동한다. 맵이 없으면 기존 선택 화면을 유지하며 편성 중 선택·변경도 보존한다. 화면 제목과 안내를 선택 상태에 맞췄다.
- 변경 파일 ESLint·TypeScript, 임시 클랜의 맵·분석·경기 준비 E2E 4건 통과. 지명/추첨의 선택 맵 유지·영웅 밴/경기 진입, 명시적 맵 변경·미선택 흐름과 기존 투표를 확인했다. 영웅 밴 검증은 QA DB와 PC의 시계 오차를 1초 허용하고 마감 경계 후 시작한다. DB·시드·운영 배포 변경 없음.

## 2026-10-09 설정 미리보기 수치 편집 위치 강조

- 경매 수치 6종의 입력 포커스·편집 시 해당 장면으로 이동해 일시정지하고 적용 요소 내부에 테두리·배경과 초기 설정 → 편집 값을 표시한다. 연장 0초를 명시하며 재생·구간 이동·방식 전환 시 강조를 해제한다.
- 변경 파일 ESLint·TypeScript 및 임시 클랜의 미리보기 E2E 1건으로 6종 장면/전후 값, 자동 재생 정지·재개, 동작 줄이기·모바일 경계와 DB 설정 미저장을 확인했다. 기존 QA 명단·설정은 보존한다.

## 2026-10-09 주장 입찰·편성 맵·분석 점수

- 입찰 버튼과 요청을 해당 팀 주장으로 제한하며 최고가 팀의 자기 증액을 UI·서버·CAS에서 차단한다. 낙찰 공개 2.5초 뒤 준비 시간에는 다음 선수를 표시한다. 관리·지명·아이템 제어는 기존 권한을 유지한다.
- 맵 투표를 끄면 편성 화면에서 맵을 먼저 고른다. 분석 V1은 정규 내전 전체/역할/맵 전적을 10경기 prior로 보정하고 -10~10으로 표시한다. 명시 match 중복·무효·미기록·깜짝 경기는 제외한다. 표본이 없으면 A=null, 평가 점수는 유지한다. 경기 시작 시 A를 고정하고 점수 RPC는 평가만 저장한다.
- QA 마이그레이션 3개·타입 확인 완료. ESLint·TypeScript·빌드와 관련 Playwright 31건(규칙25·미리보기1·준비2·경매1·맵분석1·점수비교1), 임시 DB 회귀15건 통과. 맵별 +5→-5 변화, 동일 M 유지, 분석 입력/저장 부재, 위조 A·빈 RPC로 분석 삭제 불가, 운영진 비입찰 및 최고가 재입찰 차단을 확인했다. 초기 테스트의 예측 식별자 변경 거부 코드는 기존 trigger 메시지로 검증하고 원본 보존을 확인했다.
- [설계](02-design/formation-modes.md#2026-10-09--주장-입찰편성-맵분석-점수). 운영 DB·배포는 보류하며 사용자 QA 데이터는 재시드하지 않았다.

## 2026-10-09 경매 타이밍 설정·미리보기

- 낙찰 후 준비 0~60초(기본 5초), 입찰 연장 0~30초(기본 5초)를 추가했다. 준비는 낙찰 시점부터 계산하고 최소 2.5초 결과 공개와 겹쳐 진행한다. 마지막 선수에는 별도 준비 대기를 넣지 않는다. 연장은 남은 시간을 설정값으로 확보하며 기본 시간+30초 상한을 유지한다. 전략 아이템 준비 10~120초는 경매 전 별도 단계다.
- QA DB에서 기본값 비교·정수/범위·권한 검증·감사 기록을 확장했다. 기존 라운드를 일괄 수정하지 않고 저장/조회 시 기본값을 보완한다. 실제 두 주장 화면에서 12초 준비·다음 선수 자동 공개·아이템 선택·편성 완료를 확인했다.
- 경매 미리보기의 입찰/낙찰은 한 세트로 줄였으며 설정값 변경·준비 카운트다운·연장 고지·아이템 이름과 가격·모바일 배치를 확인했다. ESLint·TypeScript·빌드, 관련 Playwright 34건과 임시 DB 15건 통과. 운영 적용은 보류한다.

## 2026-09-30 대시보드 순위 조회 복구

- 정규 내전이 1,304경기로 늘어난 QA에서 대시보드의 1,000행 제한으로 모든 MVP 조회가 오류 처리되던 문제를 수정했다. 경기·종료 라운드·월간 예측을 ID 정렬 후 500행씩 조회하고, 페이지 오류·불완전 응답·조회 중 건수 변화는 부분 순위로 공개하지 않는다.
- 페이지 경계·후속 요청 실패·빈 기록·조회 중 변화 테스트 3건, 별도 임시 클랜의 대시보드 통합 1건 통과. 통합 픽스처를 공유 QA와 분리하고 월말 날짜 계산을 보정했다. 변경 파일 ESLint·TypeScript 통과, 실제 QA의 MVP 3부문·배지 정상 표시 확인. 스키마·권한·운영 DB 변경 없음.

## 2026-09-27 통계 초기 로딩 최적화

- 최초 응답에는 명예의 전당·내전 집계와 멤버 선택용 요약만 포함한다. 경기 기록은 해당 탭에서, 개인 기록은 선택한 멤버 한 명씩 인증된 API로 조회한다. 페이지 내 재선택은 응답을 재사용하고 점수 수정·페이지 갱신 시에는 다시 조회한다. 실패 시 재시도를 제공한다.
- 각 상세 요청에서 현재 활성 멤버십·공개 설정·권한을 다시 확인하고 `private, no-store`를 적용한다. 일반 멤버는 허용된 본인 기록만, 운영진은 기존 권한 범위의 멤버·예측 원장을 조회한다. 초기 요약에서도 최근 출전 기준 멤버 정렬을 유지한다.
- 개인·경기·내전 탭 코드를 분리하고 초기 DB 조회에서 편성 상태/설정을 제외했다. 개인 전체 이력·원장·관리 전용 집계를 초기 응답에서 생성하지 않으며 과거 월·연도 명예의 전당은 기간별로 한 번 분류한 기록을 사용한다.
- 측정: 로컬 QA `next dev` 3011, 기존 QA 리더/클랜(유효 1,261경기), `node scripts/measure-qa-pages.mjs /stats`로 3회씩 HTTP 본문 수신까지 측정했다. 변경 전 **3,364/3,640/3,071ms · 13,637KiB**, 최종 **1,831/806/751ms · 1,022KiB**(압축 해제 본문). 브라우저 상호작용 완료나 운영 환경 수치를 의미하지 않는다.
- 검증: 집계·경기 기록 19건, 기간/상세 UI 1건, 예측 원장/점수 수정/권한 경계 1건 통과. 집계 동일성·최초 상세 제외·재시도·재사용·점수 수정 후 갱신, 비로그인/타 클랜/타인/공개 해제 후 접근 차단을 확인했다. 변경 파일 ESLint·TypeScript·프로덕션 빌드 통과. 실제 QA 개인 기록·포인트 그래프 확인. 스키마 변경·공유 QA 시드 재실행·운영 DB 변경 없음.

## 2026-09-27 운영진 예측 열람·평가 점수 이력 수정

- 운영진이 같은 클랜 멤버의 승부예측 실제 정산 포인트와 그래프를 볼 수 있다. 일반 멤버의 타인 조회는 유지해 차단한다. 시너지 차트의 닉네임을 위로 옮기고 프로필 이미지와 링 사이를 띄웠다.
- `edit_mscore` 기본 허용을 클랜장·운영진으로 바꾸고 점수 이력에서 완료된 정규 내전의 평가 점수만 수정하도록 했다. 서버·DB에서 권한과 점수 범위·출전자를 확인하고 직접 점수 필드 쓰기는 차단한다. QA 마이그레이션·타입 생성과 집중 E2E를 확인했다.

## 2026-09-27 무승부 예측·개인 통계 보완

- Premium 정규 내전의 비출전 멤버가 블루·레드 외에 무승부를 예측할 수 있다. 무승부 적중도 5코인을 지급하고 실패는 차감하지 않으며 무효 경기에는 지급하지 않는다. 적중력은 무효를 제외한 적중 확률로 집계한다.
- 맵별 승률 목록은 필터와 관계없이 높이를 유지하고 스크롤바 대신 남은 방향의 가장자리를 흐리게 표시한다. 역할·시너지 표의 승률/경기 열을 바꿨다. 예측 그래프는 본인의 실제 코인 원장만 반영하고 타인의 포인트 흐름은 비공개로 표시한다. QA 마이그레이션·타입 생성, DB 테스트 13건과 관련 E2E 10건 통과.

## 2026-09-27 개인 기록 표·맵 범례 정리

- 플레이어 요약의 수치 카드 3개를 전체·역할별 경기/승·무·패/승률 표로 교체했다. 맵별 승률은 기타 합산 없이 전 맵을 다섯 줄 높이에서 스크롤하고, 도넛 중앙에 선택 맵 승률을 표시한다. 시너지 기본 아바타를 원형 도넛 안에 확대했다.
- `멤버 선택`을 배너에서 고정 기간 필터 오른쪽으로 옮겼다. 타입·린트·기간/시너지 집중 E2E와 QA 화면을 확인했다. QA 시드·DB 변경 없음.

## 2026-09-27 역할·맵 기록 재분리

- 개인 기록의 역할별 승률을 3행·6열 표로 분리하고 승·무·패·라운드·승률을 함께 표시했다. 맵별 승률은 기존 도넛·목록을 유지하면서 역할·맵 형식 필터를 추가했다. 시너지 차트는 하트에서 원형 도넛으로 변경했다.
- 타입·린트·기간/시너지 집중 E2E 1건과 실제 QA 화면을 확인했다. QA 시드·DB 변경 없음.

## 2026-09-18 경기 현황 간소화·승부예측 설정

- 점수 모드 토글은 편성 화면에만 두고 경기 현황 참가자는 이름만 표시한다. 기존 카드 표시 설정과 관계없이 개인 점수·팀 합계·보조 정보·정보 팝업을 숨긴다. 승부예측과 권한이 있는 운영진의 점수 조정은 각각 별도 드로워로 제공한다.
- 라운드 설정의 밴픽 탭에서 Premium 정규 내전만 승부예측 사용 여부를 바꾼다. 기본값은 기존 동작을 유지하는 사용이며 다음 라운드로 이어진다. Free·깜짝 내전은 UI에서 잠기고 예측 제출도 서버·RLS에서 거부한다. 경기 시작 후 변경은 금지하며 관전자·마감 시각 조건은 유지한다.
- 평가·분석 점수는 −10~10의 유한 소수를 허용한다. 잘못된 입력을 저장 시 보정하지 않고 UI·서버에서 거부한다. QA 마이그레이션 76개 적용·생성 타입 확인, 운영 50개 유지.
- 검증: 관련 DB 19건(새 설정 6·밴픽/선호 13), 점수 규칙 5건, 집중 E2E 2건(기존 정보 표시·새 설정/드로워), 변경 파일 린트·타입·빌드 통과. 운영진/멤버 화면, Free 잠금, Premium 저장·해제, 참가자 참여 거부·관전자 예측 변경, 모바일, ±10 저장과 10.1 거절을 확인했다. 테스트 전용 개발 캐시의 404를 정리한 뒤 통과했으며 사용자 QA 서버·명단·운영 DB·전체 회귀는 변경/실행하지 않았다.

## 2026-09-18 주장 지명·자동 경매·전략 아이템

- 지명·경매 영역을 참가자 표 위로 옮겼다. 주장을 겸하는 관리자는 자기 팀만 조작하며 서버도 상대 팀 입력을 거부한다. 경매는 좌우 증감 버튼, 현재 선수·타이머·낙찰 연출과 자동 다음 경매를 제공한다. 연결 중인 참가자 누구나 서버 기한 확인을 요청할 수 있어 관리자의 버튼 클릭이나 화면 유지에 의존하지 않는다.
- 아이템 기능을 켜면 무작위 3개 공개·전략 준비·선수 경매·양 팀 아이템 선택·편성 완료로 진행한다. 준비 시간과 경매 시간을 설정하며, 클랜 운영진은 내전 관리 설정에서 아이템을 관리한다. 기본 구매 규칙은 팀당 최대 1개·양 팀 동일 구매 가능·남은 예산 사용이고 효과는 운영진이 직접 적용한다. 공개한 내용은 경매별로 고정한다. 상세는 [편성 명세](02-design/formation-modes.md#주장-조작자동-경매전략-아이템-2026-09-18)를 따른다.
- 양 팀 동시 선택은 현재 편성 식별자와 최신 상태를 대조해 합치며 중복 차감·초기화 전 요청을 차단한다. 기존 라운드에 없는 새 설정값은 기본값으로 보완한다. QA 마이그레이션 75개 적용·생성 타입 확인, 운영 50개 유지. 사용자 QA 명단은 시드로 초기화하지 않았다.
- 검증: 편성 규칙 22건, 관련 DB 22건(편성 8·아이템 권한 1·밴픽/선호 13), 집중 E2E 3건(카탈로그·주장 경매·기존 직접 배정/공통 추첨), 변경 파일 린트·타입·빌드 통과. 실제 전략/입찰 기한·낙찰 후 다음 선수, 관리자 이탈 후 멤버 진행, 양 팀 동시 구매/기권과 중복 차감 방지, 초기화 전 요청 차단, 공개 아이템 고정, 858/390/320px 화면을 확인했다. 전체 회귀·운영 반영은 수행하지 않았다.

## 2026-09-16 내전 로비·예약

**추가 수정 — 편성 진행 간소화:** 직접 배정은 `다음 단계` 한 번으로 저장·맵 단계 이동을 처리한다. 공통 추첨은 별도 팝업 없이 현재 편성판에서 같은 서버 결과를 순차 공개하고 완료 후 자동 이동한다. 지명·경매도 편성 완료 시 자동 적용한다. 린트·타입과 직접 배정/밴픽 3건, 멤버 권한 1건, 공통 추첨·자동 전환·기록 1건, 편성 규칙 17건을 통과했다. DB 스키마·운영 환경은 변경하지 않았다.

**추가 수정 — 참가자 점수·전적:** M/A를 평가/분석 점수로 표시하고 개인 점수 배지와 팀 합계를 분리했다. 호버·키보드 정보창에는 현재 세션의 승·무·패/승률/연속 기록과 권한에 맞는 점수를 제공한다. 카드 점수·보조 정보·팀 비교 및 플레이어 정보 팝업의 표시 여부와 세션 전적/연승·연패 선택을 라운드 설정에 추가했고, 설정은 편성/화면 표시/밴픽 탭으로 분리했다. 결과에 실제 무승부를 추가했으며 무효와 분리 집계하고 보상 없이 다음 라운드로 진행한다. QA 70개·운영 50개(20개 대기). 상세 규칙은 [편성 명세](02-design/formation-modes.md#참가자-정보무승부-2026-09-18)를 참조한다.

검증: 관련 DB 7건·집계/점수 규칙 10건·집중 E2E 1건, 린트·타입·빌드 통과. PC/모바일, 점수 모드·합계·교환, 호버/Tab/Escape, 일반 멤버 비공개, 실제 무승부 입력 후 1승 2무 1패/25% 갱신을 확인했다.

**추가 수정 — 세션 자동 종료:** 새 클랜은 마지막 입력 후 3시간 자동 종료를 기본 사용한다. 운영진은 클랜 관리의 내전 관리 설정에서 기능을 끄거나 1~168시간으로 변경한다. 세션 편집·역할 선호·맵/영웅 투표·예측 입력이 활동 시각을 갱신하며 QA cron이 1분마다 만료 세션을 무효 종료한다. 기존 세션의 활동 시각이 배포 시각으로 초기화되던 문제를 실제 확인 가능한 마지막 입력 시각으로 보정했다. QA 67개·운영 50개(17개 대기). 별도 임시 클랜의 권한·비활성 유지·활동 갱신·만료 종료 DB 테스트와 실제 기존 정규·깜짝 세션의 예약 자동 종료를 확인했다. 사용자 QA 명단·전체 회귀·운영 DB는 건드리지 않았다.

**추가 수정 — 팀별 영웅 밴:** 팀당 1/2명 설정·초상화 즉시 투표·팀별 득표순(무투표는 없음)·밴 확정과 경기 시작 원자 저장을 적용했다. 역할/팀별 밴 맥락과 모델 입력 키를 준비했으며 실제 숙련도 승률 모델은 후속이다. QA 65개·운영 50개(15개 대기). 린트·타입·빌드·관련 DB 6건·집계 1건·집중 E2E 1건 통과. 새 분석 컬럼 저장 권한을 운영진 RLS 범위로 보완하고 멤버 쓰기 차단을 검증했다.

**추가 수정 — 정규 승부예측 제한:** 액션과 DB의 제한 정책으로 정규 방만 예측을 등록/수정할 수 있다. 기존 Premium·관전자·미종료·마감 조건을 유지한다. 깜짝 UI는 계속 예측 참여를 숨긴다. 팀 합계/총점·토글 옆 안내·카드의 중복 역할 표기를 제거했다. QA 63개 적용·운영 50개(13개 대기), 생성 타입 동일·새 정책 advisor 경고 없음. 린트·타입·빌드와 집중 E2E 1건 통과(정규 예측 등록/수정, 깜짝 신규 예측 거절·기존 예측 변경 불가·정규 예측의 깜짝 이동 거절, UI). 마이그레이션의 중복 정의를 제거한 후 QA 적용에 성공했다. 시드·전체 회귀는 실행하지 않았다.

**추가 수정 — 맵 결과·승률 간소화:** 실제 결과 팝업을 본문 카드 강조로 교체하고 승률을 선택 맵 반영 여부에 따라 바뀌는 한 줄로 통합했다. 이전 맵이나 일반 예측을 새 맵의 예측으로 재사용하지 않는다. 변경 파일 린트·타입 및 운영진/멤버의 실시간 확정·재접속·경기 시작 E2E 1건 통과. 표시 변경 범위라 DB·전체 빌드·전체 회귀는 생략했다.

**추가 수정 — 비교 위치·자동 참여:** M/A 토글을 출전 인원 표시 자리에 두고 팀 점수/일반 승률을 출전 카드 위에 통합했다. 맵별 승률은 맵 선택/투표 단계에만 노출한다. QA 전용 샘플 점수·승률은 저장하지 않으며 실제 점수 편집과 분리한다. 깜짝 생성자는 즉시/예약 모두 참여 처리하고 기존 활성 방의 누락 응답만 보완한다. 로비 버튼은 더보기 유무와 관계없이 같은 열에 배치한다. QA 62개·운영 50개(12개 대기), 생성 타입 동일·새 트리거 advisor 경고 없음. 린트·타입·빌드와 기존 집중 E2E 1건으로 점수/맵/샘플 비저장·생성자 참여·데스크톱/모바일 정렬을 검증했다. 계정 전환 쿠키와 모바일 캡처 대기만 보완했으며 앱 빌드를 반복하거나 QA 명단을 초기화하지 않았다.

**추가 수정 — 깜짝 수명·점수 비교:** 일반 멤버의 전체 기록 아이콘을 숨기되 열린 깜짝 세션 개설자는 해당 기록만 조회한다. 종료 트리거가 깜짝 방·라운드·참여·투표·예측을 삭제하며 정규 기록은 유지한다. 깜짝 결과는 영구 통계·코인 보상에 반영하지 않는다. 운영진 정규 편성의 M/A 토글·팀 점수 차이·예측/맵별 승률 UI를 추가했으며 실제 모델 연결 전에는 `—`로 표시한다. 수동 맵 선택은 즉시 비교 영역에 반영한다. 종료는 기존 편성 방식 설명 위치의 빨간 버튼과 확인창으로 이동했다. QA 61개 적용·운영 50개 유지(11개 대기), 생성 타입 동일·새 삭제 함수의 보안 advisor 경고 없음. 변경 파일 린트·타입·빌드와 집중 E2E 2건(권한/종료 삭제, 점수 토글/맵 즉시 표시/모바일/무보상) 통과. 테스트 선택자·경기 시작 준비 단계를 수정한 뒤 실패한 시나리오만 재실행했다. 전체 회귀·빌드는 반복하지 않았으며 기존 QA 명단은 시드로 초기화하지 않았다.

**추가 수정 — 기록 권한·방송 화면:** 내전 기록 버튼과 조회 액션을 활동 중인 운영진 이상으로 제한했다. 일반 멤버는 본인 깜짝 방을 운영해도 기록을 열 수 없다. 별도 방송 모달·버튼을 제거했다. 린트·타입·빌드 통과, 임시 계정 2개의 집중 권한 E2E 1건 통과(멤버 비활성화, 직접 액션 거절, 운영진 승격 허용·강등 즉시 거절). 첫 검증의 HTTP 재전송 형식을 실제 브라우저 요청으로 보완한 뒤 해당 1건만 재실행했으며 빌드는 반복하지 않았다. 점수·승률은 [제안](01-plan/product-design-evolution.md)에 기록했고 이번에는 구현하지 않았다. DB 변경 없음.

**추가 수정 — 예약·목록 간소화:** 캘린더 팝업을 날짜/시/분/초 휠로 교체하고 매주 예약은 요일/시각만 선택한다. 정규 내전을 상단에 배치하며 같은 반복 일정의 열린 세션과 다음 예약은 한 행으로 표시한다. 깜짝 내전은 목록에서 참여/취소하고 미정·불참 UI는 제거했다. 변경 파일 린트·타입, 임시 계정 1개를 쓰는 핵심 E2E 1건 통과(한국 시간·초 저장, 마우스 드래그, 주간 중복 행 제거·정렬, 참여/취소·새로고침, 390px 휠). 전체 빌드·DB 회귀·기존 전체 내전 E2E는 반복하지 않았다. DB·운영 변경 없음.

- `/balance`는 내전 목록과 추가 버튼을 표시한다. 방에 입장하면 `?room=` 주소로 기존 편성·밴픽·경기를 이어간다. 중복 Premium 표시를 제거하고 로비 안내를 새 흐름에 맞췄다.
- 정규 내전은 운영진 이상, 깜짝 내전은 활동 중인 클랜원이 개설한다. 깜짝 개설자는 자기 방을 운영하고 다른 방의 운영 권한은 얻지 않는다. 클랜장은 정규 방의 임시 진행 운영진을 지정·해제하며 종료 시 해제된다.
- 즉시 개설·예약·정규 매주 반복, 깜짝 내전 참석 응답(1~30일 전부터)을 지원한다. 참석 응답은 실제 출전 명단을 바꾸지 않는다. 세부 동작은 [로비 명세](02-design/session-lobby.md)를 따른다.
- QA 마이그레이션 60개 적용, 운영 50개 유지(10개 대기). 기존 기록은 방으로 연결해 보존했다. `balance-room-materializer` cron은 매분 활성화되어 실제 `succeeded` 실행을 확인했다. 보안 advisor에서 새 방 관련 경고는 없으며 기존 경고는 남아 있다.
- 검증: 빌드·타입·변경 파일 린트, QA DB 34건(방 8·세션/편성/밴픽/선호 26), 관련 Playwright 9건(브라우저 8·권한 규칙 1) 통과. 입장 링크의 접근성 역할과 비동기 반복 설정의 테스트 대기를 보완한 뒤 관련 6건을 재검증했다. 예약·위임·참석 응답·동시 방 격리·개인 선호·맵/영웅 밴·추첨/지명/경매·기록을 확인했다. 쓰기는 별도 임시 계정·클랜으로 검증했고 사용자 QA를 시드로 초기화하지 않았다. 데스크톱·390px 로비 레이아웃과 가로 넘침을 확인했다.
- 적용은 QA DB·로컬 앱·작업 브랜치까지다. 전체 회귀, main 병합 및 운영 반영은 별도 단계다.

## 2026-09-16 밸런스메이커 QA 피드백 반영

**추가 수정 — 맵 선택 화면:** 저장되는 `편성 적용` 단계 이후 맵 전용 화면으로 이동한다. 투표는 유형 복수 선택 → 선택 완료 즉시 시작하며, 수동 선택은 유형별 이미지 아코디언·저장된 맵 강조 후 경기 시작으로 이어진다. 팀 명단·설정은 라운드 도구 drawer로 옮겼고 안내는 현재 단계에 맞춘다. 전장 이미지 27개(약 1.9MB)의 출처는 `public/images/overwatch/maps/SOURCES.json`에 기록했다. 변경 파일 린트·타입, 편성 규칙 17건·관련 UI 3건 통과. 멤버 미확인 추첨 팝업이 맵 단계에서도 유지되도록 보완 후 내전 통합 1건을 재검증했다. 390px 키보드 조작·이미지 로드·단계별 안내·양측 화면/재접속과 데스크톱·모바일 스크린샷을 확인했다. DB 스키마 변경이 없어 전체 빌드·DB 회귀는 반복하지 않았다.

**추가 수정 — 경기 전 밴픽:** 편성 후에도 경기 시작 전까지 밴 사용·시간을 바꾸고, 유형별 맵 투표 또는 필수 수동 맵 선택 후 별도로 경기를 시작한다. QA 설정에 3·5·2표 연출 테스트를 제공하며 실제 투표·기록에는 쓰지 않는다. 규칙은 [편성 명세](02-design/formation-modes.md#경기-시작-전-밴픽-설정-2026-09-16)를 따른다. 빌드·타입·변경 파일 린트, 밴픽 2건+기존 내전 통합 1건, 관련 DB 26건 통과. 마지막 투표 식별 보완 후 밴픽 2건·DB 6건을 재검증했다. 서버가 브라우저의 투표 마감 시각과 현재 투표를 대조해 재시작 전 표를 거절하고 직접 테이블 쓰기를 막는다. 운영 DB·main 반영은 보류한다.

**추가 수정 — 역할 추첨 팝업:** 18초 공개·본인 순번 유지·개별 확인·완료 후 재접속 동작은 [편성 명세 §5](02-design/formation-modes.md#5-선호-추첨--공통-무작위-순서)를 따른다. 변경 파일 린트·타입·내전 통합 E2E 1건 통과. 검증은 위험도별로 선택하며 전체 빌드/회귀는 이번에 반복하지 않았다.

**추가 수정 — 멤버 입력·화면 간소화:** 멤버 전용 `127.0.0.1` 개발 리소스 차단을 명시적 허용 호스트 설정으로 해결했다(수정 전 403 → 수정 후 200, 실제 멤버 저장·새로고침 확인). 라운드 선호는 세 아이콘과 옵션 메뉴로 줄이고, 날짜·라운드는 편성 헤더에 통합했다. 설정·운영 가이드·방송 버튼은 멤버에게 숨기고 기록은 통계 아이콘으로 표시한다. 빌드·타입·변경 파일 린트, 관련 E2E **19건**, 기존 격리 선호 DB 테스트 **7건** 통과. DB/API·운영 환경 변경은 없다.

**추가 수정 — 역할 아이콘 입력:** 프로필·라운드의 텍스트 선호 목록을 아이콘 순서 입력으로 교체했다. 드래그·클릭 교환·좌우 방향키와 프로필 복귀/선호 없음/실패 복구를 확인했다. 빌드·타입·변경 파일 린트, 관련 Playwright 18건(17건 통과 후 저장 완료 대기를 보완한 내전 통합 1건 재검증) 통과. QA 운영진과 클랜원 클라이언트는 localhost/127.0.0.1의 별도 로그인으로 함께 테스트한다. DB/API 변경은 없다.

**적용 환경은 QA DB·로컬 앱이며 운영 반영은 보류한다.** `codex/live-session-formation`에서 작업한다. 최신 QA 스키마·검증 상태는 위 내전 로비 기록을 따른다. 현재 사용자의 QA 클랜·열린 라운드·명단은 초기화하지 않는다.

- **명단:** 400ms 자동 저장과 쓰기 순서 직렬화. 편성·설정 적용 전 미완료 저장을 기다리며 서버 revision 충돌·연결 오류에서 로컬 변경을 보관한다. 다른 화면 변경은 재적용 또는 최신 명단 불러오기로 해결한다.
- **선호:** 게임별 프로필 선호는 본인이 저장한다. 출전자는 편성 시작 전에 이번 라운드만 덮어쓰거나 프로필 기본값으로 복귀할 수 있다. 미설정/선호 없음은 남은 역할 자리에서 추첨하며 체크인·운영진의 선호 재입력은 요구하지 않는다. 비공개 순위는 본인 외 화면과 공개 편성 상태에 전달하지 않는다. 프로필 저장의 중복 경로 갱신을 제거하고 저장 응답에서 입력 잠금을 해제한다. 실패 시 마지막 확정값으로 복구한다.
- **설정:** 역할 직접 배정/공통 순서 추첨, 현재 팀 유지/역할별 추첨/주장 지명/경매, 같은 역할 주장, 경매 예산·최소/증액 단위·시간, 맵/영웅 밴을 한 패널에서 저장한다. 다음 라운드에는 규칙·밴픽을 이어 쓰고 주장 지정·개인 라운드 선호·추첨 이력은 초기화한다. 다른 운영진이 바꾼 설정을 오래된 편집본으로 덮어쓰지 않도록 기준값도 확인한다. 적용 중 패널 닫기를 잠그고 부모 화면이 저장 이후 revision을 받은 뒤 닫아 직후 시작 요청의 이전 설정 사용을 방지한다. 그 사이 다른 운영진이 다시 변경했으면 최신 규칙 확인을 안내한다.
- **동시성·복구:** 편성 시작은 클릭 당시 명단·설정·밴픽과 추첨 이력 길이를 확인한 뒤 최신 개인 선호를 해석하고 최종 revision CAS로 저장한다. 개인 선호만 먼저 저장된 경우는 수용하되 시작→초기화 뒤 도착한 오래된 시작 요청은 거부한다. Realtime 인증을 동기화하고 DB 구독 준비/재연결 시 놓친 변경을 재조회한다. 화면이 보이는 동안 활성 라운드는 2초(없으면 5초)마다 작은 revision 상태만 비교하며 변경 시 페이지를 갱신한다. 투표·예측·M/A 등 별도 상태는 30초 전체 갱신으로 복구한다.
- **공개·배치:** 서버가 저장한 추첨 식별자·순서·결과를 18초 동안 팝업과 참가자 영역에서 공개한다. 직접 배정+현재 팀 유지에는 가짜 추첨 연출을 넣지 않는다. 완료 결과용 명단을 중복 배치하거나 다시 보기 버튼을 만들지 않는다. 공유 화면은 읽기 전용이며 같은 결과·진행 시점을 사용한다.
- **안내·기록:** 안내 아이콘을 눌렀을 때만 대상 영역을 강조하는 단계별 도움말을 연다. 기록 아이콘은 데스크톱 넓은 drawer/모바일 전체 화면으로 최근 30세션을 조회한다. 개설 KST 날짜·라운드 명단/맵/결과, 유효 승패만의 고유 출전·승률·현재 연속 승패, 공개 추첨 순서/시각/규칙/초기화 이력을 표시한다. 0경기 승률은 `—`이며 개인 선호·베팅 내역은 포함하지 않는다.
- **검증 완료 범위:** 역할/편성 순수 로직 14건, 자동 저장 8건, 기록 6건, QA DB 전체 **44건**(기존 37+선호 7), SQL 린트·빌드·타입·src 린트 통과. 기록 조회의 회원/비회원 RLS와 사용자 QA의 안내·기록·설정 읽기 화면을 확인했다.
- **브라우저 검증 범위:** 전체 회귀 82건 통과 후 수정한 내전 통합 1건과 프로필 1건 개별 재검증 통과, **총 84시나리오**. 내전 통합은 자동 저장·개인 선호·실시간 반영·설정 적용 직후 시작·공유 추첨·지명·경매·기록을, 프로필은 연속 저장과 실패 시 확정값 복구를 확인한다. 새 내전 테스트는 독립 사용자 12명·임시 클랜을 생성/정리하며 프로필 테스트도 별도 임시 사용자를 쓴다. 실행 시 `E2E_SKIP_SEED=1`로 기존 세션을 보존한다.

세부 화면·후속 범위는 [편성 명세](02-design/formation-modes.md), 실행 명령은 [E2E 안내](../e2e/README.md)를 따른다.

## 2026-09-16 실제 내전 운영 페이지

**이 절은 최초 적용 당시 기록이다.** 사용자 지시로 QA DB·로컬 앱에 적용했고 운영 DB·운영 배포는 보류했다. 당시 운영 50개·QA 53개 마이그레이션이었으며 현재 상태는 위 피드백 반영 기록을 따른다.

- 세션 부모 `balance_session_series`와 라운드 `balance_sessions`를 분리했다. 개설 한국 날짜 고정·회차·다음 라운드 명단 유지·라운드별 결과/예측/기록을 저장한다. 기존 데이터는 각각 한 라운드 세션으로 보존한다.
- 수동 명단의 DD/T/SS 배치, 순차 입력, 선택자 숨김, 우클릭·드래그·되돌리기·초기화 및 최근 참여순을 반영했다. 최근 확정 100개 라운드를 정렬 근거로 사용하며 이력 밖 인원은 닉네임순이다.
- 역할 직접 배정/공통 무작위 순서, 현재 팀 유지/역할별 추첨/같은 역할 주장 지명/1,000P 경매를 조합했다. 당시 운영진 선호 입력은 위 후속 구현에서 프로필 기본값·본인 라운드 선호로 대체했다.

## 2026-09-15 로그인·페이지 이동 성능 개선

- 운영 함수가 미국 `iad1`, Supabase가 서울 `ap-northeast-2`에서 실행되는 것을 확인했다. `vercel.json`의 함수 지역을 `icn1`으로 지정했다. [Vercel 함수 지역 설정](https://vercel.com/docs/functions/configuring-functions/region).
- 정상 로그인은 검증된 비밀번호 인증 응답을 재사용하고 프로필 저장·잠금 초기화를 병렬 처리한다. 프로필이 없을 때 복구하는 경로는 유지한다.
- RSC 렌더 안에서만 인증 사용자·클랜 맥락·권한 조회를 재사용한다. 사용자 간 공유 캐시는 없고 Server Action은 새 권한을 조회한다. 클랜 공통 조회와 관리·이벤트 본문은 독립 요청을 병렬 처리한다.
- 페이지 이동 표시·경로별 로딩 화면을 추가했다. 홍보 정렬은 현재 목록을 재정렬하며 검색과 브라우저 기록을 유지한다.
- 회귀 검사에서 발견한 인증 쿠키 400일 덮어쓰기를 수정했다. 로그인·서버/브라우저 갱신에 24시간/30일 선택을 유지한다. 공지 편집창의 지연된 초기 초점도 수정해 빠른 제목·본문 입력이 섞이지 않도록 했다.
- 검증: 운영 설정 빌드·타입 검사·전체 `src` 및 변경 테스트 ESLint 통과. 전체 회귀 43건 중 42건 통과 후 공지 편집 수정·해당 1건 재실행 통과. DB 스키마 변경 없음.
