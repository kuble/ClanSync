- 2026-09-15 사용자 위임: 오래 걸려도 목업을 기준으로 전체 프론트엔드를 재구성하고 검증까지 진행. 작업 커밋은 자동 푸시한다.
- 이전 DB 리뷰 수정은 `bbc84a3`까지 운영 반영 완료. 인증·권한·트랜잭션을 유지하고 실제 데이터를 목업 구조에 연결한다.

- `mockup/pages/`와 `mockup/styles/main.css`가 시각 기준, 최신 결정 문서와 실제 DB가 권한·업무 규칙 기준이다. 스튜디오·허브는 개발 보조 도구로 운영 이식 대상에서 제외한다.

## 검증 원칙

- 목업과 앱을 같은 화면 크기에서 비교한다. 색상 변경만으로 완료 처리하지 않는다.
- 기본·데이터 없음·로딩·오류·권한 없음 및 Free/Premium 조건을 확인한다.
- QA DB `moretvteewfcztxvwztw`만 시드·업무 동작 테스트에 사용한다. 운영에 QA 데이터를 추가하지 않는다.
- 테스트 셀렉터를 임의로 무효화하지 않는다. 변경된 사용자 흐름에 맞는 의미 있는 검증만 보강한다.
- 전체 코드가 준비된 단위마다 lint/build/E2E 후 커밋·푸시, 운영 자동 배포를 확인한다.

## 사용량과 중단 시 재개

- 시작 시 주간 잔여 15%, 리셋 크레딧 3개. 10% 이하에서 **1개 사용**에 대한 승인을 요청 중이며 답변 전에는 사용하지 않는다.
- 크레딧 사용은 승인된 1개에만 한정한다. 추가 크레딧은 새 승인이 필요하다.
- 의미 단위 커밋과 이 파일의 상태를 수시로 갱신한다. 중단돼도 이미 검증한 기능을 재작성하지 않는다.
- 다음 실행은 `git status`, 최근 커밋, 이 작업표를 확인하고 진행/대기 항목을 이어간다. 커밋되지 않은 다른 작업자 파일을 삭제·되돌리지 않는다.
- 사용자 기존 파일: BACKLOG·QA 시나리오 변경, `.obsidian/`, 개인 메모는 별도 작업이며 이번 일괄 스테이징에서 제외한다.

## 발견된 차이

- 운영 대시보드는 세션 요약 임시 화면. 목업의 3열 공지/규칙·일정/배지·MVP 구성 미구현.
- 기본 shadcn 회색 토큰·Geist가 적용돼 목업의 녹색 계열·Pretendard·카드 크기와 다름.
- 일반 클랜 공지 테이블/CRUD와 규칙 편집 UI가 없음. 공개 투표만으로 일반 공지 완료를 주장하지 않고 F09에서 보완한다.
