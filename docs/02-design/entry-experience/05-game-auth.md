# 게임 계정 연결 상세 설계

작성일: 2026-10-24 · 상태: **상세 설계 제안 / 검토용 / 구현 전**

적용 경로: `/games/{gameSlug}/auth`. 공통 치수·표면·헤더·접근성은 [공통 설계](README.md)를 따른다.
앞뒤 흐름: [게임 선택](04-game-select.md) → 이 화면 → [클랜 가입](03-clan-join.md) 또는 기존 목적지.
계정 생성·진입은 [회원가입](02-sign-up.md)·[로그인](01-sign-in.md), 서비스 소개는 [랜딩](00-landing.md)에서 다룬다.

## 1. 역할과 현재 제공 범위

ClanSync 로그인과 별개로, 선택한 게임에서 사용할 계정을 연결하는 화면이다. 가입 폼에서 게임 비밀번호를 받지 않고 공통 닉네임도 새로 만들지 않는다.
현재 이메일/비밀번호 로그인은 실제 기능이나 Battle.net·Riot 연결은 **QA/개발용 시뮬레이터**다. 이 문서로 외부 OAuth를 구현 완료로 간주하지 않는다.

| 모드 | 현재 가능한 동작 | 이 설계의 표시 |
| --- | --- | --- |
| QA 테스트 연결 | 서버가 허용한 환경 + 활성 게임 + 지원 설정에서 전체 테스트 ID 저장 | `QA 테스트 연결`, 테스트 입력, 테스트임이 명확한 제출 |
| 운영 연결 미제공 | 신규 연결·재연결 실행 불가 | 준비 중 안내 + 실제 이동 가능한 게임 선택/프로필 링크 |
| 지원하지 않는 게임 | 알 수 없는 게임은 서버에서 게임 선택으로 복귀, 설정 미지원은 안내 | 지원 상태 설명과 게임 선택 이동 |
| 미래 외부 OAuth | 현재 미구현 | 별도 출시 의존성. 실제 제공 전에는 활성 버튼·성공 예시로 노출하지 않음 |

현재 `oauthReady=true`는 실제 외부 연결이 준비되었다는 증거가 아니다. 제공자 설정만으로 운영 버튼을 활성화하지 않는다.

## 2. 데스크톱 배치

```text
[ClanSync / 게임 계정 연결]                     [게임 선택] [계정 메뉴] [테마]

                게임 선택 ✓ — 게임 계정 연결 — 클랜 참여
                [게임 아이콘] 오버워치
                오버워치 계정 연결
                게임을 연결하면 전체 배틀태그로 클랜에 참여해요.

                [Battle.net 계정]
                현재: 계정 연결 준비 중
                현재 이 게임의 신규 계정 연결은 제공되지 않아요.
                연결된 기존 계정은 게임 선택에서 활동을 이어갈 수 있어요.
                [게임 선택으로]   프로필로

                QA 허용 환경에서는 위 안내 대신:
                QA 테스트 연결
                테스트 배틀태그 [AimZero#12345]
                이름과 #번호를 모두 입력해 주세요.
                [테스트 배틀태그로 연결]
                게임 선택으로
```

본문은 읽기 편한 좁은 영역, 입력은 공통 인증 폼 폭을 사용한다. 제공자 박스를 카드 안에 여러 번 중첩하지 않는다.
큰 홍보 이미지·클랜 목록·통계·꾸미기 설정은 두지 않는다. 게임 아이콘과 제공자 이름은 연결 대상 확인용이다.

## 3. 모바일 배치

```text
[ClanSync / 게임 계정 연결]         [테마] [계정 메뉴]
게임 선택 ✓ · 게임 계정 연결 · 클랜 참여
[게임 아이콘] 오버워치
오버워치 계정 연결
전체 게임 ID로 클랜에 참여해요.
[QA 테스트 연결 또는 준비 중 안내]
[입력·도움말·오류: QA일 때만]
[주요 행동]
게임 선택으로 / 프로필로
```

단계는 줄바꿈 가능한 짧은 표기로 유지하며 가로 스크롤을 만들지 않는다. 게임 선택 완료를 표시해도 연결 완료를 미리 체크하지 않는다.
키보드가 열려도 입력 아래 도움말·오류·제출에 접근할 수 있어야 한다. 작은 높이에서 세로 중앙 고정이나 고정 하단 버튼을 사용하지 않는다.

## 4. 진입 맥락·문구

| 맥락 | 제목·안내 | 주요 행동·보조 이동 |
| --- | --- | --- |
| 처음 연결 | `{게임명} 계정 연결` / `게임을 연결하면 게임별 ID로 클랜에 참여해요.` | 해당 제공 모드의 행동, `게임 선택으로` |
| 인증 만료·미확인 | `{게임명} 계정 다시 연결` / `클랜 활동을 이어가려면 계정을 다시 확인해 주세요.` | 연결 후 검증된 원래 목적지, 취소는 게임 선택 |
| 프로필에서 명시적 재연결 | `{게임명} 계정 다시 연결` / 현재 전체 ID를 읽기 전용으로 별도 표시 | 연결 후 `/profile`, `프로필로 돌아가기` |
| 연결 제공 안 됨 | `계정 연결 준비 중` / 첫 연결은 `현재 이 게임의 신규 계정 연결은 제공되지 않아요.`, 재연결은 `현재 이 게임의 계정 재연결은 제공되지 않아요.` | `게임 선택으로`, `프로필로` |
| 미지원 | `아직 연결할 수 없는 게임이에요` | `게임 선택으로` |

재연결의 목적지가 검증되지 않았으면 `원래 화면으로 돌아갑니다`라고 보장하지 않는다. 완료 후 게임 선택/클랜으로 이어진다는 정확한 안내를 쓴다.
운영에서 재연결이 필요한 사용자는 `기존 계정으로 계속하기`처럼 우회가 가능한 버튼을 받지 않는다. 프로필·게임 선택 이동만 제공한다.
이미 인증된 사용자가 `reauth=1` 없이 접근하면 기존 서버 판정대로 클랜 또는 가입 화면으로 보낸다. 연결 폼을 잠깐 먼저 노출하지 않는다.
현재 프로필의 `계정 변경` 링크에는 `reauth=1`이 없어 인증된 사용자에게 폼이 열리지 않는다. 재연결 진입을 제공하려면 링크와 서버 분기를 함께 검증해야 한다.
재연결은 별도 계정 소유권 이전·클랜 기록 이동을 약속하지 않는다. 실제 제공자 계정 교체 정책은 미래 OAuth 의존성으로 남긴다.

## 5. QA 입력·버튼 규격

| 게임 | 레이블·예시 | 도움말 | 제출 |
| --- | --- | --- | --- |
| 오버워치 | `테스트 배틀태그`, `AimZero#12345` | `이름과 #번호를 모두 입력해 주세요.` | `테스트 배틀태그로 연결` |
| 발로란트 | `테스트 라이엇 ID`, `Player#KR1` | `게임 이름과 #태그를 모두 입력해 주세요.` | `테스트 라이엇 ID로 연결` |

QA 구역 상단에 `실제 Battle.net·Riot 인증이 아닌 QA 테스트 연결입니다.`를 한 번 표시한다.
현재 값이 있으면 본인 전체 ID를 미리 채운다. 인증되지 않은 기존 값은 `기존 입력`으로 구분하고 연결 완료 표시를 붙이지 않는다.
배틀태그는 현행 파서의 이름 2~20자 + 숫자 4~10자리, 최대 31자 규칙을 유지한다.
라이엇 ID는 현행 파서의 이름 3~16자 + 태그 3~5자, 최대 22자 규칙을 유지한다. 이는 현재 QA 검증이며 실제 제공자 정책이라고 설명하지 않는다.
정규화·검증은 서버 도우미를 재사용한다. 입력의 `#` 이하를 숨기거나 이름만 잘라 저장하지 않는다.
형식 오류는 입력 아래 `배틀태그 전체를 입력해 주세요. 예: AimZero#12345` 또는 라이엇 ID 대응 문구로 표시한다.
제출 중 `연결 중…`으로 바꾸고 중복 제출을 막는다. 실패 시 입력을 유지하며 오류를 읽을 수 있게 초점/알림을 제공한다.
운영 준비 중 상태에는 테스트 입력과 테스트 제출을 렌더하지 않는다. 활성 `Battle.net으로 계속하기`·`Riot 계정으로 계속하기`를 장식으로 두지 않는다.
지원 예정 상태에 눌러도 동작하지 않는 제공자 버튼을 추가하지 않는다. 상태 문구와 실제 이동 링크로 끝낸다.

## 6. 상태·전환 표

| 시작/사건 | 결과·화면 처리 | 다음 위치 |
| --- | --- | --- |
| 로그인 안 됨 | 로그인 필요, 원래 경로의 안전한 `next` 보존 | `/sign-in` |
| 게임 불명·조회 불가 | 게임을 선택할 수 있는 화면으로 복귀. 실패를 연결 완료로 처리하지 않음 | `/games` 또는 재시도 안내 |
| 이미 인증됨·재연결 아님 | 최신 소속/신청으로 서버 이동 | 검증된 게임 하위 경로 → 클랜 홈/가입 |
| `reauth=1` | 제공 가능한 모드에서 재연결 안내·기존 ID 표시 | 현재 화면 |
| QA 연결 성공·`next` 유효 | 서버 저장·재조회 후 복귀, 클라이언트 성공 화면만으로 완료 판단하지 않음 | 권한을 확인한 원래 목적지 |
| 성공·`next` 없음/무효·소속 있음 | 새 소속을 만들지 않고 기존 클랜으로 이동 | `/games/{gameSlug}/clan/{clanId}` |
| 성공·미소속/신청 중 | 기존 신청을 보존하고 클랜 참여로 이동 | `/games/{gameSlug}/clan` |
| 형식 오류·중복 ID·저장 실패 | 같은 폼의 입력·도움말·오류 유지 | 현재 화면 |
| 운영 연결 미제공 | 입력/제출 없음, 준비 중 안내 | 게임 선택 또는 프로필 |
| 취소·뒤로가기 | 연결·신청·소속을 변경하지 않음 | 프로필 진입이면 `/profile`, 그 외 `/games` |

현재 연동 저장 액션은 `next`가 없으면 가입 경로로 보낸 뒤 서버 진입 제어가 소속에 맞춰 클랜으로 돌린다. 새 구도에서도 결과를 보존한다.

## 7. 복귀·취소의 안전 조건

- 로그인/가입 왕복과 연동 단계에서 원래 `next`를 보존하되 `safeNextPath`로 같은 출처의 정규 경로만 허용한다.
- 외부 URL, `//` 경로, 제어문자·우회 구분자, 로그인/가입 자신으로의 복귀를 거부한다. 인증 화면 자신으로 돌아오는 순환도 막는다.
- 원래 목적지는 해당 페이지의 최신 인증·소속·권한 판정을 다시 거친다. 다른 클랜 경로라고 가입·열람 권한을 부여하지 않는다.
- 완료 후 복귀와 취소 후 이동을 같은 링크로 처리하지 않는다. 미연동 상태에서 보호된 `next`로 취소하면 다시 연결 화면으로 돌아올 수 있다.
- 취소는 프로필 맥락이면 `/profile`, 나머지는 `/games`로 정한다. 일반 `history.back()`만 의존하거나 외부 이전 페이지를 그대로 열지 않는다.
- 게임 선택·프로필 이동은 가능한 보조 행동이며 `연동 건너뛰고 클랜 가입` 버튼으로 설명하지 않는다.
- 프로필 재연결 진입은 `reauth=1&next=/profile`을 사용한다. 목적지 없는 재인증은 게임별 상태를 다시 읽어 기본 경로로 보낸다.

## 8. 데이터·미래 외부 연결 의존성

| 구분 | 범위 |
| --- | --- |
| 기존 | 게임 slug·활성 여부, 제공자 설정, 서버 QA 허용 판정, 현재 사용자·인증·소속·신청, 본인의 기존 전체 ID |
| 표시 추가 | QA 여부/실제 제공 여부를 분리한 화면 상태, 재연결 맥락, 검증된 완료 복귀와 취소 목적지 |
| 저장 유지 | QA 액션의 본인 게임 프로필 갱신·안정적 `game_uid` 보존. 닉네임·클랜·경기·대표 엠블럼을 초기화하지 않음 |
| 미래 출시 | 실제 제공자 승인/설정, 시작·콜백 경로, 요청 위조 방지·세션 연결, 거절/취소/만료 처리, 중복 소유·재연결 정책 |

미래 OAuth의 활성 버튼은 실제 연결·실패·취소·복귀 검증 후 별도 출시한다. 이 문서의 UI 개편에 키 발급·운영 DB 변경·배포를 묶지 않는다.
표시용 ID와 안정적 제공자 ID를 구분한다. `game_uid`가 내부 식별자이면 사람에게 보여줄 이름 대신 노출하지 않는다.
QA 허용 판정은 화면과 서버 액션 모두에 유지한다. 프런트 화면에서 버튼을 숨긴 것만으로 허용 여부를 판단하지 않는다.

## 9. 수용 시나리오

- QA 최초 연결: 전체 ID 입력 → 서버 저장 → 미소속은 가입 목록. 공통 닉네임을 요구하지 않는다.
- QA 재연결: 기존 ID 표시·입력 보존, 성공 시 해당 클랜/안전한 원래 목적지 또는 프로필로 복귀한다.
- 이미 인증됨: 일반 접근은 폼 없이 이동하고 `reauth=1`일 때만 재연결 폼을 연다.
- 운영/미지원: 활성 외부 인증 버튼·테스트 입력을 노출하지 않고 게임 선택과 프로필 이동이 작동한다.
- 무효 `next`·인증 화면 재귀·취소: 외부 이동이나 인증 루프 없이 기본 경로로 돌아간다.
- 중복 ID·저장 실패·세션 만료: 완료로 오인시키지 않고 입력·기존 소속/신청·기록을 보존한다.
