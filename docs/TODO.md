# 현재 작업

마지막 갱신: 2026-10-28

**클랜 채팅방:** 운영 설정 → 알림·연동에서 Discord·카카오톡 오픈채팅·LINE·Telegram·WhatsApp·Steam 초대 링크를 등록한다. 클랜장만 수정하고 활성 클랜원은 대시보드 배너 아이콘으로 입장한다. Free 포함·기존 Discord 봇 알림과 별도이며 QA 스키마 적용·운영 반영 보류다. [검증](TODO_Phase2.md#2026-10-28-클랜-채팅방-초대-링크).

**클랜 규칙:** 게시판에서 항목별 추가·수정·삭제와 자동 번호를 제공한다. 기존 줄바꿈 규칙·저장 방식·운영진 권한을 유지하며 대시보드와 같은 항목 경계를 사용한다. [검증](TODO_Phase2.md#2026-10-28-규칙-항목별-추가수정삭제).

**가독성·로딩:** 대시보드는 배너에 대표 배지를 통합하고 그 아래 한 줄 규칙을 8초마다 넘긴다. 공지·일정 아래 승률·참여율·승부예측 세 부문을 한 행에 배치하고, 챔피언 포커스 구성으로 1위를 크게·2~3위를 정렬된 행으로 표시한다(800px 미만은 세로). 닉네임·비율 중심이다. 경기 기록 필터는 헤더 아래 고정하며 게시판 5종/상세에 스켈레톤을 제공한다. [검증](TODO_Phase2.md#2026-10-28-mvp-챔피언-포커스).

**계정 탈퇴:** 일정·내전 등 공동 운영 기록은 보존하고 작성자/호스트 연결만 해제한다. 운영자 이름은 텍스트로 남기며 경기 기록 시각 옆에 표시한다. QA 적용·운영 DB/배포 보류. [구현·검증](TODO_Phase2.md#2026-10-27-운영-기록을-보존하는-계정-탈퇴).

**소개·검색:** 개인 기록은 모든 역할에 멤버 검색을 제공하고 비공개 통계와 소개를 분리한다. 게임별 부계정은 기존 공개 범위로 표시하며 소개 편집 영역·좌우 높이·제목 크기를 정리했다. [소개 명세](01-plan/pages/14-Profile-Customization.md).

**로딩 배치:** 통계·목록·관리/게시판·프로필 진입의 조회 중 배치 유지를 점검했다. [대상·수정 근거](03-analysis/loading-layout-audit-2026-10-27.md). 긴 목록은 영역 안에서 스크롤하고 미수신 값과 빈 결과를 구분한다.

**진입 화면 상세 기획:** [변경 기획](01-plan/entry-experience-redesign.md) → [공통·화면별 상세 설계](02-design/entry-experience/README.md)로 연결했다. 랜딩·로그인·회원가입·게임 선택·게임 인증/재연동·클랜 가입과 이메일 확인·생성/환영 흐름의 구도·문구·상태·복귀·완료 조건을 작성했다. 검토용 설계안·구현 전이며 실제 OAuth와 운영 반영은 별도다.

**현재 프로필:** 2026-10-26 사용자 요청으로 진열장 기능·보관함·전용 상점·코드·에셋·전용 기획과 시안을 제거했다. 본인 소개는 게임 프로필에 실제 연동 ID의 공통 네임카드를 통합한다(미연동은 Player). 꾸미기 도구는 한 번만 제공하고 보유 디자인의 실제 네임카드 미리보기를 비교·선택해 공통으로 저장한다. 기본 방패와 무료 심벌 5종·프레임 6종·이름표 6종·칭호 8종을 제공하고 하단 안내·상점은 아이콘으로 표시한다. 넓은 화면에서 게임·기본 정보와 소개·엠블럼을 두 열로 배치한다. 계정 탭은 계정·게임별 관리에 집중하며 방문 공개 범위는 유지한다. 내전의 비운영 네임카드는 해당 클랜의 개인 기록으로 연결한다. 상대의 현재 게임 프로필·소개·계정 대표 엠블럼은 개인 기록 상단에 통합한다. 클랜 이름/역할은 숨기고, 열람 가능한 성별·출생 연도·해당 클랜 가입일을 표시하며 케이스는 소개 아래에 둔다. 일반 멤버도 열람 가능한 기록의 멤버를 선택하며, 상대 링크는 통계 공개 범위와 별개로 해당 소개를 연다. 기존 방문 주소는 공통 클랜 개인 기록으로 이동하고 공통 클랜이 없으면 본인 소개/대상 엠블럼 케이스로 연결한다. 소개 공개와 통계 열람 권한은 각각 유지한다. 미니룸·가구 기능은 제거하고 개인 상점은 네임카드 디자인 비교·구매·적용으로 재구성했다. [프로필 명세](01-plan/pages/14-Profile-Customization.md).

**QA DB 정리:** 진열장과 폐기된 공개 설정·웹훅·5칸 배지·게임별 꾸미기 선택의 9개 테이블·24행, 함수 8개·enum 2개를 삭제했다. 나머지 70개 테이블은 데이터 동일성을 확인했다. 운영 적용은 보류한다([대상·검증](03-analysis/retired-db-storage-2026-10-26.md)).

**보안 검증 완료:** 실행 문제로 제외했던 보안 E2E 17개와 관련 규칙 4개를 수정·재실행해 총 21개 전부 통과했다. 시드 없이 임시 데이터와 별도 로그인 세션을 사용했으며 실행법은 [E2E 안내](../e2e/README.md)에 반영했다.

**현재 QA:** 개인 상점은 네임카드 6개 분류·검색·보유·기본 제공을 포함한 모든 상품의 등록일 최신순·분류별 6/12개 페이지로 구성한다. 미니룸 전용 테이블 3개·함수 8개를 QA에서 제거했으며 코인·구매·네임카드·클랜 데이터는 보존했다. 기존 QA 명단 시드 금지·운영 DB/배포 보류를 유지한다. [상세](01-plan/pages/14-Profile-Customization.md#개인-상점).

클랜 관리는 운영 / 구성원 / 설정의 가로 분류와 여덟 하위 영역이다. 공지·규칙은 새 게시판으로 이동했다. 선택한 영역만 조회하고 내전의 독립 조회를 병렬화했다. QA 관리 첫 응답은 178→86KiB, 반복 요청은 약 1.0~1.8→0.3초로 줄었다([구현·검증](TODO_Phase2.md#2026-10-09-클랜-관리-구조조회-최적화)). 운영 성능은 별도 확인이 남아 있다.

운영 현황은 아이콘이 있는 구성원·내전 회차·코인 표시 카드와 설립일·최근 내전·배지로 구성한다. 카드 이동·보조 문구·배지 케이스 바로가기는 제거했다. 대시보드 공지는 고정 우선 최대 3개로 표시한다([검증](TODO_Phase2.md#2026-10-28-운영-현황-요약-카드-정리)).

통계는 기간·날짜 변경 중 영역을 유지하고 목록·빈 상태의 높이를 고정했다. 기록 정정 권한으로 경기 추가/수정/제거와 당일 승/무/패 자동 갱신을 QA에 적용했다. 원본 라운드와 코인 정산은 보존한다([구현·검증](TODO_Phase2.md#2026-10-10-통계-화면-유지경기-기록-정정)).

통계 설정은 네 탭의 필터 행으로 분리했다. 경기 기록의 역할별 열람·추가·편집·삭제와 개인 기록의 최소 공개 역할(상위 포함)·통계 항목을 QA에서 검증했다([검증 범위](TODO_Phase2.md#2026-10-10-탭별-통계-설정공개-권한)).

Discord 연결은 클랜 관리의 `알림·연동`으로 통합했다. 갤러리와 실제 알림의 임베드 카드 구성을 통일하고 공지 본문·링크, 투표 시작/종료 문구와 링크 임베드 권한을 QA에서 검증했다. 카카오 알림톡 UI·저장 API·기존 수신 희망은 제거했다. 앱 키는 설정되어 있으며 임베드의 실제 수신 확인과 분 단위 워커 상시 실행은 남아 있다([연결 조건](guides/discord-bot-setup.md)).

캘린더의 선택 날짜 일정은 데스크톱 우측 패널·모바일 하단 드로워로 표시한다. 우측 패널 높이는 캘린더에 맞추고 목록·상세 전환과 이전/다음 일정 이동을 제공한다([검증](TODO_Phase2.md#2026-10-11-이벤트-캘린더-반응형-일정-패널)).

투표는 활성/예정/종료 Rubber Segment와 도넛 결과로 구분한다. 공개 참여자 hover·키보드·터치, 익명 응답 보호와 시작 전 참여 차단을 적용했다. Discord/자동 종료 설정은 변경 시 직렬 저장하고 오류 재시도·이동 중 저장을 제공한다([규칙·검증](TODO_Phase2.md#2026-10-15-투표관리-화면-정리)).

명예의 전당은 운영진의 미달자를 승률순 `--`로 구분하고 기본 이모티콘·댓글 공감을 QA에 적용했다. 내전 통계는 기간 고정·선호 맵 유형 필터와 전체 항목 목록을 사용한다([구현·검증](TODO_Phase2.md#2026-10-10-통계-순위공감필터-정리)).

승부예측은 개인 코인 풀·편성 중 참여·경기 시작 후 설정 시간 마감(기본 2분)·현재 내전 공개 순위를 QA에 적용했다. 개설 관전자는 코인 없이 예측·적중률만 기록하며 이미 시작한 경기의 마감과 정산된 과거 기록은 유지한다([규칙](02-design/formation-modes.md#관전자-코인-풀공개-순위-2026-10-09)). 맵 투표 마감 후 확정 맵 확대와 다음 단계 자동 전환을 적용했다.

역할 자동 배정 후에는 팀 조정 단계에 머물며 같은 역할끼리 교환한 뒤 운영진의 `다음 단계`로 진행한다. 마지막 변경 자동 저장·공유 화면·재접속·경기 시작 전 권한 검증을 QA에서 확인했다([검증](TODO_Phase2.md#2026-10-09-역할-자동-배정-후-팀-조정)).

시연: 대시보드·내전·통계의 실제 촬영본을 Vrew용 11분 40초 영상과 완결 발화 89개 자막으로 구성했다([산출물](clansync-demo-video.md)). 사용자 확인을 받은 [문장 단위 내레이션 제작 방식](guides/demo-video-vrew-workflow.md)을 다른 프로젝트용으로 문서화했다. 촬영용 임시 클랜·계정은 정리했으며 기존 테스트 경기·명단은 보존한다.

네임카드 후속(2026-10-27): 심야 아케이드·전술 기록·성운 항해의 그림 배경과 독립 초상 프레임을 QA에 추가했다. 테마 세트 또는 개별 조합을 사용하며 성운 초상은 원형이다. 기존 심벌·칭호·구매는 유지한다. [명세](01-plan/pages/14-Profile-Customization.md) · [제작 에셋](design/namecards/v1/README.md). 움직임은 후속이다.

## 실행 제약

- **QA 우선, 운영 DB·운영 배포 보류.** 작업 브랜치: `codex/live-session-formation`. 통계 방문·예측 RLS 및 명예의 전당 댓글 마이그레이션을 QA에 적용했다. 운영 적용은 보류한다.
- 사용자 QA: `npm run dev:qa`(3011). 열린 명단을 시드로 초기화하지 않는다. 자동 E2E는 `E2E_SKIP_SEED=1`, 쓰기 테스트는 별도 임시 픽스처를 사용한다.
- 변경 위험에 맞는 검증만 실행한다([기준](../.cursor/rules/agent-auto-tasks.mdc) · [실행법](../e2e/README.md)). main 병합·운영 반영 전에는 전체 회귀·빌드가 필요하다.

알파 범위는 1개 클랜·100명 이하로 확인했다. [알파 점검·손익](03-analysis/alpha-review-2026-10-16/README.md)에 디자인 6항목·추가 페이지·라이트 테마/모바일 점검의 수정 결과와 OCR 검토를 모았으며 로비 이벤트 갱신·설정 지연 로딩을 적용했다. 실제 배포의 사용자 체감 지표와 100명 동시 부하는 미검증이다.

## 다음 우선순위

개인 엠블럼: [투명 이미지 50장](design/personal-emblems/production-v1/README.md)을 프로필·개인 기록에서 여는 전용 케이스 페이지에 연결했다. 클랜 배지와 같은 진열·상세 창, 날짜+월12색/연6색, 최고 단계·관련4단계와 게임·클랜을 섞은 계정 공통 대표3을 제공한다. 프로필에는 캐러셀 밖에 한 번만 진열한다. 본인은 현재·탈퇴 클랜의 기록을 같은 케이스에서 게임별로 필터링하며 상세에 게임·클랜을 표시한다. 마감 수상과 최초 달성일을 영구 보관하고 고유 이름 대신 `10승 달성`처럼 설명만 표시한다([구현·검증](TODO_Phase2.md#2026-10-23-개인-엠블럼-공통-케이스)). 운영 DB·배포는 보류한다.

클랜 게시판·배지: 다섯 공간·핀 케이스, 선생님 지정 신청/알림, 복수 방송 링크와 폴라로이드 사진 목록을 QA에 적용했다([명세](01-plan/pages/15-Clan-Board.md)). 신청 목록·상세 정보 구분·아이콘·입력창 스크롤을 정리하고 목록 전송량·중복 조회를 줄였다. 방송 API 실조회와 소개 입력을 제거하고 작성자 수동 생방송 표시를 추가했다. 추억은 앨범 전환 없이 게시일을 자동 표시한다. 주년은 잎 1·3·5개와 무성한 10주년 나무, 멤버는 커지는 성채이며 금빛 테두리를 사용한다. 모든 단계형 배지는 최고 달성 한 슬롯과 이미지/설명/연관 단계 상세로 통일했다. 멤버 배지는 활성 인원 미달 시 회수한다. 시즌 배지·비공개 신청은 후속 범위다.

배지 확장: 선택한 [6계열·21개 투명 핀](design/clan-badges/expansion-v1/production-v1/README.md)과 발급을 QA에 적용했다. 내전은 유효 결과가 있는 회차당 1회, 코칭은 완료 신청, 게시글은 자유 게시판이다. 장기 동료는 10명 이상의 연속 소속 기간을 판정하며 재가입은 초기화한다. 전체 30종·최고 단계 진열을 집계/회수·권한·모바일과 빌드로 검증했다.

배지 케이스는 5개 Rubber Segment 분류와 카테고리 N으로 정리했다. 정보·대표 선택은 모든 핀의 상세 창으로 모으고 상단 배너/선택 밑줄을 제거했다. 부분 확인은 현재 브라우저, 전체 확인은 서버에 반영한다([표시 규칙](01-plan/clan-badge-expansion-v1.md#2026-10-15-케이스-분류와-새-배지-확인)).

1. [클랜 통계](01-plan/pages/10-Clan-Stats.md)의 4영역·관리 방문 화면 1차 구현을 QA에서 검토한다. 잔여 항목은 예측 최소 표본, 개인 비공개 오버라이드, 기간 상태 복원, 자체 이모티콘 등록·첨부, 우세 예측·요일/시간대 및 원본 이력이다. 구현·검증 범위는 [Phase 2 현황](TODO_Phase2.md)에 기록한다.
   기존 내전 로비·경기 흐름의 QA 피드백과 [보안·기능 리뷰 후속](03-analysis/review-fixes-2026-09-23.md)도 이어간다.
2. 성능: 클랜 통계는 DB 기간별 요약과 날짜·멤버별 조회를 QA에 적용했다. 1만 경기·출전자 10만 행에서 첫 화면 통계 모델 조회 209~725ms, 38,285 bytes([설계·측정](02-design/clan-stats-read-model.md)). 결과 정정의 요약 갱신은 3.3초이며 더 큰 규모의 쓰기 비용·개인 전체 이력·운영 성능은 후속 계측 대상이다.
3. M8: 접근성 전수 감사, 모든 권한 조합 점검과 PR 필수 CI.
4. 후속: 실력 기반 팀 균형·OCR·대진 진행·클랜 기본정보/리더 위임, 실제 게임 OAuth·유료 결제·알림 전달 연결.
