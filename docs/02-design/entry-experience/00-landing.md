# 랜딩 상세 설계안

작성일: 2026-10-24 · 상태: **상세 설계 제안 / 구현 전** · 경로: `/`

상위: [변경 기획](../../01-plan/entry-experience-redesign.md) · [공통 기준·전체 흐름](README.md)

## 1. 역할과 완료 행동

처음 방문한 사람에게 ‘클랜원들과 무엇을 함께할 수 있는지’를 설명하고 계정 생성으로 연결한다. 이미 로그인한 사람은 게임 선택으로 활동을 이어간다. 클랜 홈의 함께하는 활동과 프로필의 게임별 정체성을 첫 화면부터 연결한다.

첫 화면에서 읽어야 할 정보는 서비스 목적 한 문장, 대표 장면 한 개, 시작 행동 한 개다. 실제 계정 가입이나 게임 연결이 완료된 것처럼 보이는 체험 버튼은 만들지 않는다.

## 2. 화면 배치

```text
PC · 1024px 이상
[ClanSync]          서비스 화면 · 지원 게임                   [테마] [로그인]

[우리 클랜의 다음 경기부터,]       [클랜 홈 대표 장면 · 예시 화면]
[함께한 기록까지.]               [클랜 배너 / 공지 / 다가오는 일정]
 내전 준비와 일정, 경기 기록을
 클랜원들과 한곳에서 이어가세요.
 [무료로 시작하기]  서비스 화면 보기 ↓

[함께 준비하기]          [함께 기록하기]          [나를 보여주기]
 내전·일정 장면           경기 기록 장면           게임 ID·소개·엠블럼 장면

[지원 게임과 현재 제공 상태]
[현재 이용 안내]
[함께할 준비가 됐나요?                              무료로 시작하기]
[하단 정보]

모바일 · 1024px 미만
[ClanSync]                                      [테마] [로그인]
 제목 → 설명 → 주 CTA → 서비스 화면 보기
 클랜 홈 대표 장면
 함께 준비하기 → 함께 기록하기 → 나를 보여주기
 지원 게임 → 이용 안내 → 마지막 CTA → 하단 정보
```

- 헤더 60px, 본문 최대 1280px, PC 좌우 24~32px·모바일 16px를 사용한다. 헤더는 상단 고정을 기본으로 하지 않아 좁은 세로 화면을 지속 점유하지 않는다.
- PC 히어로는 소개 약 40%·대표 장면 약 60%, 간격 40~48px를 기준으로 한다. 상하 여백은 64~80px부터 조정하며 현재의 큰 중앙 빈 공간을 제거한다.
- 모바일 히어로는 상하 32~40px, 제목 30~36px, 설명 16px·행간 1.6을 기준으로 한다. 제목은 의미 단위로 줄바꿈하고 고정 줄 수 때문에 넘치지 않게 한다.
- 1280×720 화면에서 제목·CTA와 대표 장면의 주요 부분을 함께 볼 수 있어야 한다. 390×844에서는 CTA 전에 큰 이미지나 긴 소개를 배치하지 않는다.
- 사용 장면 3개는 PC 3열·모바일 1열이다. 기능 목록을 가로 스크롤하거나 자동 전환하지 않는다.

## 3. 영역별 요소와 문구

| 순서 | 영역 | 표시 요소·기본 문구 | 행동 |
| --- | --- | --- | --- |
| 1 | 헤더 | 로고, `서비스 화면`, `지원 게임`, 테마, `로그인` | 로고는 `/`, 앵커는 같은 페이지, 로그인은 `/sign-in` |
| 2 | 히어로 제목 | `우리 클랜의 다음 경기부터, 함께한 기록까지.` | H1 하나만 사용 |
| 3 | 설명 | `내전 준비와 일정, 경기 기록을 클랜원들과 한곳에서 이어가세요.` | 2~3줄 안에서 제품 목적 설명 |
| 4 | 히어로 행동 | `무료로 시작하기`, 보조 텍스트 `서비스 화면 보기` | 가입 `/sign-up`, 보조는 `#features` |
| 5 | 대표 장면 | 클랜 홈 정적 이미지, `클랜 홈 · 예시 화면` 캡션 | 이미지 자체를 로그인 없는 실사용 화면 링크로 만들지 않음 |
| 6 | 함께 준비하기 | `일정을 모으고, 다음 내전을 준비하세요.` + 내전·일정 장면 | 별도 CTA 없이 기능 이해 |
| 7 | 함께 기록하기 | `경기 결과를 남기고, 함께한 플레이를 돌아보세요.` + 기록 장면 | 별도 CTA 없이 기능 이해 |
| 8 | 나를 보여주기 | `게임별 ID와 소개, 대표 엠블럼으로 나를 보여주세요.` + 프로필 일부 | 프로필의 현재 검증된 구성만 표시 |
| 9 | 지원 게임 | 게임 로고·한국어 이름·현재 제공 상태 | 지원 상태만 안내, 게스트에게 보호된 게임 화면 버튼을 나열하지 않음 |
| 10 | 이용 안내 | `회원가입은 무료입니다.` / `Premium 구독 결제는 준비 중입니다.` | 가격표·구매 버튼 없음 |
| 11 | 마지막 CTA | `함께할 준비가 됐나요?` + `무료로 시작하기` | `/sign-up` |
| 12 | 하단 | 서비스명·연도·서비스 화면/지원 게임 링크·실제로 준비된 정책 문서 | 연결 가능한 경로만 노출 |

영어 브랜드 문구는 필요한 경우 하단의 작은 보조 서명으로만 사용한다. 기능 레일의 스크림·대진표 등은 구현 상태를 확인한 뒤 준비/기록 장면 아래 짧은 보조 문장에 포함할 수 있으나, 새로운 네 번째 장면을 계속 늘리지 않는다.

## 4. 로그인 상태와 목적지

| 진입 상태 | 헤더 우측 | 본문·마지막 주 CTA | 이동 규칙 |
| --- | --- | --- | --- |
| 비로그인 | 테마 + `로그인` | `무료로 시작하기` | 로그인→[로그인](01-sign-in.md), 시작→[회원가입](02-sign-up.md) |
| 로그인 후 `/` 직진입 | 기존 자동 이동 유지 | 랜딩을 먼저 깜빡여 보여주지 않음 | `/games` |
| 로그인 후 `/?from=logo` | 테마 + `게임 선택` + 기존 계정 메뉴 | `게임 선택으로` | [게임 선택](04-game-select.md) |
| 로그인 세션 조회 실패 | 개인 정보·소속 정보를 추측해 표시하지 않음 | 중립적인 `시작하기`로 표시 가능 | `/games`의 기존 인증 가드에서 재확인 |

- 로고를 통해 랜딩을 다시 본 로그인 사용자에게 가입을 반복 권유하지 않는다. 계정 메뉴의 프로필·로그아웃 진입은 유지한다.
- 랜딩은 승인된 클랜·게임을 임의 선택하지 않는다. 게임 상태별 목적지는 게임 선택이 판정한다.
- 각 앵커는 실제 `#features`, `#games` 영역으로 이동하고 제목이 보이게 한다. 키보드 사용 시 해당 제목에 초점을 연결하고, 모션 감소 설정에서는 즉시 이동한다.
- 모바일은 앵커 탐색을 헤더에서 생략해도 본문 순서와 하단 링크로 접근할 수 있다. 메뉴를 줄이기 위한 별도 햄버거 패널은 추가하지 않는다.

## 5. 대표 이미지와 지원 상태의 계약

### 이미지

- 히어로는 최신 검증된 클랜 홈 한 장을 사용한다. 공지·다가오는 일정·클랜 이름이 구분되는 범위를 16:10 정도의 비율로 편집하고, 전체 앱을 축소해 글자가 읽히지 않는 이미지로 만들지 않는다.
- 모바일은 같은 의미가 보이는 4:3 내외의 전용 크롭을 사용한다. 게임 ID·이름·정보를 중간에서 자르는 대신 필요한 장면 범위를 다시 선택한다.
- 내전·기록·프로필 이미지는 각각 기능을 설명하는 구간만 담는다. 실제 개인 이메일·QA 계정명·사용자 테스트 명단을 공개 홍보 자산으로 사용하지 않는다. 촬영용 예시 이름·ID·기록임을 캡션에 표시한다.
- 테마별 자산이 준비되면 현재 테마와 맞춘다. 한 테마 자산만 사용할 때는 이미지가 독립된 예시임이 보이는 고정 프레임 안에 둬 이미지 색상을 강제로 반전하지 않는다.
- 프로필 진열장 변경은 병행 작업의 검증·완료 상태를 확인한 뒤 반영한다. 기존 미니룸·신규 진열장 중 소스 파일이 존재한다는 이유만으로 출시 장면으로 확정하지 않는다. 미완성 콘셉트 이미지를 현재 기능으로 소개하지 않는다.

### 제공 상태

| 내부 근거 | 고객에게 표시할 문구 | 제약 |
| --- | --- | --- |
| 게임 활성 + 운영 신규 연동 제공 확인 | `이용 가능` | 실제 출시 확인 후에만 사용 |
| 게임 활성이나 운영 신규 연동 미제공 | `신규 계정 연결 준비 중` | QA 연결 성공을 운영 제공으로 표시하지 않음 |
| 게임 비활성·출시 미확정 | `지원 예정` | 날짜나 기능 전체 지원을 추측하지 않음 |
| 목록/제공 상태 조회 실패 | `지원 정보를 불러오지 못했어요.` + 영역 내 재시도 | 잘못된 기존 상태나 `지원 게임 없음`으로 대체하지 않음 |

표시의 기준은 게임 활성 상태와 실제 운영 연동 제공 여부다. 현재 랜딩의 발로란트 고정 `지원 예정`과 QA 게임 선택의 활성 표시 차이를 해소할 공통 상태 원천이 필요하다. 구체적인 구현 방식·제공자 설정 변경은 [게임 인증 설계](05-game-auth.md)와 함께 결정한다. 고객 문구에 내부 환경명이나 개발 설정을 드러내지 않는다.

## 6. 유지·삭제·추가 범위

| 유지 | 삭제·축소 | 추가·교체 |
| --- | --- | --- |
| 브랜드 로고·테마·비로그인 접근·기존 로그인 리다이렉트·하단 기본 정보 | 큰 영어 히어로·과도한 여백·동일 비중 로그인/가입·점 미리보기 전환·6개 기능 레일·큰 미출시 요금표 | 한국어 목적 설명·3개 사용 장면·최신 정적 이미지·로그인 상태 CTA·공통 지원 상태 |

클랜 목록·구성원 수·최근 경기 같은 실제 서비스 데이터를 랜딩용으로 새로 집계하지 않는다. 통계 숫자·후기·이용자 수를 만들어 사회적 증거로 추가하지 않는다. [클랜 가입](03-clan-join.md) 탐색이나 게임 인증 건너뛰기를 랜딩에서 제공하지 않는다.

## 7. 로딩·접근성·성능

- 대표 이미지의 가로세로 비율과 캡션 높이를 확보해 로딩·실패 때도 CTA와 아래 영역이 이동하지 않게 한다. 이미지 실패는 같은 프레임 안에 `화면 예시를 불러오지 못했어요.`로 표시한다.
- 히어로 이미지는 우선 로딩 대상으로, 아래 사용 장면은 지연 로딩 대상으로 삼는다. 실제 앱·3D 장면·영상·외부 위젯·자동재생을 삽입하지 않는다.
- 이미지에는 기능을 설명하는 짧은 대체 텍스트를 제공하고, 장식용 프레임·기호는 읽기 순서에서 제외한다. 화면 속 작은 글자를 정보의 유일한 전달 수단으로 사용하지 않는다.
- 헤더→본문→하단의 읽기 순서, H1/H2/H3 구조, 포커스 표시, 최소 44px 주요 조작 영역을 유지한다. 이미지·장식으로 제목이나 CTA를 가리지 않는다.
- 세션/지원 상태 갱신은 해당 영역에서만 처리한다. 페이지 전체를 로딩 화면으로 바꾸거나 이전 계정의 개인 정보를 남기지 않는다.

## 8. 구현·검증 기준

1. 1280/1024/768/390/320px에서 제목·CTA·예시 이미지의 순서와 넘침을 확인한다. 320px의 헤더에도 로고·테마·로그인이 겹치지 않는다.
2. 비로그인, 로그인한 `/`, 로그인한 `/?from=logo`의 라벨·목적지가 표와 일치한다. 가입·게임 선택 CTA를 헤더 상태와 다르게 표시하지 않는다.
3. 앵커 이동·키보드 초점·모션 감소·라이트/다크를 확인한다. 별도 캐러셀 조작 없이 세 장면을 모두 읽을 수 있다.
4. 이미지 지연/실패·지원 상태 실패에도 제목·CTA·프레임 위치가 유지된다. 실패를 현재 지원 정보처럼 표시하지 않는다.
5. 공개 자산에 개인/QA 식별정보·미완성 기능·미확정 가격이 없고, 모든 행동이 실제 경로로 연결된다.

이 문서는 상세 기획이다. 새 레이아웃·이미지 제작·지원 상태 통합·브라우저 검증을 완료한 상태가 아니다.
