# 로컬 자동 검사와 실시간 현황

사용자가 직접 확인하는 3011 QA는 기존 온라인 DB와 계정·내전 기록을 유지한다. 자동 검사는 이 데이터에 연결하지 않고 PC의 별도 Supabase 프로젝트 `clansync-automated-tests`를 사용한다. 운영 DB도 연결하지 않는다.

## 한 번 준비하기

Windows에서는 Docker Desktop과 WSL이 필요하다. Docker를 실행한 뒤 다음 명령으로 준비한다.

```powershell
npm run test:local:setup
npm run test:dashboard
```

현황은 <http://127.0.0.1:3040>에서 본다. 첫 명령은 저장소의 마이그레이션만으로 새 로컬 DB를 구성하며 온라인 데이터를 복사하지 않는다. API는 `127.0.0.1:55431`, DB는 55432, 테스트 메일함은 55434다. 로컬 연결값은 Git에서 제외되는 `.env.test-local`에 자동 생성된다.

Docker 네트워크는 loopback 바인딩 옵션으로 생성한다. Windows Docker Desktop에서 실제 포트가 모든 인터페이스로 표시될 수 있으므로 관리자 PowerShell에서 `scripts/local-tests/protect-windows-ports.ps1`을 실행해 이 세 포트의 외부 접근을 차단한다. 현황 서버 자체는 `127.0.0.1`에만 바인딩하며 읽기 기능만 제공한다.

## 검사 실행

```powershell
# 필요한 파일만 선택
npm run test:db -- scripts/role-preferences-db.test.mjs
npm run test:e2e -- e2e/auth-performance.spec.ts:66

# 전체 DB / 전체 브라우저 검사
npm run test:db
npm run test:e2e
```

브라우저 검사는 프로덕션 빌드 후 전용 3010 서버·worker 1·재시도 0으로 실행한다. 파일 또는 `파일:줄번호`만 인수로 받는다. 로컬 테스트 계정은 새로 만들며 온라인 QA의 동명 계정과 무관하다. 실행 중인 다른 로컬 검사나 정리가 있으면 중복 실행을 거부한다.

검사 시작 전 전용 로컬 스택을 비우고, 성공·실패·일반적인 중단 후에도 같은 스택을 다시 만들어 데이터와 Storage 파일을 정리한다. 계정·클랜·경기 기록이 0건인지 확인한 뒤에만 정리 완료로 표시한다. DB 일부만 초기화할 때 발생했던 서비스 재연결 오류를 피하기 위해 전체 **전용 로컬** 스택을 재생성한다. Docker 이미지 캐시는 보존한다.

PC 강제 종료처럼 종료 처리가 불가능한 경우 다음 실행의 시작 단계에서 잔여 데이터를 정리한다. 직접 정리하려면 `npm run test:local:clean`을 실행한다. 진행 중인 검사가 있으면 이 명령도 거부된다.

## 현황 읽기

- 통과·실패·진행 중·건너뜀과 현재 단계는 1초 간격으로 갱신된다.
- 실패 필터와 상세 원인, 검사 파일·줄번호, 오래 걸린 검사, 최근 20회 실행 이력을 제공한다.
- 로컬 DB의 계정·클랜·경기 수는 10초 간격으로 갱신한다. 연결이 끊기면 이전 값을 현재 값처럼 표시하지 않는다.
- 준비 실패와 검사 실패, 검사 후 정리는 별도로 기록한다. DB 검사 수에는 상위 묶음이 포함된다.
- 이력을 선택하면 과거 실행을 보고, `실시간 보기`로 현재 실행에 복귀한다. 연결이 끊기면 재연결 상태를 표시한다.

이력·오류 로그·브라우저 검사 산출물은 `.local-tests/runs/`에 남는다. DB를 정리해도 문제 추적용 이력은 유지된다. 인증값은 현황과 저장 로그에서 가린다. `test:db:raw`와 직접 Playwright 실행은 내부 진단용이며 자동 정리를 제공하는 위 래퍼 명령을 사용한다.

## 병목 지표 수집

`test:dashboard` 프로세스가 실행되는 동안 수집한다. 브라우저 탭을 닫아도 프로세스가 켜져 있으면 계속 기록하고, 프로세스를 종료하면 수집도 멈춘다.

| 대상 | 간격 | 수집 내용 |
|---|---|---|
| 전용 로컬 DB | 10초 및 검사 단계 전환 | PostgreSQL 블록 읽기, 행 추가·수정·삭제 횟수, 캐시 적중률, 임시 파일 쓰기, 교착 상태, 실행 중·잠금·I/O 대기, 최장 실행 시간 |
| 로컬 요청 통계 | 위와 동일 | DB 초기화 이후 실행 시간 합계가 큰 요청 8개: 요청 번호·호출 수·평균/합계 실행 시간·읽은 블록·임시 블록. `pg_stat_statements(false)`로 SQL 본문 파일을 읽지 않으며 입력값도 수집하지 않음 |
| 온라인 QA | 60초 | Supabase Metrics API가 제공하는 디스크 읽기/쓰기·IOPS·대기 작업, CPU 사용/I/O 대기, 가용 메모리, DB 연결·캐시 통계 |

온라인 조회는 `clansync-test` 프로젝트로 고정하고 `.env.local`의 관리 토큰을 서버 내부에서만 읽는다. 별도 업무 테이블 조회나 검사 데이터 생성·삭제를 하지 않는다. 토큰이 없거나 조회가 실패하면 미연결 상태로 표시한다. 운영 프로젝트는 조회하지 않는다.

수치는 현재와 이전 누적값의 차이로 계산한다. 온라인 지표가 캐시되어 같은 측정 시각을 반환하면 0으로 계산하지 않으며, DB 재시작·통계 초기화·미수신 때도 빈 값으로 둔다. 읽기가 없으면 캐시 적중률은 미확인이다. 로컬 블록 읽기에는 운영체제 캐시가 포함될 수 있고, 행 변경 횟수는 디스크 쓰기 바이트와 다르다. 온라인 디스크 지표와 직접 비교하지 않는다.

짧은 검사도 비교할 수 있도록 실행기는 검사 직전·정리 직전에 `db-before.json`·`db-after.json`·`db-comparison.json`을 실행 폴더에 저장한다. 전용 로컬 서버의 설정을 다시 읽혀 기존 연결까지 I/O 시간·WAL 기록/동기화 시간·함수 실행 통계를 켠다. 초기 데이터 준비를 제외한 모든 역할의 요청별 호출 수·실행 시간·읽기/쓰기·임시 파일·WAL과 함수 자체 실행 시간의 차이를 남긴다. 식별에는 요청 번호·역할·스키마 객체명만 쓰고 SQL 본문·인자는 저장하지 않는다. 요청 최대 시간은 DB 초기화 이후 값이며 구간 최대값과 구분한다. PostgreSQL 요청 통계에는 실행 중 실패한 요청이 빠질 수 있어 오류 로그·실시간 대기 관측도 함께 확인한다.

화면의 실행 중 요청·최장 실행 시간은 일반 클라이언트 연결만 센다. 실시간 전송을 위해 계속 열려 있는 `walsender`를 느린 화면 요청으로 해석하지 않는다. 과거 이력의 `timingScope=new-connections-v1`은 이미 열린 연결의 I/O 시간이 빠질 수 있으며 WAL 시간도 없으므로, `server-reload-v2`와 동일한 측정 범위로 비교하지 않는다.

브라우저 검사 실패에는 재시도 없이도 Playwright trace를 보관한다. trace는 로컬 테스트 계정의 요청 정보를 포함할 수 있으므로 Git에서 제외되는 실행 폴더에만 보관하고 공개하지 않는다.

`.local-tests/metrics/YYYY-MM-DD.jsonl`에 측정 시각과 당시 실행 ID·단계·검사 파일을 함께 저장한다. 속도는 직전 측정부터의 평균이므로 짧은 검사 여러 개가 한 구간에 포함될 수 있다. 화면에는 최근 로컬 20분·온라인 2시간을 표시하며, 원본 측정 이력은 DB 정리 후에도 유지한다. 과거 검사 이력을 선택해도 자원 패널은 **현재 상태**다.

Disk I/O 예산 잔여량은 이 API로 확인하지 못했다. 순간 사용량 감소나 로컬 검사 통과만으로 온라인 자원의 완전한 회복 또는 병목 원인을 확정하지 않는다. 실패 시각의 읽기·쓰기/대기 변화와 해당 검사·요청 번호를 대조한 뒤 필요한 요청만 재현한다.

참고: [Supabase Metrics](https://supabase.com/docs/guides/observability/metrics), [PostgreSQL 누적 통계](https://www.postgresql.org/docs/17/monitoring-stats.html).

## QA와 구분

`npm run dev:qa`와 명시적인 QA 관리 도구는 기존 `.env.e2e.local`을 읽는다. `db:test:push`·`db:test:types`도 기존 온라인 QA 스키마 관리 명령이다. 자동 검사 공용 로더는 `.env.test-local`만 읽고 온라인 QA·운영 주소 또는 다른 로컬 포트를 거부한다. `.env.local`로 되돌아가는 경로가 없다.

로컬 검사는 온라인 서비스의 자원 한도나 외부 인증 제공자 장애까지 재현하지 않는다. 운영 반영 전 온라인 환경에서 확인할 항목은 별도 소규모 검증으로 구분한다. 이 환경 구성 자체가 전체 기능 회귀나 운영 출시 완료를 의미하지 않는다.
